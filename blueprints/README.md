# 量子流水线蓝图

本目录包含可由“蓝图与待建施工”直接导入的 DSP极简网络 v2 蓝图：全物品 1 万堆叠、非豁免制造品最低 10 万/s，以及专供建筑制造中心批量制造射线接收站的四材料极限流水线。

## 射线接收站四材料极限流水线

完整稳态测试见 `射线接收站四材料-极限产能测试.md`。

- `射线接收站四材料-量子下载-配送枢纽-极限产能.json`
  - 从量子库存下载铁矿、硅石、铜矿和光栅石，完整生产钢材、高纯硅块、光子合并器和处理器。
  - 四种净输出按射线接收站 `20:20:10:5` 的建造配比配置，连接 2 座物资配送枢纽。
  - 共 153 个设备节点、20,189 条逻辑线路，需要 82,275,240 条 Mk.III 传送带施工件。
- `射线接收站四材料-量子下载-量子上传-极限产能.json`
  - 使用同一生产网；101 座量子塔同时承担原矿下载和四种成品上传，不额外建立传统星际航线。
  - 共 151 个设备节点、20,212 条逻辑线路，需要 82,275,260 条 Mk.III 传送带施工件。

两版都使用 101 座各 `1,000,000` 堆叠的量子塔和 48 个分支专用配方节点。单个生产节点不超过 `100,000,000` 堆叠；每组并行线路只有最后一条按实际余数裁剪为 179～4,096 并联，其余均为 4,096 并联、Mk.III、4 层堆叠。额定配套能力为 `24,990,000` 座射线接收站/秒，约为量子仓库单物品五秒结算理论上限 `25,000,000/s` 的 99.96%。

两座微型黑洞各提供最低优先级的应急溢流口。由于黑洞每端口只能接一条线路，它们不能吞掉数亿件/秒的全部额定输出；要保持极限产能，物资托盘或量子库存必须被建筑制造中心等下游持续取走。正常目的地不堵塞时，测试中黑洞销毁量为 0。

这两张专用蓝图超过旧交换格式的 512 线路限制，需要使用已将交换校验上限与 `MAX_BLUEPRINT_CONSTRUCTION_BELTS = 250,000` 对齐的当前版本。

## 非豁免制造品最低 10 万/s

完整稳态实测数据见 `全物品流水线-10万每秒稳态产量.md`。

- `全物品-量子下载-配送枢纽-10万每秒.json`
  - 48 种非豁免制造品的满原料毛产量全部不低于 `100,000/s`，72 种非矩阵物品全部接入物资配送枢纽。
  - 共 101 个设备节点、433 条逻辑线路，其中 199 条额外直连并行带用于突破单条 Mk.III 线路的吞吐上限。
- `全物品-量子下载-量子上传-10万每秒.json`
  - 使用同一套扩容生产网，并把 54 种制造物品及生产副产氢上传至量子仓库。
  - 共 88 个设备节点、415 条逻辑线路，同样包含 199 条额外直连并行带。

两版均使用 4 座各 `234,000` 堆叠的量子下载塔；54 个配方节点按依赖负载分别为 `10,000`～`7,114,000` 堆叠。以下 6 种按要求豁免 10 万/s 目标并保留 `10,000` 配方建筑堆叠：小型运载火箭、湮灭约束球、反物质燃料棒、氘核燃料棒、蓄电器、蓄电器（满）。多余制造品和副产物继续走最低优先级的 19 座微型黑洞。

这组蓝图仍在旧版交换格式的 256 设备、512 线路限制内。仅传送带 Mk.III 就分别需要 1,773,568 条（配送版）或 1,699,840 条（量子上传版）；生产建筑堆叠和供电需求仍然非常高。

## 全节点 1 万堆叠

满原料、满功率并启用黑洞溢流后的 72 种物品实测速率见 `全物品流水线-满原料稳态产量.md`。

- `全物品-量子下载-配送枢纽-1万堆叠.json`
  - 4 座量子下载塔接收 18 种基础/稀有原料。
  - 54 个非矩阵配方节点组成完整生产依赖网。
  - 72 种非矩阵物品（包含原料、中间材料和成品）全部接入 24 座物资配送枢纽。
  - 19 座单体微型黑洞以 57 条最低优先级线路销毁无法配送的制造产物和副产物。
  - 共 101 个设备节点、234 条逻辑线路。
- `全物品-量子下载-量子上传-1万堆叠.json`
  - 使用同一套 4 座原料下载塔和 54 个生产节点。
  - 11 座量子供应塔把 54 种制造物品及生产副产氢上传至全局量子库存。
  - 原料下载端不会直接回接上传端，避免无意义地循环占用量子带宽。
  - 19 座单体微型黑洞以 57 条最低优先级线路销毁无法上传的制造产物和副产物。
  - 共 88 个设备节点、216 条逻辑线路。

## 共用参数

- 1 万版的每个物流塔、生产设备和物资配送枢纽 `machineCount` 都精确为 `10,000`；10 万/s 版使用按配方负载计算的不同堆叠数。微型黑洞属于唯一巨构，引擎强制每个节点为单体 `1`。
- 所有线路使用传送带 Mk.III、最大允许并联数 `4,096` 和 4 层货物堆叠。
- 上游生产输入使用优先级 2，配送/上传末端使用优先级 1，黑洞溢流使用最低优先级 0。只有下游和正常目的地都接收不下时，剩余产物才进入黑洞。
- 熔炼、制造和化工分别使用位面熔炉、制造台 Mk.III 和量子化工厂；专用配方仍使用原油精炼厂、分馏/对撞、能量枢纽或射线接收站。
- 稀有资源路线优先使用可燃冰、刺笋结晶、分形硅、单极磁石、光栅石和金伯利矿配方。
- 电磁、能量、结构、信息、引力和宇宙矩阵全部排除；所选生产配方也不消耗任何矩阵。

## 使用前提

1. 解锁整条生产链、星际物流站 Mk.II、量子物流网络和微型黑洞约束工程，并保证量子库存已有 18 种原料。
2. 准备足够施工库存，包括 19 座微型黑洞。1 万版仅传送带 Mk.III 分别需要 958,464 条（配送版）或 884,736 条（量子上传版）；10 万/s 版的需求见上文。库存不足时可进入待建队列。
3. 给流水线接入足够电力。蓝图没有附带发电设施；10 万/s 版的长测使用了充足的独立测试电源，实际存档也必须满足满功率条件。
4. 临界光子节点必须放在已有戴森云/球功率的恒星系，否则射线接收站会等待能量。
5. 使用配送版时，建议把所在行星每种物资的托盘上限设为 100,000,000，避免配送枢纽很快堵塞。

## 黑洞溢流安全

这两张蓝图按明确用途把 19 座微型黑洞设置为“部署后启用”。它们会永久销毁已经走完最低优先级溢流线路的物品，无法恢复；累计销毁量从 0 开始。若不希望自动销毁，请在导入前删除 `black_hole_overflow_*` 节点及其线路，或把对应节点的 `operationEnabledOnDeploy` 改为 `false`。

导入后，量子塔会在满足科技和安全交接条件时按蓝图意图接入共享网络。已有传统星际尾货不会被蓝图强行清除。

## 重新生成与校验

在仓库根目录运行：

```powershell
node scripts/generate-all-material-blueprints.mjs
node scripts/generate-all-material-blueprints.mjs --check
node scripts/generate-100k-all-material-blueprints.mjs
node scripts/generate-100k-all-material-blueprints.mjs --check
node scripts/analyze-all-material-blueprint-throughput.mjs --profile=10k
node scripts/analyze-all-material-blueprint-throughput.mjs --profile=100k
node scripts/generate-ray-receiver-material-blueprints.mjs
node scripts/generate-ray-receiver-material-blueprints.mjs --check
node scripts/analyze-ray-receiver-material-blueprints.mjs
```

生成器会执行蓝图交换格式往返校验，并在匿名、全科技、足库存的临时游戏状态中真实放置蓝图，核对设备数量、线路数量、配方、配送端口、量子供需槽以及黑洞单体/启用/端口/优先级规则。全物品产量分析器执行 8 小时预热、4 个 2 小时采样窗口和完全重复运行校验；射线接收站专用分析器按 0.1 秒在线步长执行 120 秒预热、4 个 60 秒采样窗口，并对两版各完全重复一次。
