## 发布结论

`1.0.37` 已完成香港、上海 Web/API、上海下载页、Android stable APK 和 Windows stable 测试包发布。两地 Web/API 当前均为 `web-1.0.37-853ecdb12795` / `api-1.0.37-853ecdb12795`，上海下载站为 `download-site-1.0.37-853ecdb12795`。Web/API 与下载页直接代码回滚均为完整 `1.0.36-e0ad49062fa3`；代码回滚不恢复数据库。

本版修正旧存档资源目录可能引入幽灵单极磁石的边界，提供只读审计和有确认/回滚约束的人工工具；横向科技树覆盖多输入方式与多字号；普通离线的不可靠候选改为玩家决策，速通继续 exact-only；星图增加轨道收集器批量接入量子网络。GameState v46、存档 envelope v2、云 schema v7、SQLite layout v2 和排行榜协议均未变化。

用户明确豁免精确候选 `1.0.37-853ecdb12795` 的 Android 真机、低配 Windows、`1.0.36 → 1.0.37` 覆盖升级和约一小时后台门禁，并接受交接记录的性能残余风险。该豁免不等于测试通过，也不适用于后续版本：23.5 MB 真实档端到端快速离线约 36.5～36.8 秒，30 天非关键估计误差约 81.5%，16x 关键误差上界为 1.0，60 秒精确模拟约 12.75 秒。

## 原子切换与观察

顺序为香港 Web/API 灰度 → 上海 Web/API → 上海下载页。Web/API 使用固定 `/usr/local/sbin/dsp-idle-switch-release`，切换时暂停健康、节点和对应异地备份/恢复 timer；香港使用扩展健康窗口并等待自动 COS 快照回到 `ready`，成功后恢复全部 timer。上海下载页使用受保护状态文件、临时 symlink 和 `nginx -t` 原子切换。

香港灰度期间一次只读 `/api/admin/metrics` 大库治理聚合在客户端 60 秒超时后继续占用 Node 主线程，导致匿名 analytics/presence/public-status/errors 和一条 health 请求短暂出现 106 条 502/504；没有云存档写路径 5xx。发布流程立即停止推进上海，暂停 timers 并受控重启当前 1.0.37 API，等待自动备份重新 `ready`。随后轻量健康 20/20 通过，最小/平均/最大为 0.9/13.7/143.2 ms；新进程 journal 关键错误 0、`NRestarts=0`，最近 200/50 条访问 5xx 均为 0。确认稳定后才继续上海和下载页。该事件不是功能回滚，也不能从发布记录中省略；大库管理员聚合端点仍需后续异步化或分页治理。

发布收口时香港/上海新 API uptime 分别超过 1,460/728 秒；两地服务 active、`NRestarts=0`、备份状态 `ready`、timer active，最近 200 条 Web/下载 5xx 均为 0。根盘约为香港 83%、上海 83%；没有删除生产数据库、当前版、直接回滚版或有效发布前备份。

## 明确未验证与后续风险

- Android 物理真机、低配 Windows、`1.0.36 → 1.0.37` 实机覆盖升级、约一小时锁屏/后台、温度/耗电和长时内存未执行，由用户只对本候选明确豁免。
- Windows 仍无 Authenticode 证书，继续按公开测试包策略标记 `NotSigned`。
- 23.5 MB 真实档端到端快速离线、长窗口非关键估计误差、16x 关键误差上界和 60 秒精确模拟性能风险按用户书面接受保留，不能描述为已优化消除。
- 香港约 3 GB 数据库的管理员完整治理聚合可能阻塞事件循环；发布与日常监控继续使用轻量健康，治理指标必须后续改为有界、分页或异步任务。
- COSFS 的 Node `copyFile` 曾对本次完整加密对象返回 `EIO`；人工重试与双端哈希已恢复本次备份，但传输工具仍需增加流式重试、目标哈希和原子状态恢复。
