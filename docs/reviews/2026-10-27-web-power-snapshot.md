# 时间扭曲供电准备：省去无关运输线索引

状态：功能与浏览器回归通过，正在冻结构建；未发布。用户已要求恢复持续性能优化；本轮之后继续排查转换时的复制与保存开销。

## 给玩家看的结果

同一终局大档中，时间扭曲的供电准备不再建立用不到的整套运输线查询表。

| 测量项目 | 优化前 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 供电快照刷新，三组中位 | 1.173 秒 | 0.421 秒 | 64.1% |

这个数字只代表供电准备步骤，包括既有状态复制，不包含整个进入/退出过程。
完整页面仍有存档、校准和主线程转换开销，不能据此宣称整体帧率或内存已改善。

## 范围与实现

角色 develop，任务 web-power-snapshot-20261027，P1；来源为香港网页版持续性能优化的直接授权。
维持 GameState v47、存档封套 v2、材料守恒、供电分配规则、配方优先级及自动备份停用设置。
本轮没有发布、修改服务器、迁移存档或调整原生引擎。

[engine.ts](../../src/game/engine.ts) 的私有索引构建器按调用目的选择是否建立运输线运行目录。
`refreshTimeWarpPowerSnapshotInPlace` 保留实体、电网、机器、物流塔和在途货物相关索引，
仅跳过该计算不读取的运输线 Map、邻接表与路线目录。
普通模拟仍通过公开 `createSimulationLookupContext` 建立完整索引并遵守原持久顺序。
公开不可变供电刷新仍保留原状态复制语义，未将存档字段改为共享可变引用。

[新增测试](../../src/game/timeWarpPowerSnapshot.test.ts) 对供电路径安装禁止读取运输线的守卫，
覆盖正常供电、禁用、缺失控制器以及冻结输入下的状态和库存保留。

`fa4b11d37ea8c011d9d025db9497d40238ec616902015c57e95576d36b3bbea5`，实际倍率均为 8。

## 整页结果与剩余瓶颈

使用旧版 1.3.2 冻结 Web 包及新候选生产构建，在原库存条件下分别推进约 40 个模拟秒，
随后通过实际按钮进入 8 倍产率复制、观察 5 个墙钟秒并停止结算。六次均完成有效主档读回，
实体数、运输线数、暂停状态和副本中禁用自动保存的设置保留。

| 实际页面指标，三组中位 | 旧版 | 新版 |
| --- | ---: | ---: |
| 普通模拟预热等待 | 48.010 秒 | 47.969 秒 |
| 停止并保存等待 | 17.719 秒 | 17.543 秒 |
| 进入阶段最长画面间隔 | 1.191 秒 | 1.164 秒 |
| 退出阶段最长画面间隔 | 1.323 秒 | 1.366 秒 |
| 渲染进程旅程峰值工作集，十进制 GB | 5.411 GB | 5.624 GB |

整页差异不足以形成稳定的总体提速结论，内存中位反而约高 3.9%。工作集是整个测试旅程的
进程峰值，不等于供电函数净分配；本轮没有证明内存改善。三次旧版停止等待为
18.286、17.299、17.719 秒；三次新版为 29.837、17.543、17.436 秒。
新版第一例在普通模拟、进入和退出多个阶段都明显变慢；保留该例参与所有汇总，原因未确定。
内存、长帧和退出等待仍是后续门槛，不将这一步局部收益写成“全程丝滑”。

普通运行另做一次固定 30 模拟秒的旧/新对照，不补充材料，完整状态 SHA-256 均为
`932decef7a8a201cfd01ea46cdb96118360f4ce917523283930a892bae3720a5`，
量子网络 SHA-256 均为 `f497973e3429e51dbb8a56185fe0233b2b5e3e581157cfdf0e37f12de63212d5`。
推进耗时为 18.881 / 19.179 秒；该单组只用于兼容性检查，不据此声称普通模拟加速。
