## 执行方法与资源约束

- 2026-11-05 用户再次确认优先让出电脑资源。轻量源码审查持续；测试进程 Idle、单核心、单浏览器 worker、每 Node 进程 2 GiB 堆上限。内存连续四次、间隔 5 秒达到 8 GiB 才启动下一检查，低于门槛就等待，不靠增加并行度抢占资源。
- 实测发现隔离 Chrome 的 GPU/渲染子进程会自行升至 AboveNormal/Normal，而同核测试驱动仍为 Idle。这是测试调度混杂因素，不是游戏提速证明。增加最长 20 分钟的本轮进程树守护，只将本次测试根进程的 Chrome 后代降回 Idle；守护程序在另一逻辑核心以 Idle 做稀疏检查，测试仍单核心、单 worker。没有修改其他项目或日常浏览器进程，不能把堆上限说成整浏览器内存上限或承诺零影响。
- 只用合成存档、隔离浏览器和本机回环地址；不开生产写测试，不登录玩家账号，不读取/上传真实玩家正文，不 SSH 或修改生产。
- 已通过门禁与待验证候选分开记录。没有新的真实百 MB 存档、整体 FPS、低配长时或实体手机输入法数据，不给全游戏虚构百分比。

## 第二批：文件选择与手势中断

- 在正式 1.3.7 冻结包复现三个文件失败用例：空文件没有就地错误、损坏 gzip 后残留旧预览及确认按钮、内容包读取拒绝没有反馈。修复后这三项已在构建网页验证通过；新选择先调用现有取消预览接口，再按原 256 MiB 存档边界读取，不写入主档。
- 新增共用 `useFileImport`，用于存档、只读内容包检查、内容包注册三个入口。显示读取/失败状态，允许同文件重试；请求代次和卸载失效保护阻止迟到的旧读取调用导入器，导入检查期间保持读取状态。旧内容包结果在新读取/失败期间隐藏，不改内容包格式或任意新增体积限制。七项单元覆盖顺序、卸载、读失败及检查失败。
- 横向拖动、抽屉下滑和长按增加 `lostpointercapture` 收尾；容器内部正常捕获转移不误取消，释放捕获前先清理状态，避免嵌套事件导致重复关闭。原实现三项失败已留证；中断、迟到事件、多指和正常完成控制均在单元检查通过。

## 第三批：真实触摸释放点击

CDP 触屏事件在构建网页复现长按设备菜单出现后，松手产生额外点击，使菜单消失。原先只派发 `pointerdown/up` 的测试不会生成浏览器兼容点击，无法覆盖此问题。仅拦画布尾随点击的候选在第 08 轮仍失败，证据保留；追加菜单背景的同指针按下/抬起判断，避免将菜单出现前开始的长按松手当成背景关闭。普通后续点按和键盘激活保留，已有端口长按拉线继续由原端口逻辑处理。实际触屏用例在松手后再次断言菜单可见，检查关闭按钮、背景正常点按及取消触摸不会延迟弹出。

最新相关单元为 **57 文件 / 327 通过 / 0 跳过 / 0 失败**（`final-unit-09.json`）；类型、第 09 轮 Web 构建/启动预算/原生边界通过。CDP 触屏专项 **1/1**（`focused-browser-09.json`），包含松手保持、关闭按钮、真实背景点按与取消触摸。`completion-exit-09.json` 核对该轮 src/tests/原生清单身份始终相同；不累加此前 322/325/327 项轮次，也不把这个 grep 子集说成整版回归。
