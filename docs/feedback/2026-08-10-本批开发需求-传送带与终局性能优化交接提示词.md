## 3. 需求一：新建传送带默认并联数量

### 用户需求

在设置中增加“新建传送带默认并联数量”选项。玩家可以选择 1、2、4 或自定义正整数，最大值为 4096。设置为 4096 后，后续新拉出的传送带默认使用 4096 条并联线路，不需要每次手动调整。

### 数据语义必须确认

本需求中的“4096 堆叠”应解释为传送带的 `lanes`，不是货物堆叠 `stackSize`。

- `lanes`：传送带并联线路数量，当前系统上限为 4096；
- `stackSize`：货物在传送带上的堆叠数量，当前通常是 1、2、4；
- 不能把货物 `stackSize` 设置为 4096；
- 必须沿用现有传送带容量公式、科技限制和材料消耗规则。

### 适用入口

默认值至少适用于：

- 桌面端鼠标拖动拉线；
- 点击式连接；
- 连续拉线；
- 批量拉线；
- 移动端拉线；
- 蓝图放置时新生成的传送带；
- 传送带复制、批量增加或自动连接操作。

### 规则

1. 只影响新创建的传送带，不修改已有线路；
2. 自定义值必须是正整数；
3. 输入 0、负数、小数、文字或超大数字时显示明确提示；
4. 最终值不能超过 4096；
5. 材料消耗必须按照实际 lanes 数量计算；
6. 材料不足时整条操作原子失败，不能只生成一部分线路或丢失材料；
7. 不得绕过已有科技、建筑和线路数量限制；
8. 新建传送带失败时，必须显示缺少的数量和原因；
9. 设置必须在刷新、重新进入和存档恢复后保持一致；
10. 如果该设置属于设备级偏好，应沿用项目已有的 localStorage 设置规范，不写入 GameState。

### UI 与测试

设置界面需要显示当前值、最大值、常用预设、自定义输入和恢复默认按钮。

必须测试桌面端、经典手机端、新版手机端、横屏/竖屏以及 80%、100%、125%、150%、200% 字号。

## 4. 需求二：火力发电站支持燃烧可燃冰

### 用户反馈

火力发电站目前可以燃烧氘核燃料和反物质燃料，但不能燃烧可燃冰。需要核查是否为燃料兼容列表遗漏，并在设计允许时加入可燃冰。

### 实现要求

1. 先从内容目录确认可燃冰的真实 `ItemId`，不得凭空假设字段名；
2. 检查燃料定义、火力发电站允许燃料列表、单位能量和消耗速度；
3. 如果设计允许，将可燃冰加入火力发电站的合法燃料列表；
4. 可燃冰的单位能量和效率必须按照现有燃料体系平衡；
5. 不得因为支持可燃冰而绕过燃料消耗、供电效率或缓存规则；
6. 如果存在副产物，必须使用现有库存和守恒逻辑处理；
7. UI 燃料选择器、燃料耗尽提示、发电统计和生产统计必须同步支持；
8. 不能破坏煤、高能石墨、氢、氘、氘核燃料和反物质燃料。

### 回归测试

至少覆盖：可燃冰单独燃烧、不同燃料并存、燃料耗尽、输入缓存满、发电站供电不足、多个火力发电站同时运行、离线结算和时间扭曲。

## 5. 需求三：传送带活跃线路结算优化（P0）

### 优化目标

把传送带从“每秒全面处理所有线路”逐步改为“只处理有流量、有缓存变化或状态发生变化的线路”。

目标样本包括：

- `C:/Users/WINDOWS/Downloads/dsp-idle-save-2026-08-09.json`；
- `C:/Users/WINDOWS/Downloads/dsp-idle-save-2026-08-07 (1) (1).json`；
- 项目内合成传送带压力测试夹具。

### 星球级运行索引

为每个星球建立可重建的运行时索引，至少考虑：

- `beltById`；
- `sourceToBelts`；
- `targetToBelts`；
- `itemToBelts`；
- `activeBelts`；
- `blockedBelts`；
- `inputStarvedBelts`；
- `outputFullBelts`；
- `powerLimitedBelts`；
- 同物品/同等级/同网络的批处理分组。

索引优先作为运行时缓存，不要直接持久化为新的权威存档数据。缓存失效时必须能够安全重建。

### 线路状态分类

至少区分：

1. 有实际流量；
2. 完全空闲；
3. 输入不足；
4. 输出缓存已满；
5. 线路堵塞；
6. 电力不足；
7. 等待物流或建筑；
8. 状态不确定，需要回退完整计算。

### 重新加入活跃队列的事件

以下事件发生时，相关线路必须重新加入活跃队列：

- 起点库存变化；
- 终点输入缓存变化；
- 建筑输出缓存变化；
- lanes 变化；
- stackSize 变化；
- 优先级变化；
- 路由变化；
- 供电变化；
- 建筑配方变化；
- 建筑新增或删除；
- 传送带新增或删除；
- 物流塔供应/需求状态变化；
- 量子库存或跨星球可达性变化。

不得把每秒刷新 `flow` 或 `lastFlow` 本身当作结构变化。

### 批量结算边界

只有满足以下条件的线路才允许批量结算：

- 同一星球；
- 同一物品；
- 同一传送带等级；
- 同一 stackSize；
- 同一优先级；
- 同一路由模式；
- 同一供电条件；
- 相同输入/输出状态。

以下情况不得直接合批：

- 不同优先级；
- 混带；
- 四向分流器或其他特殊路由；
- 不同目标端口；
- 不同路由偏移；
- 不同供电状态；
- 不同堵塞状态；
- 影响顺序的线路。

批量处理必须使用稳定、可复现的排序，例如项目已有的 `planetId → networkId → itemId → priority → beltId` 规则。不要依赖对象遍历偶然顺序。

### 运行字段和守恒

重点审计：

- `flow`；
- `congestion`；
- `lastFlow`；
- `progress`；
- `totalTransferred`；
- routing cursor；
- 临时调度标记。

可重新计算的诊断字段可以从持久化存档中分离，但不能删除影响生产连续性的字段。所有产量、库存、缓存、在途物资、运输船、运输机和翘曲器必须守恒。

### 性能目标

在传送带密集终局存档上，以实测基线为准，目标为：

- 传送带模块耗时下降 40%～65%；
- 19 MiB 存档 60 秒精确模拟从约 12.1 秒降至约 7～9 秒；
- 单秒 P95 从约 1,058ms 降至 400～650ms。

这些是验收目标，不是未经测试的承诺。如果状态哈希或库存不一致，性能提升不得算作成功。

### 必测场景

- 空闲线路；
- 输入不足；
- 输出缓存已满；
- 传送带堵塞；
- 混带；
- 四向分流器；
- 不同线路优先级；
- 同物品并联线路；
- 不同等级和堆叠；
- 线路新增、删除和修改；
- 建筑配方修改；
- 供电中断与恢复；
- 传统物流塔和量子塔混用；
- 离线、纯挂机和时间扭曲。

## 6. 需求四：高密度星球画布内存和交互优化（P0）

### 目标

解决高密度星球上的：

- 暂停后拖动仍然卡顿；
- 缩放和 Fit View 长时间无响应；
- React Flow 节点/线路对象占用过多内存；
- `DataCloneError: Data cannot be cloned, out of memory`；
- `Should not already be working`；
- 线路过多导致移动端崩溃或无法点击。

### 渲染策略

高密度星球不应继续让全部传送带都保留完整 React Flow 命中层。

建议：

1. Canvas 绘制普通线路；
2. 空间索引负责线路命中；
3. React Flow 只保留当前视口、选中、悬浮、正在连接和寻线相关线路；
4. 远处线路不创建完整 DOM Edge；
5. 线路点击后再临时创建详细显示；
6. Canvas 失效时自动回退到可用的安全线路模式；
7. 不能为了减少 DOM 而失去蓝图、拉线、选中或移动功能。

### 节点轻量投影

节点显示数据只保留：

- 位置；
- 建筑类型；
- 配方 ID；
- 运行状态；
- 输入输出摘要；
- 选中状态；
- 命中信息；
- 当前视图需要的显示字段。

不要给每个节点重复携带完整科技树、全星系数据、完整戴森状态、全局运输网络或无关星球数据。

### 增量刷新

避免：

```text
一个建筑状态变化
→ 重建整颗星球所有节点
→ 重建全部线路
→ 重新诊断全部传送带
```

建议拆分和复用：

- `topologyRevision`；
- `runtimeRevision`；
- `nodeRevision`；
- `beltFlowRevision`；
- changed entity IDs；
- changed belt IDs。

移动建筑时，只更新被移动节点、相邻线路、空间索引和对齐线。

### 自动进入轻量模式

可以根据以下条件建议或自动进入轻量画布：

- 当前星球实体超过 700；
- 当前星球传送带超过 1,500；
- DOM 数量超过安全阈值；
- FPS P95 低于目标；
- 浏览器堆内存超过阈值。

必须保留玩家设置和安全回退，不得静默关闭关键交互。

### 画布验收目标

在约 900～1,000 个实体、2,000～2,500 条传送带的星球上：

- 暂停拖动 P95 小于 16.7ms；
- 不出现 DataCloneError；
- 不出现 React scheduler 错误；
- Fit View 目标 3 秒内完成；
- Chrome 画布堆内存目标低于 200MB；
- 建筑、线路、蓝图、拉线、寻线、移动端触控均可用。

## 7. 需求五：生产和缓存批处理优化（P1）

### 当前压力

- 生产实体约 6,449 个；
- 建筑堆叠约 8.72 亿；
- 输入输出槽位超过 44,000 个；
- 生产、缓存和递归制造字段较多。

### 分组计算

可以按照以下维度分组计算：

```text
planetId
buildingId
recipeId
生产倍率
供电倍率
增产剂状态
输入可用状态
输出容量状态
```

分组只允许共享计算，不得合并独立建筑缓存。

### 缓存守恒

必须保证：

- 每个建筑输入缓存独立；
- 每个建筑输出缓存独立；
- 输出满时不能继续扣输入；
- 输入不足时不能凭空完成生产；
- 副产物不能丢失；
- 液体、氢、反物质等特殊物品仍然守恒；
- 递归制造不能形成无限循环；
- 增产剂耗尽后按正常倍率继续生产；
- 建筑制造中心不会因为缓存上限或中间产物阻塞永久卡死。

### 进度和整数

- 玩家库存必须是非负整数；
- 连续生产进度使用隐藏的小数余量；
- 批量提交时再结算整数产出；
- 不得把浮点误差写入可见库存；
- 不得超过安全整数后静默丢失精度。

### 测试

必须覆盖矩阵研究、喷涂、液体、氢、副产物、递归制造、建筑制造中心、输入不足、输出堵塞、增产剂耗尽、供电不足、时间扭曲、离线和纯挂机。

生产模块目标下降 30%～50%，但最终结果必须与旧路径一致。

## 8. 需求六：物流塔脏标记和批量调度优化（P1）

### 目标

将“每秒扫描所有塔和所有槽位”改为“只有状态发生变化的塔和槽位重新匹配”。

### 调度索引

按照以下维度建立运行时索引：

- `planetId`；
- local / remote；
- quantum / legacy；
- `itemId`；
- supply / demand；
- priority；
- power state；
- warper availability；
- transport capacity。

### 脏标记事件

以下变化必须标记相关塔或槽位：

- 供应数量变化；
- 需求数量变化；
- 槽位物品变化；
- 最低库存变化；
- 优先级变化；
- 供电变化；
- 运输船数量变化；
- 运输机数量变化；
- 翘曲器数量变化；
- 量子库存变化；
- 线路接入或断开；
- 物流塔新增或删除；
- 跨星球可达性变化。

### 批量请求约束

同一物品、同一范围、同一优先级的请求可以批量生成，但必须保证：

- 供应/需求优先级不变；
- 运输船分配顺序稳定；
- 翘曲器消耗正确；
- 在途货物不重复；
- 供应塔不会被重复占用；
- 量子塔和传统物流塔不会互相污染。

量子共享库存和传统运输必须分开结算，不得为了跳过传统扫描而遗漏运输船、运输机、翘曲器或本地缓存状态。

目标是物流模块耗时下降 30%～50%，调度重复扫描次数下降 60% 以上。

## 9. 需求七：存档结构与体积优化预研（P2）

### 当前情况

实体和传送带占大存档体积约 94% 以上。此项先做审计和原型，不得直接删除字段或强制迁移。

### 字段分类

逐项划分为：

1. 权威玩法数据；
2. 可重新计算的运行时数据；
3. 仅 UI 显示数据；
4. 性能缓存；
5. 旧版本迁移所需数据。

### 研究方向

- 删除可安全重建的运行时索引；
- 将线路拓扑和运行状态分离；
- 传送带使用紧凑数组或压缩结构；
- 删除重复全局数据；
- 序列化和压缩放入 Worker；
- 云上传使用流式压缩和分块上传；
- 保持 checksum、导入导出和恢复能力。

### 不得删除的数据

- 建筑输入输出库存；
- 生产进度；
- 递归制造状态；
- 物流塔库存；
- 量子库存；
- 在途物资；
- 传送带实际进度；
- 建筑堆叠数量；
- 科技、任务和戴森进度。

### 兼容性测试

必须使用 v46 存档、旧版本存档、普通模式、速通模式、本地保存、IndexedDB、云上传、云下载、导出导入和 checksum 校验进行测试。

如果需要升级存档版本，必须先提交独立的迁移设计、备份和回滚方案，不得与本批性能修改直接绑定上线。

- 1 秒切片 P50/P95/最大耗时；
- 物流、传送带、生产、电力和量子耗时；
- Worker 传输大小；
- 浏览器和 Node 内存；
- 状态哈希；
- fallback 次数；
- 库存、缓存和在途物资差异。

### 确定性对照

至少比较 1、4、12、60、600 秒、1 小时和 1 天。必须比较完整状态哈希、库存、缓存、传送带进度、物流塔库存、量子库存、运输船、运输机、翘曲器、在途物资、电力、科研和戴森数据。

### 多 Worker

按单 Worker、2 Worker、4 Worker、8 Worker 顺序测试。只有在完整哈希一致、库存守恒、无跨星球偏差、内存安全且实际速度提升至少 15% 后，才允许讨论默认开启。

### 画布

测试普通模式、终局极限模式、暂停拖动、运行拖动、缩放、Fit View、线路点击、建筑点击、蓝图、拉线、寻线、移动端、横竖屏和 80/100/125/150/200% 字号。Canvas 失败时必须验证安全回退。
