# Rust 开发第三批完整报告｜2026 年 9 月 9 日

**这一批完成了“让普通玩家的正常存档真正用上 Rust 短离线计算”的接入，并通过 Windows 实际游戏流程验证。代码已提交，尚未发布；本批没有新的终局玩家提速百分比。**

## 1. 这次解决了什么

上一批的新引擎已经能读取存档、计算并返回结果，但还没有接到“继续游戏”按钮。此前的一条路径还要求额外准备一份完全匹配的原生检查点，而正常游戏保存不一定产生这份文件。

现在，游戏可以把已经验证的普通存档分批交给 Rust 临时计算。玩家不需要手工转换存档，也不需要先生成另一套原生存档。计算成功后，游戏核对完整结果，再沿用正常保存流程。

可以理解为：前面是在验证新发动机，这次把它接到了正常使用的入口。

## 2. 本批完成的功能

- **正常存档接入：** 点击“继续游戏”时，符合条件的短离线状态可以直接交给 Rust。
- **大档传输准备：** 来源分块传送、逐块确认，避免为上传一次性再生成完整 JSON 字符串和整块字节数组。完整状态证明和返回结果仍有开销，终局表现需要下一批测量。
- **取消保档：** 本次计算使用独立临时进程；取消只结束它，不接管正在游玩的引擎，也不覆盖原存档。
- **成功后清理：** 结果传回并验证、临时文件清理完成后，才向游戏报告成功。
- **旧路径兼容：** 条件不符或验证失败时，保留原始状态，继续使用现有结算流程。

| 检查 | 本批结果 | 对玩家意味着什么 |
| --- | --- | --- |
| 普通存档直接继续游戏 | 通过 | 没有额外原生检查点也能采用 Rust 结果 |
| 游戏内“立即保存”后关闭、再进入 | 通过 | 正常游玩产生的存档也能走新入口 |
| Rust 已算出候选后点取消 | 通过 | 原普通主档不变，没有悄悄提交离线收益 |

| 完整单元测试 | 3,159 通过，39 跳过，0 失败 | 核心与共享功能回归通过 |

三组桌面场景使用公开合成工厂，110 个实体、2 条传送带，各结算真实经过的 5 秒。自然保存场景确实点击了游戏内保存按钮，未额外写入原生检查点。

测试中曾因能力清单过期而构建失败，已补齐生成清单；Windows 标准输出目录有文件占用，最终通过项目现有备用目录完成打包。原始失败记录保留，构建门槛没有降低。

## 4. 现在能获得多少性能提升

**本批最直接的进展是普通存档入口可用，尚不能给出“终局工厂从此快了多少”的新数字。** 公开小工厂的正确性验证不能代替大工厂性能测试。实际界面测试还与浏览器回归同时进行，其计时不作为独立性能对照。

此前已经测得的局部 Rust 提速保留各自范围，例如开档或精确计算步骤；不能把多个百分比相加，也不能直接当成点击到可以操作的完整等待缩短比例。

目前仍只自动采用 **1–30 秒的精确离线结果**。长达几分钟、几小时的离线，以及正常游玩时的实时模拟，并没有因为本次接入而交给 Rust。

## 6. 总体进度与接下来的顺序

当前仍在 RP1“离线 Rust 接入与收益验收”阶段。可以明确完成的里程碑是：底层能够计算，短样本完整结果一致，普通保存来源能够进入 Rust，取消与持久保存重开通过。**RP1 总验收仍未完成，更没有完成全面 Rust 化。**

接下来优先做：

1. 按你的要求把后续桌面验证改为后台方式，不显示游戏窗口、不切换前台、不抢焦点。旧的可见驱动不再直接运行。
2. 使用已授权终局存档的副本，测量从点击到能操作的完整等待，做多轮独立对照，找出传输、校验、计算和保存各自的成本。
3. 根据真实瓶颈扩大有界离线计算范围，逐步验证更长时长及容量、矿量、研究等边界，继续保持完整状态和存档保护。
4. 后续再推进实时模拟接管及网页、安卓 Rust 接入。

历史上出现过一次尚未定位根因的 debug 堆异常；本批没有改 Rust 算法，也没有把这一旧问题宣称为已修复。它与终局完整等待、长离线范围等事项仍需后续验证。
