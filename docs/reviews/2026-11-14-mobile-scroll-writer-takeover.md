## 受控复现与原因

### 选择列表

在现代 Chrome 原生触控下，原选择器可以滚动。移除 CSS `inset` 声明并重新解析样式后，原弹窗 portal 高度为 0，列表可视高度约 485，内容高度约 9928，但原生触控滚动量为 0。

原 portal、遮罩及目录遮罩依赖 `inset: 0`。不支持该简写的内核失去视口高度约束。`inset` 的兼容范围可核对 [MDN 浏览器兼容数据](https://raw.githubusercontent.com/mdn/browser-compat-data/main/css/properties/inset.json)。这证明了一个可导致相同表现的兼容路径；原玩家的实际内核能力仍待回测。

### 接管与重新载入

当 Navigation Timing API 缺少或抛错，旧代码的同一个异常分支同时跳过了 sessionStorage 标签页身份处理。受控旧基线中，每次接管并刷新都生成新 writerId，新文档再次成为只读。

移动浏览器还可能不派发 beforeunload/pagehide。即使成功接管，依赖这些事件才写入的延续标记也可能丢失。独立故障注入组合缺失导航接口和卸载事件，复现并覆盖该路径。

另外，已关闭文档的普通 15 秒租约可能暂时保留。此前仅 Android 启动会在加载玩家候选状态前等待该租约自然到期；Web 启动直接进入只读。此处复用已有启动等待及比较交换保护。

### 视频中的快速结算提示

视频还显示“30 秒轻量校准没有形成可持续普通生产合同”的保守决策提示。它要求玩家选择精确结算、重试快速结算或跳过，属于已有离线结算保护。该算法本批没有修改。成品故障注入验证提示出现时原主档逐字保持，选择“使用精确结算”后进入工厂，测试库存 42 保留。该证据不等同于已经复测玩家原档或原设备。

## 实现与兼容边界

运行提交依次为 `d4a8e7ec7d085b7af9febbc4a9bf564a80bda016`、`91375af3361434983a92f6fe4eda7a96564030de` 和最终 `cd57a20b876c95523c89e57e4233f6e7eb911cf3`。

- `accessible-dialog.css`、`styles.css` 使用物理 top/right/left 和 height:100% 约束 portal 与遮罩，遮罩使用 border-box。保留三个边加高度，避免压缩器把四边重新合并成不兼容的 inset。实际编译 CSS 已核对。
- `localSaveStore.ts` 单独处理可选导航接口，保留 sessionStorage 处理，兼容旧 navigation.type；导出 `prepareLocalSaveWriterReload()`，在应用主动刷新之前记录标签页身份和一次性延续标记。
- `localSaveTakeover.ts` 的共用接管入口在成功结果返回之前记录延续标记，菜单及工厂入口共用。复制标签页仍取得新身份，过期或不匹配标记不能沿用身份。
- `analytics.ts` 将可选性能统计隔离，导航接口缺失或抛错不会再产生页面运行异常。
- 启动等待复用原 Android 逻辑，扩展到 Web，在 main.tsx 挂载菜单或加载候选状态之前执行。只等待普通短租约；owner/fence 变化、原持有者续约、页面隐藏或关闭会终止等待。长租约及原生权威不进入短等待，已经捕获玩家状态的只读页面也不会自动升权。
- `local-save-writer.css` 使用物理定位和 transform:translateX，保证缺少 inset 或独立 translate 的内核仍可看见并操作提示条。

验收要求是两个目录在横竖屏及大字号均可上下滚动，标题和关闭按钮可达；接管后的新文档保留同页身份，旧页失去写权；过期普通租约可以在启动阶段安全恢复；主档、库存及旧 IndexedDB 数据保持。GameState v47、envelope v2、云 schema8、SQLite layout3、模拟算法及原生权威门槛保持。
