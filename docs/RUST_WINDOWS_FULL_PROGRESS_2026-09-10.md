## 最新一批：阻止旧接口改动 Rust 权威状态

实际 RPC 负例确认：交接后旧 renderer 会被桌面层拒绝，但直接到达 Rust 的 `coreAdvance` 仍成功推进一秒。这段推进未经过玩家运行器的持久事务，会造成内存与已保存状态脱节。问题不是云存档损坏，本次也没有操作玩家原档。

Rust 现在先读取并校验实际持久租约，再处理旧命令和旧模拟：玩家权威已经准备或运行时，同一普通存档的旧接口拒绝执行，换一个会话 ID 也不能绕过。关闭旧会话会清理进程级历史上下文，因此玩家租约存在时也拒绝该接口；正常进程退出保留磁盘恢复路径。没有玩家租约的普通影子运行和既有 E1 实验合同继续保留。

实际跨进程场景在接管、暂停及三次重开后，各发送四种旧模拟、旧改状态命令和两个关闭请求，共 **35 次拒绝检查**。每轮确认主存档、恢复日志和租约文件的内容摘要未变，完整状态仍一致，再继续原 **62 秒生产科研和三次重开**。只把无数据的独占 OS 锁验证为存在且零字节；派生导出目录另行处理。

正常优化 RPC、调试 RPC 和五种租约状态/同存档别名检查已通过；完整优化 Host 库 **290 通过、5 ignored、0 失败**，完整桌面 Native 回归 **987 通过、1 项 Windows 权限条件跳过、0 失败**，普通 Host 构建和严格 Clippy 通过。首次组合检查在生产构建时发现二进制文件读取缺少 TypeScript 重载声明，因此该组合报告仍记 FAIL；补齐正确的 Buffer 返回声明后，单独补跑生产构建通过，包含类型、启动预算和界面边界检查，没有重跑已通过的完整 Native 套件。

正常优化 RPC 记录为 `owner-guard-release-v1/report.json`，Host/Clippy 为 `owner-guard-host-v1/report.json`，完整 Native 和初次构建为 `owner-guard-closure-v1/report.json`，修正构建为 `owner-guard-build-v2/report.json`。提交后专项使用 `owner-guard-rpc-committed/report.json` 记录实际源码提交；元数据检查另记 `owner-guard-metadata-v1.json`。最初的真实失败、测试读取独占锁的错误、损坏租约夹具目录错误均保留，未降低门槛或删除负例。当前仍为 **TEST_ONLY 授权**，并不证明正式玩家资格、真实浏览器落盘或完整游戏验收。

## 这条真实流程找出的三个问题

1. **新熔炉会误选铜锭。** Native 目录原先按 ID 排配方，原游戏按定义顺序选择默认配方。现在保留游戏顺序，并重新生成内置目录；五类机器的配方与解锁顺序有回归检查。
2. **切换配方或仓库物品后，完整存档字段不一致。** Rust 现在重现原引擎状态拷贝对新建筑两个空映射的初始化，以及退款前的行星托盘快照顺序。完整字段比较保持不变，JavaScript 引擎没有为测试修改。
3. **有真实科研进度后，暂停科研被拒绝。** Rust 自己产生的整数进度可能使用 1.0 表示。现在按数值判断安全整数；小数、字符串、布尔值、负数和超限数仍拒绝。

仓储命令只提交建筑和物品 ID，Rust 从当前权威状态计算库存和传送带退款，并写入原有恢复日志。没有交给界面计算或预扣库存。
