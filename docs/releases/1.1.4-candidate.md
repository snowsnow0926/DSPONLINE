## 发布边界与回滚

- Web/API、下载页、Windows、Android 必须作为同一完整发布完成；失败时不做跨目标部分发布。
- API/data-affecting 操作前必须分别在香港、上海创建并验证 SQLite Backup API evidence，保持磁盘低于 90% 保护线，保留数据库/WAL/SHM 与现有 current/previous/rollback。
- 使用新不可变目录、远端清单复核和原子切换；不在服务器热改源码或数据库。
- 生产成功后将 1.1.3 设为 previous-stable，并保留直接回滚指针；数据库不随代码回滚。
- Windows 延续历史 `NotSigned` 策略，不创建证书；Android 必须保持批准长期证书连续性。
