## 本轮已经完成的收益阶段

Rust 离线结算已从“最多 30 秒”扩展到“8 小时以内、状态变化能完整证明的产线”，并完成新 Windows 开发包的真实保存与重开验证。设备与传送带合计最多 2,000 条，并保留内存和运算预算；终局大工厂的长离线仍要后续扩展。检查不通过时继续使用原结算流程，不会直接采用缺失生产进度的结果。

实际新 Host 已通过 10 分钟、8 小时及小数时钟/历史边界的 12 个完整状态候选对照。正常优化 Rust 核心 1,116 项、Host 272 项、完整 Native 工具 885 项、完整游戏 3,210 项及类型检查通过；专用或环境限制的跳过分别记录。首轮编译耗尽总时限、过宽测试预期和清单未更新的失败已保留，最终复验通过。

新包六组实测全部通过：10 分钟、接近 8 小时，以及容量触顶场景，分别完成成功保存和取消保档；每组两次重开一致。实际成功等待约 2.1 / 3.6 / 2.1 秒，测试是 110 个设备、2 条传送带的公共产线，不能代表终局大厂或稳定提速比例。全部 24 次游戏启动隐藏、静音、不聚焦，并正常退出；原档和线上服务未变。

代码提交 `a96250b0` 已推送，Windows 开发包已冻结，`NotSigned`，未公开发布。量子容量临界点的一些短瞬态仍交回原流程，不计为 Rust 支持；本轮完整云端检查尚待终态。[本轮完整记录](./reviews/rust-windows-complete-long-offline-2026-09-10.md)

## 上一批已经确认的进展

**本批最重要的进展：终局大存档的成功结算、保存和两次重开终于在同一新包中完整通过，取消保档也通过。** 测试使用约 108 MB、11 万设备、23 万条传送带的授权存档副本，原档未变。实际 Rust 计算 9 秒游戏时间，结果和原 JavaScript 完整重算一致，真正写入磁盘的数据也一致。

成功流程从点击继续到进入工厂、打开设置约 **87.3 秒**。这说明流程正确性取得进展，但对玩家来说仍然慢；目前只有一轮完整通过，不能宣传稳定提速。原来的失败记录仍保留，后续继续优化和做可重复的前后对照。

两组测试共 **八次后台游戏启动，八次正常退出**；窗口没有显示、没有声音、没有抢焦点。取消后主档没变，两次重开仍保持原状态。这里只验证实际 9 秒短离线，没有修改真实时钟或减少工厂，也不代表原存档积累的长时间挂机已经支持。

最新 `d97c7732` Windows 开发包已构建并冻结，76 项制品、79 个文件一致。Rust 和 Electron 现在都能独立核对安装包的版本与程序摘要，真实包内对照也通过；发现并修复了一处损坏文本未被拒绝的问题。272 项 Rust 测试、63 项进程等检查、类型和构建门禁通过。这是在为实时接管准备可靠依据，玩家实时接管仍关闭。

大存档取证工具使用分片传输，本次据此读回并校验了真实保存数据。工具的传输改动与游戏保存分别验证；没有改变玩家存档格式。

## 正在开发的性能改动

此前 9e 批次给 Rust 完整状态检查增加固定 1 KiB 缓冲，保留全部字段、顺序和校验算法。代码已通过完整核心、实际 Host 和完整终局结果对照；公开合成场景的校验耗时少约 **14.6%**。

真实终局存档固定计算 9 秒，三组前后配对的完整 Native 请求中位从 **49.90 秒到 49.02 秒**，约少 **1.8%**。样本区间重叠，其中一对还慢了一些，因此目前只观察到小幅差异，不能宣传明显或稳定的整段提速；这也没有包含菜单、进入工厂和后续保存的全部等待。

开发同时推进到实时接管的前置环节：桌面程序和 Rust Host 均能从自己的安装文件核对版本、源码标识和实际程序摘要。此前 main 专项 51 项通过、1 项权限限制跳过，本批 Host 新增验证另列在上方。内容与规则身份、可信时间和撤销条件、正式准入还要继续接，当前玩家实时接管仍关闭。技术细节见[本批记录](./reviews/rust-windows-host-installed-program-2026-09-10.md)。

已有的历史收益仍成立于各自冻结候选：公开大工厂的短离线完整等待曾从约 20.8 秒降到约 6.0 秒。这个结果不能推广成所有终局存档、实时游戏或最新候选都提速同样比例。
