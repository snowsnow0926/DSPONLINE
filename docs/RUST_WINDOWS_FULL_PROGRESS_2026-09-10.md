## 玩家能理解的实际进展

- 新建熔炉、储物仓和研究站，连接矿脉与仓库，实际生产并收下铁锭。
- 把仓库改为磁铁：原铁锭退回托盘，旧传送带退回施工库存；熔炉换配方、重新连线后继续产出磁铁。
- 给研究站投入矩阵，开始火力发电科技，暂停科研后进度不增加，恢复后消耗矩阵并完成科技。
- 整个场景实际推进 **62 个模拟秒**，包含原来的建造重试、暂停一小时不计时、已提交建造丢失确认后恢复。四个 Rust 进程、三次重开之后，完整状态与独立 JavaScript 引擎一致。
- 原生检查面板增加储运物品选择。当前跨进程产线使用普通储物仓；储液罐和分流器接入同一命令边界，尚未单独完成实包操作验收。

这是小型公开合成工厂的正确性结果，未使用玩家原档。调试和正常优化构建都实际执行通过，授权仍为 **cfg(test) 合成授权 / TEST_ONLY**，不能据此开启正式玩家入口或计算整体提速百分比。

## 这条真实流程找出的三个问题

1. **新熔炉会误选铜锭。** Native 目录原先按 ID 排配方，原游戏按定义顺序选择默认配方。现在保留游戏顺序，并重新生成内置目录；五类机器的配方与解锁顺序有回归检查。
2. **切换配方或仓库物品后，完整存档字段不一致。** Rust 现在重现原引擎状态拷贝对新建筑两个空映射的初始化，以及退款前的行星托盘快照顺序。完整字段比较保持不变，JavaScript 引擎没有为测试修改。
3. **有真实科研进度后，暂停科研被拒绝。** Rust 自己产生的整数进度可能使用 1.0 表示。现在按数值判断安全整数；小数、字符串、布尔值、负数和超限数仍拒绝。

仓储命令只提交建筑和物品 ID，Rust 从当前权威状态计算库存和传送带退款，并写入原有恢复日志。没有交给界面计算或预扣库存。
