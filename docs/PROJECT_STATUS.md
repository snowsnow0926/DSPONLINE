### 操作与分析

- 线路采用直接传送带连接，支持多输入、多槽物流站、自动物品/配方匹配、连接预览、吞吐预测和成功/失败反馈。默认会锁定施工托盘中已解锁且有库存的最高等级，耗尽后自动降级；已有并行线优先复用原等级，也可手动指定 Mk.I/Mk.II/Mk.III。
- 行星与星际物流现在允许供给站主动派车和需求站主动取货；每条在途航线记录真实载具所属站，载具占用、返航、翘曲扣除/退款和诊断均按所属站计算。两端都有空闲载具时可以共同承担运量，但不会重复预留货物或载具。
- 物流站的后续传送带会复用已有同物品槽，否则依次占用剩余空槽；玩家手动配置的槽位不会被覆盖，空槽耗尽、物品冲突和非法方向会返回具体原因。
- 分拣器 Mk.I/Mk.II/Mk.III 已从施工、制造、科技文案、图鉴和升级入口移除；传送带等级直接决定吞吐。v30→v31 将旧分拣器库存按等级等量退为对应传送带，并把旧线路/蓝图的 `sorterTier` 归一为线路等级，不删除线路。
- 四向分流器的优先模式按高（2）→标准（1）→低（0）逐级分配，同级线路轮流均分，只有高等级线路堵塞或达到吞吐上限后才向下一等级回退。
- 生产统计、网络诊断、跨星球物流诊断、工业规划、效率曲线、挂机压力测试和自动性能报告均有界面入口。
- 统计中心新增统一的全星球生产管理视图：按行星、设备族、物品和运行状态筛选设备，汇总各行星节点、产能与效率；缺料可沿输入线追踪到上游设备和原矿来源，堵塞可定位输出线与下游缓存，问题行可以直接跳转到对应设备或连续网络。

### 存档与在线服务

- 当前 clean 发布源码、香港与上海生产均为 `GameState` v46；存档封装格式保持 v2。1.0.43 不升级 GameState、存档 envelope、云 schema 或 SQLite layout；旧实体、线路、库存、科研投入、在途路线、量子库存、制造 WIP、太阳帆和戴森计划均沿用 v46 兼容边界。
- 自动保存选项为关闭、30/60/120 秒和 10 分钟，默认 30 秒；关闭周期保存不影响切后台、`pagehide`、卸载和返回主菜单的紧急保存。手机端存档摘要扫描降至 30 秒，全屏工作区或网页后台期间冻结底层画布快照更新。
- 本地主存档、槽位和快照不再持久化 `productionHistory`，内存统计曲线仍照常运行并在刷新后重新积累。主档、备份、快照和三个槽位使用 IndexedDB；主存档先写入、读回并校验，成功后才通知界面，配额异常只会清理自动快照并重试一次，最终失败会持续提示玩家立即导出。
- 本地主存档有校验和和上一份有效备份；自动快照最多 2 份、至少相隔 5 分钟，手动快照和 3 个手动槽位不会被自动清理。旧 localStorage 副本只有在 IndexedDB 读回一致后才删除；手动槽位与快照删除均要求连续两次确认并显示目标摘要。
- 离线模拟默认最多 7 天，可由终局研究逐级提高到 30 天。
- 当前工作区和线上云服务均为 schema v7。新账号使用 4～24 位 ASCII 字母、数字或下划线用户名和密码直接注册，邮箱初始为空；用户名忽略大小写且全局唯一。v1-v6 旧账号会确定性补充唯一用户名，原邮箱、密码、验证状态、会话、云存档和排行榜记录保持不变，并继续兼容原邮箱登录。
- 有效登录会话即可使用主云存档、手动槽 1/2/3、各槽历史恢复和主存档每 10 分钟自动同步。当前正式版本中，主槽每次成功上传或恢复后由服务端自动重算第一赛季排名，手动槽永不参与；无登录或无主存档不会入榜。排行榜匿名可读且不要求邮箱验证。注册、登录、退出和自动上传不会下载、替换或删除本地主存档、三个本地槽、备份或快照，云端下载和恢复仍需玩家明确触发。
- 正式代码支持腾讯云 SES 审核模板 API，并保留通用 webhook 作为回退。发送器未启用时，用户名注册、登录、全部云存档和排行榜照常工作；邮箱绑定、验证重发和找回密码标注尚未开放并返回明确错误。缺少完整 API 凭据或模板 ID 时不会伪装发送成功，线上邮件发送器仍为 disabled。
- 本地身份可以显式绑定或解除云账号，绑定元数据与 `GameState` 分离，不会改写本地工厂。
- 玩家进入工厂后发送匿名心跳；服务端只保存本机匿名 ID 的 SHA-256 哈希，并按节点统计累计、今日和最近 120 秒在线玩家。运营中心每 30 秒刷新这些聚合数据。
- 浏览器会按隐私分桶上报页面加载、LCP 和静态传输体积；运营后台显示 P75 档位，不保存原始时序、完整 URL 或玩家存档内容。
- 账号、改密、会话撤销、数据导出、注销和云修订恢复写入隐私最小化安全审计，只保留动作、时间、匿名化账号/IP 和客户端类别。
- 云端为每名玩家保存互不覆盖的主存档和手动槽位 1/2/3，各自维护修订、历史和冲突状态；手动云槽与本地手动槽一一对应，不会替换正在游玩的主工厂。有效登录会话下，主存档每 10 分钟检查并自动上传；失败只记录状态，不影响本地保存，检测到双端变化时会暂停并要求玩家选择。排行榜只读取主存档，服务端账号字段 `leaderboardVisible` 控制公开参与；退出后删除公开记录且后续同步不会重新加入，恢复参与时若已有主存档会立即回填。
- 服务端生产存储为 SQLite，每 6 小时备份一次，部署配置保留最多 30 份。layout v2 将紧凑账号/指标/存档元数据保存在 `app_state`，每个云存档修订正文独立存放在 `cloud_save_payloads`，避免普通写入完整重写全部历史。

- Nginx 模板提供 gzip、静态资源长期缓存、SPA 回退、安全响应头、TLS 和 `/api` 反向代理；线上是否启用必须以节点响应头为准。
- PWA service worker 使用确定性 build ID 隔离缓存版本，避免代码发布后混用新旧应用壳。
- systemd 配置包含云服务自动重启和每两分钟健康检查。
- 认证加密的异地备份、隔离恢复演练、五分钟公网/API/磁盘/TLS 探针和可选告警 webhook 已落地；6 项运维工具测试通过。香港每日备份与上海每月恢复 timer 均已启用，首份真实生产备份已在上海隔离恢复成功，恢复过程未留下明文 SQLite。

## 4. 版本基线

项目中同时存在三种版本概念，后续发布必须分别管理：

| 概念 | 当前值 | 用途 |
| --- | --- | --- |
| npm 应用版本 | clean 香港 Web 源码/制品为 `1.0.43`；香港 API、上海 Web/API、Windows 和 Android 均为 `1.0.42`；Android versionCode `1000042` | 1.0.43 仅发布香港 Web；两类原生清单与文件继续由上海下载节点提供 |
| 游戏状态版本 | clean 运行时源码、香港与上海均为 `46` | 1.0.43 不升级 GameState，继续保留旧版本迁移链 |
| 存档封装版本 | `2` | 校验和、元数据和导入导出格式 |
| 云服务 schema | 工作区与线上 `7`，SQLite layout `2` | v7 增加唯一用户名；layout v2 拆分云存档正文 |
| 本地身份 schema | `2` | 本地排行账本和可选云账号绑定，不属于 `GameState` |
| 内容包格式 | `2` | 声明式物品、建筑、配方、科技、动态传送带与安全字段覆盖协议 |

## 6. 已知风险与技术债

### P0：发布与数据安全

- 1.0.43 的 36.7 MB 正式附件在初次导入、确认进入、手动保存和返回主页上已完成正确性/耗时验收，但主动模拟 Continue→Pause 仍需 20,887 ms，Long Task 峰值 20,291 ms；玩家独立反馈运行接近不可玩。该项从现网性能残余提升为 1.0.44 P0，必须单独分析模拟推进/渲染/派生瓶颈，不能用本热修的 O(E+B) 迁移优化代替。
- 云服务仍是单进程、单 SQLite 文件架构；认证加密异地备份和恢复演练已经形成首个闭环，但仍需持续检查 timer、30 天密文保留期和每月恢复报告。
- 腾讯云发信域名与地址已经完成验证，正式代码已支持 SES API；正式环境仍缺少完整的审核模板 ID 和最小权限 CAM 凭据。用户名注册、登录、四槽云存档和排行榜不受影响；邮箱绑定、验证重发和找回密码仍返回 `503 EMAIL_SERVICE_UNAVAILABLE`。
- 账号系统已有设备会话撤销，但尚未实现异常地点检测、登录告警和后台人工账号处置。
- 排行榜指标由服务端从主云存档快照提取，不再信任客户端提交的指标；但服务端没有重新模拟完整工厂，仍不能抵御经过篡改且通过存档结构校验的数据。
- 上海入口是 HTTP，代码已禁止云登录；不能为了兼容旧地址而放开明文凭据传输。

### P1：性能与运维

- 香港 Nginx 仍将精确 `manifest.webmanifest` 以 `application/octet-stream` + `no-cache` 返回；1.0.42/1.0.43 字节与配置继承一致，Chrome manifest 解析及 PWA 安装/控制/离线更新门禁均通过。后续只能在独立 Nginx 热修中以配置备份、`nginx -t`、原子安装和回滚证据修正 MIME，不能在应用发布时顺手改生产配置。
- 两个节点已对 JS/CSS 启用 gzip，hashed asset 保持 immutable；Brotli、真实用户一周趋势和更细的资源预算仍可继续补充。
- `src/styles.css`、`src/game/engine.ts`、`tests/e2e/game-flow.spec.ts` 和 `src/App.tsx` 已经成为超大文件，修改冲突和回归成本较高。
- Web/服务端已有可复现清单、原子切换、健康检查和固定路径回滚工具，但仍缺少从提交到双节点灰度发布的 CI 流水线。
- 节点探针已覆盖外部可用性、API、磁盘和 TLS，管理员后台能读取状态；可选告警 webhook 与集中日志仍未配置。1.0.25 发布后仍需持续执行不删除当前版、回滚版或有效备份的保留策略。香港大库的在线手工 Backup API 在活跃写入下会产生高 I/O，本轮发布前备份曾触发健康探针重启；后续必须在低流量窗口诊断，不能在生产高峰连续重跑。
- 当前环境已有 Android SDK、ADB、API 36.1 模拟器与 JDK 21，并完成原生 APK 冷启动、覆盖安装和横竖屏检查；仍没有物理 Android 或 iPhone，缺少各连续 30 分钟的耗电、温度和真机帧率记录，不能用模拟器结果冒充。
- 手机新版壳层目前仍是双节点 opt-in 试用；阶段 0-3 已完成自动化与桌面 Chrome 触摸仿真，但阶段 4 的 Android Chrome、iPhone Safari、软键盘/PWA standalone、连续 30 分钟温度耗电和真实玩家对照数据尚未完成，因此不能切为默认。
- 银河活动已经改为长期开放，但个人贡献仍只写入本地存档，全服进度仍是冻结后的服务器时钟模拟曲线。服务端贡献确认、鉴权幂等、跨槽去重、反回滚、奖励领取和空间站本体仍未实现，不能把本地记录描述为服务器已收到。

### P1：产品与合规

- 当前物品、配方、科技和流程以《戴森球计划》高还原原型为目标。公开推广或商业化前，应做名称、美术、文案、数值和世界观的原创化审查，并取得专业法律意见。
- 当前是公开测试版，不应把“功能很多”误认为“生产运营成熟”。仓库已增加隐私政策、服务条款、数据导出/注销说明和安全报告规则；正式入口仍需提供可达链接，并完成运营主体、未成年人、备案和适用法律的专业审查。公开反馈治理仍需持续完善。

### 明确不在当前范围

- 黑雾或战斗系统暂不开发。
- 原创玩法扩展应排在稳定性、数据保护和发布工程之后。
