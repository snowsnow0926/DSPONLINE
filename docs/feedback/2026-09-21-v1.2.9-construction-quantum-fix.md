## 行为变化

原基线为 1.2.9 `0521eb63f179c78421b2dbed7216f46903d6a684`，开发分支为 `codex/fix-construction-quantum-water`。固定旧基线的原因与合成观察见 [复盘](./2026-09-21-v1.2.9-construction-quantum-water-review.md)。

| 问题 | 修复后的行为 |
| --- | --- |
| 高优先级槽缺货仍吞掉全局额度，中心有水也不能取 | 先求单物品可兑现量，再分全局下载额度；空请求不占用可交付额度，部分缺货只占用实际可供数量 |
| 单物品库存不足的二次分配丢失优先级 | 单物品和全局两个阶段均按优先级分组，普通请求使用高优先级实际交付后的余量 |
| 全局余数每次从相同端点开始 | 可选持久游标跨边界轮换；高优先级组不会把后续同级轮转游标重置 |
| 新任务忽略量子现成中间件 | 规划时考虑仓库实际现货，物料仍须经共享带宽配送进本中心缓存才可消费 |
| 旧任务停在缺原料的后缀 | 实际现成中间件送达后，只重建未提交后缀，保留已完成步骤和 WIP；不虚构物料 |
| 一个缺料目标拖住后续齐料目标 | 在已有计算预算内跳过本轮不可执行目标，保留它并在后续继续尝试 |
| 几个中心瓜分唯一一套材料，全部卡在半套 | 一份共享现货预留视图，先补完已有部分配送，再轮换未预留中心的优先顺序；每笔库存仍只扣一次 |
| 显示缺水但无法解释配送状态 | 区分仓库缺货、无下载额度、等待五秒边界、等待共享配送及已送达，并显示同名库存、私有缓存、最近请求/送达 |
| 把其他中心的私有缓存算进当前材料预览 | 材料预览只采用首个中心实际可用的托盘和私有缓存；总缓存单独标注为合计 |
| 批量目标栏使状态区在窄屏被挤掉 | 网格明确分配五个内容行，状态区可换行、滚动；浏览器测试要求提示实际可见且进入视口 |

JS 与 Rust 同步实现下载、规划、预留、调度和配送回执。新增跨内核测试逐秒比较水、现成中间件和后续目标的完整状态哈希；没有放宽原生权威准入。
