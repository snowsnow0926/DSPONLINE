## 查到的实际边界

蓝图有多层不同的上限。原网页版交换限制是 512 个建筑模板节点、1,024 条内部线路、128 个外部端口、1 MiB UTF-8 文件；导入蓝图库最多 64 条。资源锚点最多 256 个。一个节点可以有多台堆叠设备，节点数量不等于堆叠数量。

本地 `createBlueprint` 没有这些交换数量上限，因此原本就能形成较大模板，随后在导出时失败。施工队列另外允许单订单 100,000 节点/250,000 线路、最多 100 个订单；这是内部预算，不能当成已证明浏览器流畅的交换规模。加载器保留既有大蓝图，不把交换上限应用到存档迁移。

## 本轮实现

| 网页交换项目 | 原限制 | 新限制 | 扩展 |
| --- | ---: | ---: | ---: |
| 独立建筑节点 | 512 | 4,096 | 8 倍 |
| 蓝图内部线路 | 1,024 | 8,192 | 8 倍 |
| 外部端口 | 128 | 1,024 | 8 倍 |
| UTF-8 文件大小 | 1 MiB | 8 MiB | 8 倍 |

资源锚点仍为 256，保持现有云端校验兼容；图库导入 64 条、队列数量/内部预算、坐标边界、每节点堆叠及每线路并联规则不变。没有删除或裁剪超过新交换限制的本地既有蓝图。先采用这一档可复现验证的扩展，不把十万节点内部预算直接开放为导入上限。

共享 `blueprintExchangeLimits.ts` 管理网页/传统 JS 路径的交换大小，文件选择和粘贴解析、导出预检/全文复核以及界面提示使用相同值。原来 20,000 个 JSON 值的隐藏复杂度预算随规模提高到 2,000,000；深度 12、完整字符/UTF-8 字节、重复 JSON 字段、端点/目录和完整规范往返检查保留。超过 8 MiB 或数量上限时明确拒绝，不截断内容。

文件入口复用严格的 UTF-8 解码/逐字节往返和文件大小竞态检查，但按调用者的固定预算执行。Native Core 的原生入口仍独立限制 1 MiB、512 节点/1,024 线路，其 IPC/耐久命令及渲染详情预算本轮不变；不能声称 Windows 性能版已获得同等容量。原生接口扩容需独立完成 Rust、Host、Preload、投影和耐久重放资格。

大选区复制同时改为 Set 筛选、Map 查询线路源和外部端口，代替每条记录再次在线性数组中查找；坐标原点线性归约，避免大数组展开成函数参数。队列载具收尾只查询有载具目标的物流站，并按实际已建 ID 复用一个局部索引，避免为每个普通建筑搜索整个工厂；部分补料与其它物流站的载具保持独立。工厂数组顺序、蓝图 key/ID、线路/端口和设备设置保持；不复制整个大工厂来追加模板，不改变材料/配方或模拟数值。

## 真实大档实测

把公开合成的 4,096 节点/8,192 线路存储网格追加到只读终局工厂副本，得到 114,138 实体/241,492 线路；清空实验队列并固定施工库存，分别测捕获、完整交换、直接部署和排队补足。四个全新 Chrome 147.0.7727.138 按旧/新/新/旧执行，无强制 GC、CPU/堆采样或并行重工作。捕获每进程三次，先取各进程中位；其它完整流程每进程一次，表中再取两个进程的中位。

| 领域计算段 | 原实现 | 新实现 | 判断 |
| --- | ---: | ---: | --- |
| 捕获/复制蓝图 | 439.20 ms | 35.55 ms | **少 91.91%** |
| 直接部署完整蓝图 | 22.90 ms | 21.65 ms | 基本持平，不申报额外收益 |
| 仅创建排队订单 | 164.15 ms | 164.00 ms | 基本持平 |
| 排队并补足、完成施工收尾 | 12,102.15 ms | 507.75 ms | **少 95.80%** |

捕获各进程中位范围旧 432.2～446.2 ms、新 33.9～37.2 ms；排队加补足旧 12,020.5～12,183.8 ms、新 501.4～514.1 ms。没有排除慢值。新模板交换正文 1,935,565 B，导出约 208 ms、解析约 55 ms；实验两边均使用新交换预算，不将这两段当成旧交换上限的提速。

四次捕获定义、规范交换定义、即时部署完整 GameState、排队施工完整 GameState 的四类全文摘要逐一相同，完整调用者输入未变；材料按全部 4,096 建筑/8,192 条 1 并联线路准确扣除，队列完成。旧引用由编译器实际加载，核对 `referenceSourceLoads` 和源码/编译摘要；不是只改变报告标签。各段不包含 React 呈现、持久化写入或网络，不等于整页 FPS/OS 内存收益，也不保证所有设备和蓝图形状都同样耗时。网格/固定库存仅在内存实验副本中构造，原夹具文件前后 SHA 不变。

初次采样有一份标为旧版的控制漏带固定版本参数，被源身份审计拦截；整组不用于性能结论，重新完成上述四次正确对照，原记录和 `initial-control-audit.json` 均保留。初次 8 MiB 单元的测试框架巨型逐项相等断言超出 5 秒；改为独立线性全字节比较，仍检查全部字节，未放宽产品边界或测试时间。旧失败日志均保留。
