## 这批做了什么

这一批修复 Rust 界面的库存上限输入：模拟刷新时不再把正在输入的数字改回原值；按 Escape 取消时不再误提交；切换存档会话或行星后，旧输入不能带到新对象。旧代码在新增的 8 个反例中全部失败，修复后相关 24 项测试、3 种窗口尺寸的真实浏览器输入检查和完整生产构建通过。这项收益是操作可靠性，暂没有新的运行速度提升数据。[本批准确证据](./reviews/rust-windows-native-limit-drafts-2026-09-10.md)。

上一批保存提示、救援读取、施工反馈和手机统计布局，在云端完整浏览器中已通过对应检查。Rust 写入覆盖清单也已补齐一个遗漏的条件分支；`1cf84cc8` 已提交推送，本机完整生产构建和新的云端生产构建通过。这个清单帮助核对操作入口，不能自动开启玩家 Rust 实时模拟。

最新完成的 `50b7af10` 全量浏览器结果为 **467 项通过、33 项条件跳过、2 项失败、1 项重试后通过**。剩下的是冷菜单批量启动超过 500 毫秒、设置页面综合测试超时，以及旧网页托盘上限偶发回退。设置的失败轨迹尚未证明页面溢出：此前检查都通过，最后一步在整例耗尽 30 秒时被中断。原测试门槛和失败记录保留。

同一 `50b7af10` 的 Windows 云端全套已成功：Rust 核心 1,115 项、Host 库 263 项、原生工具 845 项、游戏单元 3,193 项通过，各自条件跳过单独记录。清单修复后的 `1cf84cc8` 其余完整检查还在运行。完整 Windows 包、终局档保存重开和实际实时接管仍要分别验收。

新增一层实时接管前的校验：签名正确后，还会检查获准的程序、规则、测试存档和有效期是否与当前会话一致。最终代码已通过云端 Windows 完整检查，包括两端 76 个共享案例、真实签名的正反例和测试证书清理。这是在准备接管条件，尚未开启玩家 Rust 实时模拟，也不代表新增游戏性能收益。[这批的准确证据](./reviews/rust-windows-validation-binding-2026-09-10.md)。
