# 新上海节点自动备份接收端切换记录（2026-08-25）

## 结论

新上海 VPS 已切换为香港生产节点的自动备份接收端。香港应用、代理、健康检查和原有回滚边界均保持正常；没有切换公开下载流量，也没有修改数据库、玩家存档、发布目录或 DNS。

## 变更前门禁

- 香港 API、handoff proxy、备份 timer 均为 `active`，API `NRestarts=0`。
- 香港本地 `/api/health`、`/api/ready`（两个本地监听端口）均为 HTTP 200；严格 TLS 的公网 `/api/health` 为 HTTP 200。
- 香港根盘约 78% 使用，低于 90% 硬保护线；因此本次只做小型合成传输验证，没有强行启动 3.7 GiB 级生产快照。
- 新节点为独立 Linux x86_64 主机，约 36% 使用；预先迁移的加密归档和 manifest 未被本次接收端配置覆盖。
- 旧上海节点保留两份最新完整加密备份及其 manifest，作为独立历史恢复边界。

## 接收端与传输验证

- 新节点创建了锁定密码的专用 `dspbackup` 系统账户；账户 shell 为 `/bin/sh` 以兼容现有 `scp` 发送器，不提供交互登录能力。
- 接收目录由 `dspbackup` 所有，权限为 `2770`；`authorized_keys` 权限为 `0600`，没有 `.partial` 残留。
- 香港侧新私钥为发送服务用户可读且仅所有者可读（`0600`）；known-hosts 仍为受限权限并使用控制台核验的主机公钥。
- 合成探针内容固定为 31 bytes，发送、远端完整读回和 SHA-256 校验均通过；探针文件随后已删除，接收目录无残留。
- 仅在探针通过后，才原子更新香港备份配置；旧配置保留为受保护的 pre-switch 回滚副本。

## 切换后验收

- 香港备份 timer、API、handoff proxy 仍为 `active`，`NRestarts=0`。
- 香港本地 health/ready 四项均为 200，公网严格 TLS health 为 200。
- 香港磁盘仍约 78%；新节点约 36%。
- 旧上海节点的两份保留备份、文件完整性和权限未改变。
- 未执行生产全量 Backup API 快照：当前磁盘保护线下，下一次真实快照必须在低流量维护窗口执行，并记录 Backup API、quick_check、schema/layout、完整 SHA-256 和低于 90% 的证据。

## 公网下载节点边界

本次没有把新节点切为公开下载节点。该节点尚无经过清单校验的静态下载制品、TLS 证书/DNS 绑定、Nginx 配置哈希、原子回滚指针和公网 Range/cache/PWA 验收；缺少这些门禁时不得接流量。

## 回滚与后续

- 香港备份配置的 pre-switch 副本仍在目标机，恢复该副本即可回到旧上海接收端；不需要回滚数据库或应用代码。
- 旧上海节点保持可读的历史接收归档，不删除、不覆盖。
- 新节点 transport 目前只在本次受保护进程中使用；受保护加载器的长期登记仍需由运维凭据存储完成。未把主机、私钥、known-hosts 或口令写入普通环境、仓库或本文。
