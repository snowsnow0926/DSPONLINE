## 实现边界

大档使用 IndexedDB 时，页面继续持有原来的纯挂机 Web Lock。启动时的私有冻结状态按确认分批交给一个后台，每批最多 512 个实体或 2,048 条传送带；后台先写原格式恢复日志，随后复用同一份状态，交给现有主存档序列化、证明及读回流程。不会为主存档再发送一次完整状态。

普通 T0 检查点保留。小档以及非 IndexedDB 后端沿用原路径；GameState v47、envelope v2、恢复日志 schema v2 和 IndexedDB v1 对象仓库保持。没有修改离线/时间扭曲数值、材料算法或备份设置。

写入安全边界：

- 后台在一个恢复数据库写事务内比较初始心跳和接管标记，迟到的旧任务不能覆盖新会话；空日志发生强制接管也会留下一个很小的标记。
- 正式页面同时提供主存档写入者和 fencing token。后台保持恢复写事务，短暂只读核对主存档租约，再在自己的 IDB 回调里写入。这覆盖旧版页面未写新接管标记的情况；核对最多 5 秒，只允许一个保活请求等待，不在 UI 上循环。
- 页面退出、卸载或变成只读会同步取消后台；来源失效、崩溃、超时和消息错误也会释放它。
- 写入回执丢失时，只清理该次 session 的日志；新的同页创建/恢复不会被旧任务释放写入锁。主存档仍由原有 fencing、证明和独立读回约束。
