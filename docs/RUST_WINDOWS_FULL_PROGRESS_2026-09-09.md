## 这一批完成了什么

**验签助手现在真正装进 Windows 测试包了。** 打包时会记录助手的文件指纹，主进程从自己的程序包里读取这个指纹；缺文件、被替换或混入别次构建都会被拒绝。修复了 Cargo 构建输出使用硬链接的兼容问题，同时保留安装后文件必须独立的要求。

| 窗口创建、显示、焦点、对话框 | 全部为 0，正常退出、临时目录已清理 |

云端签名测试和本机冻结包是不同构建，分别记录；这些通过结果尚不能让 Rust 直接接管玩家游戏。下一步还要核对完整授权范围、证据来源、到期撤销，并完成实际游戏接管和恢复。

本批没有新增帧率或整段结算提速结论。见[本批实包报告](./reviews/rust-windows-catalog-package-2026-09-09.md)和[实际签名记录](./reviews/rust-windows-signed-catalog-ci-2026-09-09.md)。

## 已经证实的性能收益

- 较早的公开大工厂案例：约 9,100 个设备、20,000 条传送带，固定 5 秒离线的完整等待中位从 20.79 秒降至 5.96 秒；那一包的保存、取消和重开已验证。
- 11 万设备、23 万传送带的终局档：固定 9 秒精确 Rust 请求中位从 51.77 秒降至 49.19 秒，少约 2.58 秒；完整导出一致，原档未改。
- 同一终局来源的独立校验：中位从 5.49 秒降至 4.97 秒，少约 0.51 秒；完整摘要一致。
- 菜单进入和恢复保存已接到后台 Worker，旧档备份、保存冲突保护、精确读回和失败重试保留。新增的整段等待收益尚未测定。

这些结果属于不同输入、版本和处理环节，百分比不能相加，也不能外推为整款游戏帧率或内存提升。
