## 诊断证据

使用冻结的 `241d4b494233` 和 `66544ecf66ef` 网页，新增 `--profile=1 --profile-phase=starting`，仅采样开始挂机至 ready。两边各 179 个生产 JS 均与各自隐藏 sourcemap 重建逐字节相同；176 个脚本有映射。旧版前两次替换模块重建的 41 个脚本不匹配，证据保留并排除；用新的 D 盘独立旧提交检出得到完全匹配的映射，未替换冻结网页脚本。

Profiler.start 本身有约 0.7 秒协议/启用开销，不能把其 before/after 时钟中点当作精确起点。用 stop 前后边界减去 CPU profile 的实际时长，再与 start 边界求交，最大长任务的时钟不确定区间约为 5.92 / 6.44 ms。分析只使用覆盖该任务的保守窗口。

两份诊断中最大启动任务为 261 / 253 ms；复制的应用采样包含时间约 174.23 / 175.26 ms，供电刷新部分约 28.87 / 29.85 ms，另有约 51.42 / 43.74 ms 的 GC self 采样。包含时间不能重复相加，GC 不强行归到某个 JS 函数。诊断没有复现未采样对照中的 +10 ms 顺序，不能据此宣称该回升消失或已经归因；明确的共同大头是同步实体/线路复制。

## 候选实现

普通 `copyState` 仍用原复制函数和规则；新增私有记录数组参数，只供分批入口预分配目标记录。`refreshTimeWarpPowerSnapshotChunked` 在默认每 4,096 条记录后让出浏览器调度，完整保留 `cloneFactoryEntity` 的旧字段默认化、线路顺序、全部库存、科技、量子和其他头部数据，再对完整副本执行原同步供电计算。

App 只在原普通 Worker 提交屏障之后使用该入口。启动编辑屏障、Legacy authority lease、操作身份及 AbortSignal 保持，每次让出后重验；未完成副本不发布、不写恢复日志、不替换主档。源记录数组更换或长度变化会取消。正常计时器已在启动 latch 期间停止累计普通模拟债务；既有 pending wall 时间直到完整副本成功才清除，取消或调度失败不会提前消费它。恢复日志、普通 T0、独立证明、读回、fencing 和失败路径均保留。
