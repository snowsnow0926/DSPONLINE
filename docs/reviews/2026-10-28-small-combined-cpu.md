## 实际执行与结果

四个固定合成工厂有 43～162 实体、零线路，覆盖空闲、成品供料、混合递归及量子仓库。每个样本是新 Node 工作进程，实际加载并校验引擎/递归模块的冻结 Git 源码 SHA；其它游戏运行源码没有差异。原调用方输入、完整的 40 步预热终态及测量终态均一致，不只比较产量字段。

各阶段先声明旧/新/新/旧顺序，再执行。所有输入、初始短窗口及后续样本全部保留，共 **12 个独立比较进程、36 条 CPU 记录**。计时只包围 owned simulation 推进，读取进程 user+system CPU；没有遍历计数插桩，不含导入、准备索引、预热及最后 JSON/hash。墙钟另存，不拿它替代 CPU。

| 场景：960 步 | 已验收旧版两次 CPU ms | 候选两次 CPU ms | 中位 CPU 变化 |
| --- | --- | --- | --- |
| 空闲 | 374 / 375 | 390 / 374 | +2.00% |
| 成品供料 | 1,203 / 1,188 | 1,015 / 984 | **-16.39%** |
| 混合递归 | 453 / 438 | 421 / 422 | **-5.39%** |

空闲 960 步样本范围重叠，随后在保持 162 实体、不增大工厂的前提下，预先声明单独 7,680 步窗口：旧 1,453 / 1,469 ms，新 1,422 / 1,407 ms，中位 **-3.18%**。没有复现原先小幅升高，但跨窗口不稳定，不强调空闲改善。

初始 120 步数据同样保留：空闲旧 78 / 79→新 78 / 78 ms；成品 204 / 202→156 / 187；递归 62 / 78→63 / 79；量子 296 / 298→250 / 250。短窗口不足以支持递归 +1.43% 或空闲 -0.64% 的稳定结论，没有删掉不利记录，也不将不同窗口百分比相加。

所有 36 条正式记录的源模块、输入不变及完整状态校验通过。维护后的 runner 另一次空闲 smoke 通过并与正式结果全文摘要相同，排除在性能表外；准备工具复现四个冻结源码摘要。配置/准备脚本语法、加载覆盖及 runner 实际执行已检查。新工具入口：[说明](../../experiments/low-impact-engine-cpu/README.md)、[探针](../../experiments/low-impact-engine-cpu/probe.ts)、[资源受控执行](../../experiments/low-impact-engine-cpu/run.ps1)。

这些是小工厂 Node 计算段的实际 CPU 数据，优于仅统计循环次数，但只有每端两个样本，不代表大档网页帧率、启动/停止、两种时间扭曲协议或内存改善。原 136 项聚焦与类型属于未变化的 `f50c60e0` 源码，未为本次工具/文档任务重跑，不与计时记录相加。此时尚未增加整体验收资格。
