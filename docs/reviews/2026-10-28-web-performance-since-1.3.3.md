# 从 1.3.3 到现在：给玩家看的性能报告

日期：2026-10-28。本批是已经通过本地验收的开发版，**尚未发布**。原存档、产量、耗料、高级配方优先和量子取料规则保持，未修改自动备份停用设置。

**最大的改善是进入、退出挂机时不再长时间卡住画面；开始和保存仍需要等待，还没达到所有场景都丝滑。**

## 与正式 1.3.3 直接重测

同一台电脑、同一份约 105 MB 级终局档，约 11 万个建筑、23 万条运输线；正式 1.3.3 和当前开发版各用全新浏览器测三次。表中是三个结果的中间值，不是把各轮优化百分比相加。

| 玩家能感受到的项目 | 正式 1.3.3 | 当前开发版 | 改善 |
| --- | ---: | ---: | --- |
| 开始挂机时最明显的一次画面卡顿 | 1.16 秒 | **0.12 秒** | 缩短 **89.3%** |
| 开始挂机总共要等多久 | 10.95 秒 | **8.94 秒** | 少等 **18.3%**，约 2 秒 |
| 停止挂机、保存并恢复画面要等多久 | 14.29 秒 | **11.06 秒** | 少等 **22.6%**，约 3.2 秒 |
| 退出时最明显的一次画面卡顿 | 0.28 秒 | **0.10 秒** | 缩短 **63.4%** |
| 游戏进程峰值内存 | 5.38 GB | **4.09 GB** | 少 **23.9%**，约 1.29 GB |
| 停止后的游戏进程内存 | 2.06 GB | **1.38 GB** | 少 **33.1%** |

“总等待”包含后台计算、完整校验、保存和独立读回；“画面卡顿”是这段过程中最长的一次画面间隔，两者不能混为一谈。现在的改善主要是等待期间画面更容易响应，并且等待本身也有缩短。

旧版有波动：开始等待 **10.60～17.65 秒**，退出等待 **13.92～21.73 秒**；新版分别为 **8.77～8.98 秒**、**11.05～11.08 秒**。最初各两次的旧版波动较大，因此先声明补一组，再完成各三次；六次结果全部保留，没有删掉较慢的一次。

新版峰值内存范围仍为 **3.88～4.96 GB**，旧版为 5.04～5.44 GB。这里的 GB 是运行内存，不是存档大小；内存改善存在波动，不能理解成低内存手机已经能顺畅运行。这是本机一种终局档的结果，不是所有电脑或全游戏帧率承诺。

## 计算部分还快了多少

以下是各轮专项测试，计时范围比整款游戏小，不能与上表相加：

| 专项 | 优化前 | 优化后 | 计算时间减少 |
| --- | ---: | ---: | ---: |
| 巨构制造为主的固定 30 秒结算，原库存 | 5.87 秒 | 3.93 秒 | **33.0%** |
| 同一结算，量子仓库供料压力场景 | 1.07 秒 | 0.70 秒 | **34.1%** |
| 同一结算，托盘材料充足压力场景 | 1.72 秒 | 1.57 秒 | **8.3%** |
| 一轮普通模拟优化，累计推进 30 个模拟秒 | 18.63 秒 | 17.09 秒 | **8.26%** |
| 一轮完整存档检查优化 | 1.14 秒 | 0.47 秒 | **58.7%** |

制造专项的旧算法已核对与正式 1.3.3 相同；量子/托盘行是人为供足材料的压力测试。普通模拟和存档检查行分别是对应那一轮的前后对照。它们说明同样的工作少花了计算时间，**没有额外赠送建筑、增加产量或减少耗料**。

## 这批优化做了什么

1. **让主界面少承担大对象复制。** 启动检查点共用已准备的数据，大批复制分段交给浏览器调度，减少点开始时的长卡顿。
2. **减少重复计算。** 巨构制造复用相同步骤的批量耗料计算；传送带复用一个结算阶段内不变的输入；显示查询和存档检查减少无用开销。实时库存、配方优先级及完整校验继续执行。
3. **及时释放用完的数据。** 保存确认完成后回收空闲后台，解除旧画布和旧显示状态的引用，避免多份大档长时间同时占内存。
4. **避免界面恢复时做无关工作。** 焦点、坐标和线路显示只在真正需要时更新；线路新快照漏更新的问题已修正，不能以显示旧数据换速度。

没有净收益、增加峰值内存的方案已撤回。现有 Rust/WASM 也测过包含复制、计算和读回的完整成本；这次不比现有 JS 更划算，所以没有为了使用 Rust 而强行接入。

## 验证和还没完成的事

当前运行的完整单元测试 **3,725 项通过 / 38 项条件跳过**，网页测试 **521 项通过 / 34 项条件跳过**，生产模式离线缓存测试 **1 项通过**，没有失败。固定普通模拟的完整结果一致，实际两次约 111 MB 主档独立全文读回一致，真实挂机后台固定 30 秒的原始存档、加载后状态、再次保存正文三份完整结果也一致。没有跳过检查点、校验、读回或失败恢复。

接下来仍需处理：

- **约 9 秒开始、11 秒退出的等待。** 最新定位中，退出时最终结算和生成存档仍约占 4 秒，会继续拆解这段实际计算。
- **大档的几 GB 内存需求。** 本轮明显降低了中间值，但尚未获得低内存设备和长期挂机资格。
- **守恒模式、长时间离线及剩余计算热点。** 本次整页表测的是 8 倍产率复制模式；传送带调度、物流/量子/电力和画布工作区继续按原优先级推进，不能据此声称所有模式都已流畅。

整体性能目标仍未完成。报告收尾时持续任务状态查询为 `paused`，本轮后没有启动新一轮开发；后续范围和优先级保留。本报告不是发布记录，也不是全部性能工作完成的声明。
