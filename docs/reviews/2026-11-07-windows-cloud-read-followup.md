# Windows 云下载 1.3.9 漏修回归

用户在 2026-11-07 反馈正式 Windows 1.3.9 仍提示“当前接口不接受该 DSP 请求头”，并提供本地备份。附件仅作本地只读验证，未上传到生产，未将正文加入仓库。原文件 122434 B，SHA-256 `35e49f5127b4005c614f523ca8c1e31ac894399b0b70d43dd2aab78aab693cbb`；envelope v2 / GameState v47，主档、普通模式，checksum valid。

## 确认原因

`apiTransport.ts` 在所有流式 IPC 请求中把本地 requestId 写成 HTTP `x-dsp-request-id`。1.3.9 的桌面修补只停止主动追加该头，没有删除前端已经带来的值。GET 的服务端读取策略不允许上传幂等头，因此在解析存档前返回 `DSP_HEADER_NOT_ALLOWED`。

此前正式包冒烟直接调用 `requestApiTransfer()`，手写 headers 未带 requestId，绕过了真实 `downloadCloudSave() → apiFetch() → IPC → HTTP` 路径，漏掉这一缺陷。新增该完整调用链回归在修复前四种主档/槽位/修订/速通场景全部复现相同拒绝；另用未修改的正式1.3.9包、隔离D盘用户目录、本机模拟账号和真实“下载并进入”按钮，再次得到相同错误。

## 修复边界

- 前端仅为直接云上传写HTTP幂等头；下载、旧JSON和其他流式请求的ID保留为IPC取消/确认用途。
- 桌面层对非直接上传主动剔除误带的该头，兼容旧前端。直接上传仍把HTTP请求ID绑定到本地请求ID。
- 保留认证、请求大小/超时、服务器读取白名单、上传并发与存档格式；不放宽服务端校验，不改变玩家存档。
- 本批是开发修补；未覆盖已发布的1.3.9制品或更新源，也未部署服务器。
