# 网页保存：减少传输压缩与校验重复工作

状态：实现、同档实测及全量回归通过，待最终冻结包验证；未发布。

## 范围

角色为 develop，任务 `web-save-verification-20261027`，优先级 P1。
承接持续优化香港网页版性能的授权，继续上一轮槽位/手动快照检查点优化。
不改变 GameState、存档 envelope、数值规则、真实存档、备份设置或线上服务。

先对真实生产页面记录后台阶段，发现约 6.46 秒的快照等待包含：取得检查点约 1.33 秒、
序列化约 2.36 秒、持久化前验证约 1.97 秒；压缩只占约 0.46 秒，磁盘及读回约 0.41 秒。
因此本轮同时处理传输压缩和校验扫描，而没有把磁盘当成瓶颈。

## 实现

- `canonicalSaveEnvelopeInspection.ts` 用字符码判断空白/分隔符，数值栈匹配括号；普通字符串
  通过 sticky 正则原生扫描，不分配子串或匹配数组。转义、控制字符继续走原有完整检查。
- 状态 FNV 仍按原始 UTF-16 顺序计算，仅展开四个字符的循环，不省略任何字符。
- 网页槽位/手动快照的 ArrayBuffer 可直接转移所有权，因此用可选请求字段省去传输压缩。
  主存档默认行为、原生端及 Blob 路径仍保留压缩；没有增加玩家设置项。
- 持久化 Worker 复用同一未解压 ArrayBuffer 已经算出的 SHA-256。不同的解压输出仍单独校验；
  正文、目录绑定、写入权、revision 和提交后的独立读回全部保留。

专项覆盖普通/速通、Unicode 与单独代理项、转义及非法控制字符、无 Worker 回退、
Blob 保留压缩、伪造 SHA proof、同长度正文破坏、旧槽位不被错误写入覆盖。

## 实测

沿用只读准备态：205,464,026 字节，SHA-256
`6a6aa320dd9d5fd5e5b618b745fc864c2ccb2d96143e0b852d1f270358de9ebf`。
普通模式，110,042 个实体、233,300 条运输线；工厂暂停、时间扭曲和自动保存关闭。
Chrome 147.0.7727.138，独立临时上下文，API 请求屏蔽。每个入口各三次基线和三次候选，
实测时不并行运行构建或测试套件。基线为 `1.3.1+23ae7dde4d81`，候选使用本轮源码生产构建。

两个入口总等待分别缩短 16.1% 和 15.7%。画面间隔基本不变；槽位峰值工作集增加约 1.7%，
快照峰值相近，不能称为本轮额外降低了峰值内存。保留改动，因为总等待稳定减少约一秒，
没有恢复上一轮的整档界面复制和明显停顿。

独立扫描对照使用同一内存正文、每次测量前完成 GC：原扫描 1,536.7 ms，substring 中间方案
1,279.2 ms，最终 sticky 正则方案 1,153.6 ms。所有结果一致，最终方案减少约 25% 扫描耗时。
这只是扫描器对照，不代表整款游戏帧率。

传输由约 5.37 MB 压缩数据变成约 110.67 MB 的可转移内存块，发生在同页 Worker 之间，
不是网络上传或磁盘文件变大；磁盘正文长度和格式不变。原生/Blob 未参与本次速度外推。
