# 1.2.0 Windows 原生性能第二、三层开发与实测报告

> 状态：开发候选，未签名、未部署、未切换下载页。
>
> 分支：`codex/1.2.0-windows-native-layers23`。
>
> 公开兼容边界：GameState v47 / envelope v2 / cloud schema v8 / SQLite layout v3 不变。

## 1. 交付结论

1.2.0 已把第二层“Windows 私有增量存档”和第三层“独立 Rust 模拟核心”接入 Electron 的受限主进程边界。Windows 大型自动保存可以在提交兼容 v47 检查点的同一 revision 下写入不可变压缩区块、双 superblock、追加式 WAL 和可校验 generation；renderer 只能使用逻辑槽位，不能传入文件路径或启动进程。

原生核心已经具备独立状态容器、目录指纹、命令/WAL 重放、检查点流式提交、投影、规范哈希、崩溃后无静默回档状态机，以及采矿、生产、电力、线路、物流、量子网络、建筑制造、戴森、空间站、进度和速通等主要精确领域。邀请 Beta 默认关闭；开启后仍由 JavaScript 作为玩家可见权威，Rust 只做影子对照。`pureIdleMacro`、完整 `offlineAndTimeWarp` 与 `authorityEligible` 仍明确为 `false`，因此没有把尚未完成 24 小时 Gate C 的核心包装成稳定权威。

1.2.0 同时包含保守时间扭曲戴森物料复制的 P0 修复。原生保守路径也使用 `native-pure-idle-conservative-v2`：只提交有界精确前缀，冻结无法证明守恒的尾段。

## 2. 第二层：Windows 私有增量存档

- 存储位置仅限 Electron `userData/native-saves/<logical-slot>`，IPC 不接受 renderer 路径。
- 每个区块按内容 SHA-256 去重并压缩；manifest 在区块之后发布，双 superblock 交替原子切换。
- WAL 记录 `baseRevision -> resultRevision`、命令 ID、前序哈希和 payload 哈希，重复命令幂等，revision 断裂拒绝提交。
- 恢复只接受最新且完整验证的 generation；不能证明连续性时失败关闭，不会静默选择更旧进度。
- compaction 至少保留两个已验证 generation；v47 / envelope v2 继续承担导出、云同步和跨端恢复。
- 进程协议使用带 magic、版本、序号、长度和 CRC32 的有界二进制帧，单帧上限 8 MiB并实施背压。

规范见 [ADR-005](../architecture/ADR-005-WINDOWS-NATIVE-SAVE-FORMAT.md)；进程边界见 [ADR-006](../architecture/ADR-006-WINDOWS-NATIVE-CORE-PROTOCOL.md)。

## 3. 第三层：独立 Rust 模拟核心

- Rust 进程从已验证的第二层 generation 建立列式实体/线路容器和稳定索引，不在 renderer 加载 native addon。
- JS 与 Rust 从同一检查点、目录 fingerprint 和命令序列推进；检查点比较完整规范哈希、分域哈希和 revision。
- 普通操作可事务性提交命令与模拟片段到 WAL，再发布有界 projection；不要求每秒把完整 GameState 传回 renderer。
- 原生异常退出后进入显式暂停/恢复状态；只有同 revision 的兼容检查点证明通过才允许恢复或回退。
- 自定义内容包的物品、建筑、配方和传送带 tier 进入同一目录指纹与差分测试；缺失或不一致时拒绝影子提升。
- 原生权威切换门禁要求至少 24 小时影子、净吞吐不少于 1.5 倍、IPC 占比低于 20%、进程树内存确有改善、完整领域覆盖和同 revision 恢复点。当前公开 UI 不提供绕过该门禁的权威切换。

## 4. 76.9 MB 玩家存档实测

测试对象只读使用，大小 `76,898,141` 字节，包含 `80,674` 个实体和 `155,746` 条线路；原文件没有写回或上传。

### 4.1 原生存档

| 场景 | 实际新增写入 | 耗时 | 结果 |
| --- | ---: | ---: | --- |
| 首次 generation | 3,143,990 B / 158 records | 1,554.49 ms | 规范重载哈希一致 |
| 内容完全不变的下一代 | 2,858 B / 1 record | 988.03 ms | 相对 76.9 MB 几乎只写 manifest |
| 大量运行字段变化 | 3,073,755 B / 134 records | 1,195.97 ms | 比原 JSON 少写约 96% |

源状态与原生重载状态的规范 SHA-256 都是 `4d916a42ef4908b693b7f932e5851824aff5ebc704db4259069a0c2d4c8fdd90`。首次路径仍需扫描/投影兼容状态，但实际耐久写入由压缩、去重区块约束；“新增写入”不能误读成整个内存状态只有 3 MB。

### 4.2 原生核心

| 指标 | 结果 |
| --- | ---: |
| 原生载入并建立索引 | 13,009.65 ms |
| 估算 Rust 运行态 | 219,510,987 B |
| 原生进程 Private Bytes 增量 | 312,758,272 B |
| 一秒原生精确推进 | 1,988.99 ms |
| 同状态 JavaScript 精确推进 | 3,505.33 ms |
| 原生 / JS 耗时比 | 0.567（本次约 1.76 倍吞吐） |

`coreStatus` 的完整诊断哈希另耗时 5,141.13 ms；它不在普通热推进中每步执行。载入速度仍是明显优化空间，当前数字只代表这台机器、这份存档和本次单次运行，不能外推为所有玩家固定收益。

## 5. 数据保护与回滚

- 没有升级或静默迁移 GameState、envelope、云 schema、SQLite layout 或 Mod JSON。
- 现有玩家戴森球历史数值不会被自动降低、重算或回滚。
- Web/Android 继续完全使用 JavaScript + v47 路径；Windows 原生影子关闭或不可用时也继续读取同一兼容存档。
- 原生检查失败不会替换当前工厂；无法证明同 revision 时保持暂停并允许导出/人工恢复。
- 生产回滚只切回旧应用制品，不反向修改云数据库或玩家存档。

## 6. 尚未冒充完成的门禁

- 没有完成真实 24 小时 Windows 影子运行和多硬件矩阵。
- `pureIdleMacro` 与完整离线/时间扭曲原生覆盖尚未取得 `authorityEligible=true`；当前只提供有界保守原生路径和 JavaScript 权威回退。
- 本开发角色不执行 Windows/Android 正式签名，不连接香港/上海生产，也不切换下载页。
- 正式发布仍需 Release Agent 在精确候选 SHA 上复验签名、安装/覆盖升级、低配 Windows、生产备份、原子切换、公网 health/PWA/Range 和观察期。

这些限制不会阻止 1.2.0 以“Windows 私有存档 + 邀请 Beta 影子核心默认关闭”的方式进入候选，但会阻止把 Rust 核心宣传成默认稳定权威。
