# 网页槽位与手动快照：复用权威检查点

状态：开发实现、同档实测、全量单元与浏览器回归通过；最终构建验证待完成，未发布。

## 范围与改动

角色为 develop，承接“持续优化网页性能、保留存档和自动备份停用设置”的授权。
本轮没有 SSH、生产写入、下载发布或版本号变更。

主存档已有后台校验写入通道，但槽位和手动快照仍把完整工厂从界面重新复制给保存 Worker，
再把大字符串取回界面、写入和复核。现在仅当完整检查点的对象身份匹配时，单次取走它的
可转移缓冲区，复用已有保存及持久化 Worker，界面只接收小型校验结果和目录信息。

- 修改 `src/App.tsx`、`src/game/storage.ts`，增加 `SaveCheckpointTransfer` 可选参数。
- 主存档、旧版本/无 Worker 的兼容路径、其余调用者继续沿用原有入口。
- 两个操作等待同一完整检查点时，只有一个取得缓冲区；另一个仍持有完整状态供原路径使用。
- 继续校验模式、状态身份、写入权、revision、存储容量、正文及读回结果。
- 校验失败不悄悄换用另一个状态；失去写入权或 revision 冲突时保留原有失败路径。
- 槽位/手动快照不会为了复用数据而额外写入主档，也不触发主档备份逻辑。
- `native/native-coverage-manifest.json` 仅重新生成受新增行号影响的位置；没有改变原生权限。

## 大档完整性

三次基线槽位、三次基线快照的状态校验为 `6a1bb9b7`；六次新路径为 `f51ab707`。
差异来自大档旧路径把实体和运输线分块收集后放回对象尾部；新路径直接使用原检查点。
v2 校验基于 JSON 字段顺序，两者各自有效，但不能据此宣称大档输出逐字节相同。

另在测量结束并关闭工厂页面后，读取完整持久状态，递归排序对象键、保留数组顺序和值，
分别对全部 49 个顶层字段做 SHA-256，再绑定字段名与摘要。基线槽位、新槽位和新手动快照
49/49 字段一致，组合摘要均为：

`372522226c1f1b0a7033122bc2ab121bd2d170f6dd750d368f132d26be165cff`

每次真实页面运行同时确认主档未被槽位/快照改写、目录校验有效、实体/运输线数量一致、
模拟 Worker 保持 active。小样本回归另检查普通与速通的逐字节兼容、分块重组后的状态等价、
错误检查点不得覆盖旧槽位，以及无 Worker 时兼容回退不消耗原缓冲区。
