# 1.2.7 Rust 存档恢复阶段开发记录

Role: develop。基线运行包 `1.2.7+27c4f15fd621`，开发起点 `e24dccbb`，分支 `codex/1.2.7-rust-offline-gain`。本记录是本地候选开发证据，不是线上发布记录。

## 实测决定

RP0 的首轮持续生产对照发现，600 秒普通缓冲供料产线在 JS 快速结算中产出 9,600 个铁块，而旧 Rust 候选只产出 480 个。Rust 正确报告了未证明尾段被冻结，但 `supported=true` 被自动启动路径当作完整候选。量子缓冲、矿脉和上传塔的追加样本也未取得可用于加速比较的完整结果。失败输入与输出保留在 `artifacts/rust-performance/RP0/2026-09-07T08-18-40-768Z-6be3c11f/`；探索驱动前两次归一化/环境替换错误单列，不当作产品失败。

因此暂不放行长时自动 Rust 离线结算。前端超过 30 秒直接进入已有 JS 流程，Host 独立拒绝超过 30 秒的自动候选导出；短时结果仍须证明没有近似尾段、校准秒数完整、源和候选校验一致。原有 JS 快速/精确选择和保守结算确认保留。该范围限制不修改底层宏算法、存档和生产进度，也不开放 Rust 实时权威。

本批优先交付独立的存档读取阶段：

1. Windows 原生侧车先核验公开主档与清单，只在基础校验和匹配时逐块读取。手动保存形成新主档后，过期原生检查点只读取一条清单，避免搬运整份无用旧工厂。
2. 使用与 IndexedDB 相同的异步重建规则，保留区块校验和、字节长度、版本、模式、公开 envelope 校验和，以及每次 IPC 的 generation/rootHash 绑定。
3. Rust 单记录读取借用已经验证的不可变清单，消除 N 次读取反复复制 N 项元数据。每块磁盘数据仍重新验证；提交替换缓存代次，旧 generation 读取仍拒绝。

## 固定输入与验收口径

只使用公共引擎模板生成的暂停合成档，不读取玩家存档。夹具包括约 5k/20k/80k 实体的密集线路及 20k 稀疏活动设置；实际规模、字节数和 SHA-256 见运行清单。相同大小并不代表覆盖所有实际工厂。

实际 EXE、ASAR、预加载桥接和 release Rust Host 下，以全新隔离配置执行 `benchmark-desktop-native-recovery.mjs`。主指标是 **原生存档恢复入口到已校验 envelope / 确认回退的完整阶段耗时**，包含清单、区块 IPC、解析和校验；不是点击继续到整个画面可操作的总时间，不是 FPS，也不是离线产出加速。匹配检查点和过期检查点分别报告。读取后核对完整规范状态、检查点身份、原始夹具字节和正常关闭；按实际进程树采集 Private Bytes。

正式性能样本在运行/驱动源码冻结和构建完成后采集。每组至少五次独立进程，A/B 与 B/A 交错；保留失败和预热，不以少量样本声称 P95/P99。当前代码冻结前状态为 **待采集**，后续证据提交填写结果。

## 版本和后续

GameState v47、envelope v2、cloud schema v8、SQLite layout v3 不变。准备 `1.2.7` Windows 性能开发版离线候选；实时模拟继续由 JS 持有，Web/Android 尚未接入 Rust，本阶段不宣称它们获得原生性能提升。

RP0 总矩阵和 RP1 完整离线收益仍未完成。本阶段可单独评估纳入 1.2.7，但不能据此标记 RP1 或实时资格已通过。后续优先修复真实普通/量子产线的长时一致性，再补完整“保存→退出→离线→结算→保存→重开”对照。

发布交接须列出最终运行 SHA、制品哈希、实际新鲜测试、签名状态及未执行门禁。签名、升级、多硬件和线上部署属于后续明确目标的发布步骤；本记录不继承 1.2.6 的豁免。
