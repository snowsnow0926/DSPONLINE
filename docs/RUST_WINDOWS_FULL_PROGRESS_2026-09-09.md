# 完整 Windows Rust 开发进度｜2026-09-09

**完整 Windows Rust Goal 已创建并启用。** 目标包含 Rust 实时运行、完整受支持玩法、可靠存档与恢复，以及可以交接发布的 Windows 包。沿用现有界面；网页/安卓 Rust 仍另行开发，本批未发布客户端。

## 本批推进

1. **Rust 请求再省约 1.75 秒。** 同一条工厂记录只编码一次，同时更新两个独立摘要。终局档三对真实 Host 测量，固定 9 秒结算请求的中位耗时 **53.55→51.80 秒，减少约 3.3%**；完整导出和所有摘要一致，8 次运行正常退出，原档未变。这是 Native 请求收益，尚不能当作完整进入游戏或帧率提升。
2. **修正堆叠设备连线偏离端口。** 隐藏的一端无法测量时，原代码会丢掉另一端的真实位置。现在分别保留两端的测量；在测试夹具中修正了约 38 个画布单位的纵向偏移，并保留命中、选择和隐藏节点行为。三种画布检查各跑三轮，**9/9 通过**。
3. 正常优化版 Rust 核心 **1,114 通过、5 条件忽略**，Host **256 通过、1 测试驱动忽略**；严格编译检查通过。Native 接口 **750 通过、1 条件跳过**，完整游戏 **3,176 通过、39 条件跳过、0 失败**，其中实际 Rust 对照 **50 通过、1 长测跳过**；类型、Web 构建和三项构建门禁全部通过。
4. 前批已推送的 `e517526a` 省掉一次无用整档解析，该清理环节约省 **0.28 秒**，终局主档/旧备份/快照正确。它的 Windows 云端全量及 Linux 构建、单元、Server/Ops/Native 都通过；浏览器仍有 **27 项失败、10 项重试后通过**。本批新源码还须自己的云端验证，不能按历史失败数波动判断已修复。
5. **终局完整入口仍未过关。** 现有冻结 a6 包两次都返回短时 Rust 结果，但未在原 90 秒内进入可用工厂。一次正常关闭失败，另一次正常关闭成功，尚不能判定问题已解决；成功保存和两次重开仍未验收。本批新 Host 和界面改动还须生成新冻结包验证。
