# 大档显式主档检查点：后台校验与提交

状态：本轮开发验收完成，完整回归、PWA 及冻结包大档冒烟均通过。未发布。

## 问题与改动

角色 develop；任务 `web-primary-checkpoint-20261027`，P1。承接持续优化香港网页版的授权，
从真实生产页面测量普通运行、进入产率复制、持续复制和停止结算四个阶段。

大档没有可复用的权威二进制检查点时，`saveVerifiedPrimaryCheckpoint` 仍走字符串提交。
CPU 样本显示，这会在界面线程构建目录并重新扫描新旧完整正文。开始检查点的两个
同条件复测未能在 120 秒内进入纯挂机，其中一次完全未启用 CPU 剖析。浏览器自身日志
没有给出可确认的 OOM 根因，因此不把“页面失联”直接等同于已证实的内存溢出。

本轮仅在该入口的“大档、无匹配 transfer”分支请求现有 `preferWorkerProof` 通道。
序列化、正文/目录绑定验证和 IndexedDB 提交留在后台 Worker；已有 transfer 的路径不变。
小档、无 Worker/无 IndexedDB、旧格式迁移继续使用原有兼容规则。原生权威与写入权检查、
CAS、失败保护和独立读回保留；没有修改计算内核、配方、存档格式或服务器配置。

修改范围为 [App.tsx](../../src/App.tsx)、自动生成的原生覆盖行号清单，以及
[本地运行探针](../../experiments/web-live-runtime/README.md)。没有增加玩家设置项。

## 实测条件与结果

使用只读准备态 205,464,026 字节，SHA-256
`6a6aa320dd9d5fd5e5b618b745fc864c2ccb2d96143e0b852d1f270358de9ebf`。
共 110,042 个实体、233,300 条运输线，量子网络启用，使用原库存的 `stock` 副本。
Chrome 147.0.7727.138；1440×900；临时浏览器；API 屏蔽；Service Worker 在性能实验中禁用。
副本自动保存设为 0，原文件和线上备份停用设置未动。

持久化会清除运行时产率历史，因此先实际运行至少 40 个模拟秒，再从检查器启动 8 倍复制。
测量期间不并行构建或运行测试套件。原始数据留在本机忽略目录，公开
[汇总证据](./2026-10-27-web-primary-checkpoint-evidence.json) 仅含去标识化统计。

保留积压和清除积压是不同工作量，不能混算平均提升比例。首次诊断支持继续采用后台路径，
正式验收的主要证据是在同一个已复现失败的操作条件下，候选两次均完整启动并停止成功。候选两次的复制阶段
最长画面间隔仍为 183–191 ms；渲染进程旅程峰值为约 5.26–5.41 GB。
这些数字不支持“全程丝滑”、普遍降低内存或整款游戏帧率改善的结论。

另一次附加 Worker 调试器的实验在退出时超时，已排除在对照中；工具原型与证据保留在
私有目录。最初缺少载入后产率窗口的试验属于探针准备错误，也不计作游戏失败。
