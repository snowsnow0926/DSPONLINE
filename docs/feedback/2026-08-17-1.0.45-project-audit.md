## 风险与问题分级

### P0：Android stable 与 v47 云存档不兼容

证据：公网 `downloads/android/stable.json` 明确返回 `1.0.44 / 1000044`；Web/API 已运行 v47/v8/v3。Web 默认路径会把旧 v46 存档迁移到 v47，旧 Android 无法读取该新状态。

影响：跨端玩家可能在 Web 端正常游玩并保存后，回到 Android 端无法恢复云档。这是玩家数据可用性和跨端连续性的发布阻断，不是普通版本号显示问题。

建议立即动作：

1. 使用长期发布证书发布 Android `1.0.45 / 1000045`，完成覆盖升级、旧本地存档保留、签名指纹和公开 stable 清单验收。
2. 在客户端增加能力握手：上传/恢复前明确声明可读 `GameState` 版本；不支持 v47 时阻止静默升级，并给出明确升级路径。
3. 在 Android 发布完成前，不要对玩家宣称 Web、Windows、Android 已全端同步；增加 v46/v47 云档恢复失败 telemetry。

### P1：API/数据库不能直接回滚到 1.0.44

线上 API 已是 schema v8 / SQLite layout v3，不能把 1.0.44 API 和旧数据库直接切回去。Web 回滚也只能使用能理解当前 v47 数据边界的兼容 Web/bridge 制品，不能用旧 Web 直接覆盖线上。

建议：把“代码回滚”和“数据回滚”明确分开；发布记录必须固定当前 API schema、可读 GameState 版本、可用 bridge Build ID 和数据库备份指针。任何回滚演练必须使用合成数据验证，不能把生产数据库降级作为常规方案。

### P1：项目状态文档与线上事实冲突

`docs/PROJECT_STATUS.md` 顶部仍将 `1.0.45` 描述为“开发完成未发布”，并保留旧的 `1.0.44` 生产状态。这直接导致本次审计对象误判，也会误导后续开发、发布和事故响应。

建议：发布完成后由 release 记录驱动状态文档更新；文档顶部只保留当前线上事实，历史候选移入明确的历史章节，并在 CI 增加版本文件/Build ID 一致性检查。

### P1：发布门禁没有覆盖空间站核心 E2E

`.github/workflows/release-gate.yml` 的关键 E2E grep 为 `cloud|save|offline|idle|PWA|leaderboard`，没有匹配 `tests/e2e/orbital-station.spec.ts`。因此标签发布门禁可能在不执行空间站 5 个核心场景的情况下放行。

建议：把 `orbital-station.spec.ts` 作为显式 release-gate job，或将 `station|orbital|space` 加入匹配并固定报告上传；版本涉及迁移时继续保留完整 E2E，而不是只跑关键词子集。

### P2：并行 Playwright 的 hover/持久化/视口时序不稳定

当前证据是并行全量失败、串行重复通过。精确提示失败发生在 `ExactValue` hover 状态和动态工厂节点重绘交界处，当前不能据此断言线上必现业务错误，但它会降低 CI 可信度。

建议：

- 在 `ExactValue` 增加稳定的可观测状态或测试属性，避免只依赖鼠标移动后的瞬时 portal。
- hover 断言等待可见状态和稳定 presentation token，不要在高频模拟刷新期间用固定 1 秒窗口判断。
- 对动态模拟、local-save coordination、viewport persistence 三类用例分别加确定性 fixture；CI 失败保留 trace，并将一次 retry 与最终状态分开统计。
- 检查 `ResizeObserver loop completed with undelivered notifications`、React Flow fallback/stale handle 警告，避免测试日志掩盖真正错误。

### P2：PWA manifest MIME 不规范

线上 `GET /manifest.webmanifest` 返回 `Content-Type: application/octet-stream`。当前 PWA 专项仍通过，但应改为 `application/manifest+json`，并在部署 smoke test 固定校验。

### P2：Windows 安装包未签名

Windows stable 已发布 `1.0.45`，但 Authenticode 为 `NotSigned`。这会造成 SmartScreen/企业策略告警和下载信任成本，不能与 Android 长期签名包等同看待。

### P2：FactoryRuntime chunk 仍偏大

构建警告显示 `FactoryRuntime` 约 `675.85 kB` minified / `196.75 kB` gzip。启动包预算已经通过，但进入工厂后的首屏加载、缓存压力和低端设备内存仍有风险。

建议继续拆分工厂工作区、资料库/星图等重入口，并保留 Worker 权威运行时；以实际首屏、首次进入工厂和冷缓存移动设备指标作为预算，而不是只看 startup gzip。

- 生产 PWA、云存档协调、Worker 崩溃恢复、离线结算和高字体缩放场景均有较强自动化覆盖。

### B. 全量 E2E 稳定化

### C. 工厂运行时性能与分包

负责模块：`vite.config.ts`、`src/App.tsx`、工厂工作区入口、`FactoryRuntime` 相关加载边界。

交付内容：工厂运行时按工作区/资料库/星图/空间站拆分，重型 catalog 继续在 Worker 或懒加载路径解析；保留 deterministic simulation 和 authoritative save 协议。

验收：冷缓存桌面/移动首次进入工厂的长任务、JS heap、交互可用时间有基线；不增加 startup/menu 预算；大存档手动保存不回到主线程解析。

### D. 发布工程与可观测性

负责模块：`.github/workflows/release-gate.yml`、`docs/PROJECT_STATUS.md`、`docs/releases/`、部署 smoke checks。

交付内容：空间站显式门禁、Web/API/native/download 版本矩阵检查、schema/可读版本一致性检查、manifest MIME 检查、发布后 telemetry 仪表板。

验收：任何 schema 迁移在客户端 stable 不齐时自动 No-Go；发布记录与公网 version/health/feed 一致；回滚说明不会诱导 API 数据降级。

### E. 空间站体验收敛

负责模块：空间站 workspace、主 HUD 层级、桌面/移动响应式样式和视觉 E2E。

交付内容：空间站专注模式、工厂 HUD 降噪、合同/装饰/货运端口的桌面视觉快照、公开主页隐私状态和移动返回栈验收。

验收：桌面空间站首屏不被底层工厂 HUD 抢焦点；桌面、390×844、横屏、200% 字体下无遮挡；公开、私有、不存在站点状态保持严格区分。
