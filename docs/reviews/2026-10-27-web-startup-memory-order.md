# 大档启动检查点与快照的内存时序

状态：本地开发候选，未发布。接续 [旧缓冲引用诊断](./2026-10-27-web-obsolete-checkpoint-buffer.md)。仅清理引用已经证明可释放约 207 MB 可达二进制存储，但正常运行的进程峰值下降不稳定，因此继续处理较早的对象重叠。

默认大档 IndexedDB 路径保留原有私有快照生成顺序，再完成普通模拟 T0，最后创建保存后台副本。T0 数据仍完整接收、校验并作为原有回退状态保留；该次不再使用的 transfer 缓冲及时解除引用。保存阶段复用同一启动操作记录的 Worker、revision、注册表指纹；任一项失效或仍有普通操作未完成就拒绝旧快照，不能直接跳过检查点。

小档、缺少可用模拟 Worker 的路径以及可选 durable 协调器保留原流程。启动时钟仍在这些步骤之前锚定，不漏计或重复计时；GameState、材料、存档和备份规则没有调整。

初版 `709c913d` 将 T0 放在私有快照之前，单次真实页面试跑得到 621.8 ms 最长进入间隔、5.582 GB 最大渲染进程峰值；没有足够收益，并出现响应变慢的信号。该排序没有作为合格方案保留。当前排序只让 T0 提前于后台副本，避免同时改变原来的私有快照生成时机。

当前 22 项启动/故障专项通过，包括运行与暂停起步、T0 回包先于快照上传、保存失败重试、真实第二标签页接管、提前退出、退出发生在 T0 尚未返回时禁止迟到上传，以及 T0 本身崩溃后的原档保留和重试。已完成类型与 Web 构建检查；完整回归、完整大档一致性和不强制 GC 的整页对照尚待完成，不能据此宣布峰值下降。
