## 这一批做成了什么

Rust 现在能处理更多短离线场景。例如产线接近仓储容量上限时，旧算法无法证明后面的生产一直稳定，就会把结算交回原流程。新增入口会在有界范围内用 Rust 完整精确计算，验证结果后再采用。这批补齐的是 31–60 秒的短瞬态，不会把未算出的收益当作已经结算。

此前已支持的普通产线长离线继续保留：在完整状态能证明、设备和传送带合计最多 2,000 条等预算内，可处理 8 小时以内的离线。复杂终局大工厂的长挂机仍需继续开发。

代码 **68e87775** 已提交并推送。对应 Windows 开发包 **1.2.7+68e8777529d8** 已冻结，76 项制品、79 个文件核对一致；当前未数字签名、未公开发布。[本批完整技术与验收记录](./reviews/rust-windows-short-transient-2026-09-10.md)

## 真正在游戏里验证了什么

用同一个新 Windows 包，保留原来的六组测试，再加入短瞬态成功和取消，共八组全部通过：

| 场景 | 实际计算的游戏时间 | 成功进入游戏并打开设置 | 保存与取消结果 |
| --- | --- | --- | --- |
| 容量临界的短瞬态 | 32 秒 | 约 2.0 秒 | 成功落盘、取消保档、两次重开一致 |
| 稳定生产 | 601 秒 | 约 2.1 秒 | 同上 |
| 容量触顶 | 601 秒 | 约 2.2 秒 | 同上 |
| 接近 8 小时挂机 | 28,501 秒 | 约 3.8 秒 | 同上 |

这些是 110 个设备、2 条传送带的公共测试产线，每组只有一次完整样本，**不能推广成终局大厂的速度或稳定提速比例**。整 8 小时的独立程序对照另行通过；上表实包的实际时间为 28,501 秒。

每次都把 Rust 的完整结果与 JavaScript 逐秒计算结果比较，真正写入磁盘的数据也比较。八组共 **32 次隐藏、静音、不聚焦的启动和正常退出**，没有显示窗口、抢焦点或弹系统对话框；取消和重开没有改变源存档。
