# 1.1.6 纯挂机高倍率修复开发报告

## 结论

本候选基于线上 1.1.5 基线 `63149cc`，运行时修复提交为
`137be4db256da1898ecf7e1e171e145f0dbc0c8f`，分支为
`codex/1.1.6-pure-idle-conservative`。本轮只完成源码、测试和开发证据，未连接、上传或修改任何生产环境；用户提供的原始存档也未被写回。

这里的“1.1.6”是开发候选标签。源码提交仍保留 1.1.5 的公开版本元数据，避免在尚未完成版本封装、原生签名和不可变制品冻结前改变线上版本号。Release Agent 必须从该提交建立新的版本封装提交并重新运行版本一致性门禁，不能直接把本开发提交当作已发布 1.1.6。

## 根因

1.1.5 会把正文体量不少于 64 MiB 或估计峰值不少于 2 GiB 的存档路由到保守宏观路径，以避免终局档在精确校准/复制时触发内存峰值。旧路径虽然推进了高倍率时间和科研，但保守尾段使用空合同，冻结了工厂累计生产、白糖、戴森火箭/结构/太阳帆等终局产出。因此界面显示时间扭曲倍率，实际挂机收益几乎为零。

## 修复内容

- 保守路径先执行固定 1 秒、可取消的精确前缀；若能证明生产安全，则从前缀生成紧凑的累计计数器合同。
- 合同只允许单调、白名单累计字段（累计生产、白糖/戴森累计指标、发射/吸收、出口与已完成合同等），不外推库存、实体输入输出缓存、传送带在途货物、路线或循环诊断。
- 对测得累计速率应用 80% 安全折扣，之后仍按存档实际高倍率推进时间和独立科研账本；瞬时物流字段保持校准检查点，避免把一秒样本冒充长窗口精确回放。
- 有限资源模式若仍有可采矿脉，禁止外推生产/终局累计计数；该情况下只推进时间与科研，等待普通精确结算处理资源边界。
- 保守尾段明确禁止回退到不受界限的长时间精确模拟（`allowExactFallback: false`）。单个已超过 JavaScript 安全整数的累计字段会被安全冻结，不再拖累其他可安全应用的累计字段。
- 对重复 30 秒宏观桶保留整数小数余数，保证分段结算与一次性结算的状态哈希、科研余数一致。

GameState/envelope/cloud schema/layout 均未升级（仍为 v47 / v2 / schema v8 / SQLite layout v3）；算法标识继续使用 `pure-idle-macro-v3`，只在运行时摘要中以 `contractVersion=1` 表示新的保守累计合同，兼容现有恢复边界。

## 真实存档只读验收

夹具为用户提供的 `dsp-idle-save-2026-08-24.json.gz`，仅在浏览器 Worker 内存副本中解压和迁移：

- 压缩体积：1,923,618 B；源 SHA-256：`bf6a53e8f402d6bee5729eed9f389a63eba0bc7ca78e9d00807c636304b78ca1`。
- envelope v2、GameState v47、普通模式、无限资源；约 38,427 个实体和 79,755 条传送带。
- 30 天纯挂机只读结算：请求/实际倍率均为 15x，结算 2,592,000 模拟秒；结果可规范重载，实体/传送带数量保持。
- 白糖、火箭、结构点和太阳帆吸收等终局累计指标均有正增量；无限科研继续推进。
- 测试前后重新读取压缩源的 SHA-256 完全一致，未上传、覆盖或修改原文件。

## 残余风险

保守合同是有界近似：累计速率固定使用 80% 折扣，瞬时物流不在长尾中重建；因此可能低估实际收益，但不会把不确定物流或资源储量夸大为精确收益。下一次普通保存/精确窗口仍是重新校准边界。有限资源存档继续走冻结保护分支，不能以本修复绕过资源耗尽规则。
