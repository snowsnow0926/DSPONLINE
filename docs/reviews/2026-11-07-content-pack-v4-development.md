## 范围

- `technologyEffects`：生产速度、能耗、采矿速度、输入/输出容量的实际倍率。研究完成时生效，多个效果按声明顺序叠加，保留用户硬容量上限。
- `recipePolicies` / `recipeGroups`：建筑配方白名单与组合科技门槛，覆盖选择、实际生产、手合、递归制造、规划及原生相关入口。
- `fuels` / `generators` / `resources`：燃料热值、发电效率、连续发电，以及现有类地行星的自定义资源和矿机映射。采集计入整数库存，有限矿点不会因更新/读档补满。
- 作者工具：分项表单、可运行晶体工业示例、内嵌 PNG/JPEG/WebP 图标、分类筛选、旧 ID 迁移；仍经过校验和兼容性预览才应用。

规范与完整示例见 [MODDING.md](../MODDING.md) 和 [晶体工业示例](../examples/example-crystal-v4.content-pack.json)。本批不开放任意脚本、联网图片、战斗或新存档字段。

## 保档与确定性

GameState 仍为 v47，envelope 仍为 v2。v1/v2/v3 内容包继续读取。启用目录必须先于普通存档规范化；v4 旧 ID 映射在规范化前处理实体内容引用、库存、物流、蓝图、队列、规划和研究。实体 ID、坐标和名称保持。整数库存相加、十进制大整数精确相加、同科技进度取最大值；冲突或安全整数溢出取消应用。

新包需保留既有迁移规则；版本兼容结果写入 `compatibleSaveVersions`，使导出的新包可在另一设备读取已验证旧版存档。删除无映射的旧条目、改变旧配方物料/设备结构或降低建筑容量仍会被拒绝。多个旧 ID 合并时逐个检查原定义，不能用最后一个条目掩盖液体/固体等类型冲突。含隐藏小数的进度按 ID 顺序合并，与 Rust 有序映射一致；v4 规则修改也纳入更新预览的新增/修改计数。

JS/Worker 使用索引查询与按科技完成集合缓存的倍率；Rust 使用同一可选目录。连续模拟内的计算读取当前研究状态，不能沿用整段开始时的容量倍率。

原生直接导入在原文件校验完成后，对导入候选逐条应用同一类型的 ID 映射，并补齐缺失的自定义资源；原文件和源校验证明保持。已有矿点以行星/资源识别，避免改名或重复导入补满矿量。未安装对应内容包时仍遵守原先的内容引用保护。
