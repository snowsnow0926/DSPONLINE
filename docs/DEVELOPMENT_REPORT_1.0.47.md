> 日期：2026-08-20

## 交付结果

1. 设置中新增“经典”基础卡片，位置在“中等”和“一行”之前，恢复 1.0.43 的 `224×76` 精简卡片信息结构。
2. 修复拖动画布并发生选择/拓扑重绘后，批量 Canvas 传送带与 React Flow 建筑坐标分离的问题。
3. 修复任务、生产链、线路网络或寻线聚焦存在时，开始连线会让无关建筑半透明的问题。

## 根因与修复

### 经典卡片

1.0.46 只有中等和一行两类紧凑展示，无法表达玩家希望保留的 1.0.43 旧精简卡结构。现在 `classic` 是独立、可持久化的设备偏好：展示阶段仍归入 compact 性能层，但渲染使用旧紧凑卡，几何、测量缓存和诊断签名均与一行卡分开。自动、完整、中等和一行的既有语义不变。

### 传送带错位

Canvas belt layer 同时接受 React 的受控 viewport 和手势期间的实时 imperative viewport。旧同步 effect 依赖 `updateViewport` 回调身份；选择或拓扑更新重建该回调后，即使 `x/y/zoom` 没变，effect 也会把旧受控 viewport 再写回 Canvas。React Flow 节点仍停留在手势最新 transform，于是两层视觉错位。

修复后，受控同步只由 viewport 数值变化触发，最新回调放在 ref 中；手势期间的实时 viewport 不会被无关重绘回滚。自动化测试真实拖动画布，再触发堆叠代表选择使几何重算，并直接比较两层 transform。

### 连线半透明

旧聚焦规则只保护连线源和已识别候选节点。连线刚开始、候选尚未提交，或 React 节点样式晚一帧更新时，其他建筑仍继承任务/网络/生产链/寻线的 dim class，表现为连线时偶发半透明。

现在只要存在连接草稿或点击连线预览，就暂时停用这些聚焦淡化；样式层另有一帧兜底。Esc、取消或提交后，原聚焦效果按原状态恢复，不改变玩家选择和连线规则。

## 兼容与安全边界

- GameState v47、save envelope v2、cloud schema v8、SQLite layout v3 与 IndexedDB records 不变。
- “经典”只复用现有本机偏好键，不进入存档或云同步。
- 传送带修复只改变渲染视口同步，不改变 belt 实体、端点、吞吐、模拟或库存。
- 半透明修复只改变连接活动期间的展示，不改变候选判定、原子创建或材料扣除。
- 没有玩家数据、生产数据库或线上服务访问。
