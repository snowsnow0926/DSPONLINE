## 1. 范围和兼容边界

本层只优化现有 TypeScript/JavaScript、React 与 Web Worker 架构。它不引入 Electron 原生文件服务，也不迁移模拟核心；计划书的第二层和第三层均未启动。

以下持久化边界不变：

- GameState v47；
- save envelope v2；
- cloud schema v8；
- SQLite layout v3；
- 1.1.8 的 IndexedDB 主存档和分块 sidecar；
- Mod 内容包 JSON 与自定义建筑注册协议。

## 2. 权威状态和大对象所有权

| 大对象 | 创建者 | 同时允许 | 消费者 | 释放边界 |
| --- | --- | ---: | --- | --- |
| 模拟权威 `GameState` | Simulation Worker | 1 | 模拟步骤、命令合并、检查点序列化 | Worker 替换或终止 |
| React/UI 兼容镜像 | 主渲染器 | 1 个已提交 + 最多 1 个待提交 | v47 普通数组兼容视图；实时消息仅含当前行星变化和全局摘要 | React 提交、返回主页或导入新档 |
| 完整 checkpoint transfer | Simulation Worker | 1 | 手动保存、导出或流式保存失败回退；普通大档自动保存不创建 | 转移给下一个 Worker 后立即失去所有权 |
| 分块自动保存页 | Simulation Worker + 页面 IDB writer | 每批最多 8 条记录 | Worker 逐页投影，MessagePort ACK 后继续，页面持有 IndexedDB 租约 | 每批事务完成即 ACK 并释放 |
| 完整 transfer 分块回退 | 可复用 Chunk-save Worker | 严格 single-flight | 仅处理流式路径不可用或失败后的兼容回退 | 5 分钟空闲终止、卸载立即终止 |
| 完整主存档序列化图 | Save Worker | 1 | v2 envelope、校验和、压缩 | 验证回执后终止/释放 |
| 撤销/重做历史 | 主渲染器 | 40 项且最多约 32 MiB | 逆向/正向命令 | 超限、清空 redo、返回主页或导入 |
| 运行时 dirty ID | Simulation Worker | 实体+线路最多 8,192 | 增量索引失效和诊断 | 一次推进后清空；超限降级为 overflow |

开发态保存协调器断言同一时刻只能有一个完整主检查点。自动保存与生命周期保存会合并到正在进行的请求；玩家主动保存若发生冲突，会收到可见的“稍候重试”，不会再分配第二份完整图。

## 3. 命令、模拟和 UI 投影

```text
玩家操作
  │
  ├─ 建造 / 空建筑回收 / 单线拆接 / 蓝图
  │     └─ collection copy-on-write，只复制变化记录和数组指针
  │
  └─ createSimulationCommandPatch(baseRevision)
          │  精确 changed entity/belt/top-level leaves
          ▼
     Simulation Worker
          ├─ 安全运行时字段：按稳定 ID 索引原地应用
          ├─ entity / belt / planet dirty set
          └─ 配方、拓扑、策略字段：确定性完整索引重建
          │
          ▼
     当前行星增量投影 + revision
          │
          └─ React 兼容镜像只替换发生变化的记录引用
```

主线程常见编辑不再调用完整 `copyState`。未变化的实体、线路和蓝图集合保持引用稳定，因此既减少瞬时对象数，也减少 React Flow 的无效提交。复杂删除（例如含库存、站点、特殊巨构或关联线路）仍保留经过验证的完整克隆回退；这是数据守恒优先的明确边界。

Simulation Worker 持有一个可原地推进的结构化投影基线：只快照当前行星记录，字段树在每次实际发布后原地更新。稳态列式投影直接携带全局数组下标，不再常驻保存 80,674 个实体和 155,746 条线路的第二套 ID→数组位置 Map；只有罕见拓扑/全行星投影在单次应用期间创建临时 Map。它不保留权威记录引用，也不再为每个模拟秒生成整条记录的 JSON 签名。

对达到大工厂门槛、未处于时间加速且玩家没有正在选中/放置/连线的普通模拟，Worker 仍按原来的精确一秒步长推进并递增 revision，但每两个权威回执只发布一次大型记录投影。中间回执只返回 revision 与精确 `elapsedSeconds`；下一次投影仍从“最后一次实际发布”的基线计算，因此包含被延迟回执期间的全部累计变化。玩家命令和活动记录交互禁止延迟；只读工厂告警最多落后一个大工厂回执。这是 UI 复制节流，不是降低模拟帧数或产量。

计划书 JS-120 提议的“非数组固定页容器”没有进入 1.1.9 的持久或公共运行时形状。当前候选采用 v47 普通数组边界上的记录级写时复制、稳定 ID 索引和当前行星增量投影，避免一次性改写所有领域规则对 `Array` 的假设。是否把这项等价替代作为第一层交付接受，必须由同机组合峰值和 30 分钟斜率 Gate 决定，本文不提前宣告通过。若数组指针复制仍是前三热点，再以独立 ADR 引入固定页容器；容器结构不得写入 v47。

## 4. 撤销、重做和“无回档”语义

旧实现的每个撤销项保存一份完整 `GameState`。1.1.9 的 `GameStateHistory` 保存正向和逆向 `SimulationCommandPatch`：

- 同一蓝图或批次只有一个历史项；
- 逆向命令由已经生成的正向差异直接反演，只扫描被修改/删除的 ID，不再为了 undo 再做一次全工厂 diff；
- 按条目数和估算字节双重淘汰；
- 新操作会立即释放 redo 引用；
- undo 只反转该次编辑叶子，不覆盖之后已结算的 `elapsedSeconds` 或其他 Worker 进度；
- 保存 Worker 和检查点回执不引用历史栈。

内存保护也不再是恢复操作。达到保护线时，程序暂停当前玩家可见状态，并把已积累的 simulation debt 保留到恢复；它不会安装 `latestAuthoritativeCheckpointRef`。关闭保护时，内存和积压水位同时只作为诊断，不触发暂停或旧检查点替换。真正的 Worker 协议损坏仍可以进入显式错误恢复，但必须显示原因，不能伪装成内存保护。

## 5. 保存单所有权与流式提交

```text
Simulation Worker authority（唯一完整运行态）
      │
      ├─ 大型自动保存
      │     ├─ 顶层持久化投影只构造一次
      │     ├─ entity 1,024 / belt 2,048 条一页投影并 JSON 化
      │     ├─ MessagePort 每批最多 8 条 → 页面持有租约的 IDB writer
      │     ├─ 页面事务成功后 ACK；Worker 才继续下一批
      │     └─ 所有变化块成功后最后写 manifest
      │
      └─ 手动、导出或流式失败
            └─ 单个 transferable checkpoint
                  ├─ Chunk-save Worker 兼容回退，或
                  └─ Save Worker 生成 v2 envelope + checksum + readback
```

大型自动保存不再把 77 MB 完整 checkpoint 传到 renderer，也不在 renderer 构造第二份 80k/155k 对象图。页面继续拥有既有跨标签租约与 IndexedDB 写权，Simulation Worker 只负责有界投影；这避免了“Worker 内存后端误报成功”的耐久性漏洞。成功后清除菜单读取阶段的原始 77 MB envelope 缓存。流式路径失败才生成一个 transferable checkpoint 进入既有完整验证回退，绝不安装旧状态。

manifest 仍最后提交。若页面在流式中途退出，新旧 chunk 可能暂时混存，但旧 manifest 的 checksum/root 不会采纳半成品；读取方忽略不完整 sidecar，并保留兼容的完整主存档作为恢复边界。公开格式仍是 v47/envelope v2，内部 sidecar 仍是 v1 字符串记录。

## 6. 缓存和生命周期上限

- Worker 模拟 lookup 的实体/线路 ID 索引与权威记录共享对象，不再为单个命令临时构建全量 Map。
- Worker 当前行星投影基线只有一个 owner；renderer 稳态投影直接使用数组下标，不再常驻第二套全局 ID Map。切换行星时立即丢弃旧行星字段快照。
- 大型 React 根和 Canvas snapshot 各自最多一个提交在途；中间 Worker 回执合并为最新候选，旧 React commit 不得覆盖更新的命令/模拟 ref。
- 大工厂普通模拟每两个回执发布一次累计记录投影；中间只发布小 revision/时钟更新。
- 暂停时释放完整模拟 lookup，只保留两个紧凑 ID Map；恢复推进时重建一次。
- dirty entity/belt ID 总数硬上限 8,192；溢出只留下 `overflowed` 标志和行星集合，不无限持有字符串。
- 一次模拟推进后清空 dirty ID。
- 性能基准入口只在 loopback 且显式带 `dspPerformanceHarness=1` 时动态加载；生产公网不会安装该全局入口。
- 返回主页、重新导入和组件卸载继续终止既有 Simulation/Save/Chunk Worker，并清除历史对象。

## 8. 安全与回滚

本层没有扩大 renderer 文件、进程或网络权限。回滚只需要切回 1.1.8 应用代码；GameState、envelope、云端和数据库均不需要降级迁移。1.1.9 分块 sidecar 仍是既有 v1 格式，1.1.8 可继续读取或由完整主存档覆盖。

## 9. 已知剩余热点和不夸大的边界

- renderer 为兼容现有工作区仍持有一份普通数组 UI 镜像；它不是权威状态，但尚未缩成只含当前视口的数据结构。
- 实际发布的当前行星运行字段变化仍会让 renderer 浅复制实体/线路数组指针；未变化记录保持共享。隔次累计投影把频率减半，但尚未把 React 兼容镜像改成完全薄视图。
- 模拟 lookup 是权威 Worker 的主要常驻内存之一；恢复、配方或拓扑变化仍允许确定性完整重建。
- 该玩家档每个保存周期约 150/157 个区块都因真实运行字段变化，因此 Web sidecar 仍需写约 74 MB；第一层解决的是对象重叠与峰值，不宣称已达到第二层“原生增量存档”的写盘降幅。
- 物流的稳定路线可以跳过搬运，但现有路线调度仍会检查大量有效线路；本候选不宣称已经把每个模拟秒的全局线路检查完全消除。
- 上述边界不改变 v47 数据，也不构成静默降产。任何进一步页式容器或更薄 UI 都需要独立 ADR、差分测试和新的同机数据。
