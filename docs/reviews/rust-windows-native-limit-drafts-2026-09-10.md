## 输入问题与修复

`NativeResourceRail` 原来在每个 `frame.revision` 更新时重置两个输入框，玩家键入的数字和验证错误会被正常模拟刷新覆盖。Escape 先更新 React 状态再 blur，blur 仍可能提交取消前的数字；同一 revision 下换会话也没有使旧草稿失效。

两个输入框现在独立绑定 `sessionId / runId / registryFingerprint / activePlanetId` 和各自的权威原值。只有所属上下文或本字段原值变化才在布局提交前清理草稿，普通 revision 和另一字段变化保留编辑。提交读取实际输入值，再检查绑定和未完成命令；无变化不发命令。Escape 先清除提交绑定再失焦。另一命令等待期间禁止提交，但上下文不变时保留尚未提交的草稿。

这是原生界面的操作正确性修复，没有增加 JS 库存写入路径、修改库存值或开放实时准入。与云端旧 `GamePanels.ResourceRail` 的偶发回退不是同一组件，不能把本修复当作该偶发问题的根因或解决证据。
