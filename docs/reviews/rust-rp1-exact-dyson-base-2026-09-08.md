## 定位与修改

前一提交 `e5ca4b2e` 已把累积写入清单限制为唯一行，并保留原累计提交计数；完整 Rust 通过，但公共套件仍有两项 Host 请求超时，600 秒的整体计时基本持平。保留该结果，不把局部内存约束当作已解决长等待。

在冻结 `e5ca4b2e` Host 上，公开有限矿 3,600 秒的显式诊断约 30.479 秒，其中 `time-warp-and-dyson-environment` 约 11.520 秒，`logistics-dispatch-and-routes` 约 12.057 秒。前者含环境准备，后一个旧标签实际只包围 `dyson::finalize()`，不能按标签误判为物流路由热点。这些带日志的值只用于定位。

`advance_environment()` 与 `finalize()` 原先各自 `base.clone()`，连无关的生产历史、库存和全局记录都复制。`load()` 已为四份戴森记录建立独立临时结果，因此整个吸收、衰减和汇总期间可直接只读借用原基础状态；所有步骤成功后，仍由原 `save()` 发布四份结果。没有改变浮点、实体顺序、模拟秒数、物料规则、历史内容、错误处理或提交顺序。

专项包含活动与空闲戴森、0/小数/1/5/60/1,200 秒、两阶段之间的科研变化、未知字段与负零，并用旧整份复制路径逐步比对完整字节；活动场景要求实际发生帆过期。缺失四种戴森记录时，失败后基础状态完整不变。首轮活动夹具漏了逐星系吸收余数，原路径也拒绝该夹具，4 通过 / 1 失败；补齐后专项 **5/5**（新增 2、原准入 3），没有放宽规则。
