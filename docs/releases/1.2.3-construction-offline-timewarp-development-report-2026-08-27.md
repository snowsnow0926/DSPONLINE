- SHA-256：`34d772c6ed0c91fa216c99d89ed5e91e7b788682cca0faaee4ef9ae08074824a`
- 拓扑：45,992 个实体、92,370 条线路

修复内容：

1. 量子直供建筑制造使用递归副产物时，旧批处理把每一轮的完整输入都当成必须预存的本金，并把不稳定的一作业阶段错误缓存；真实闭环因此被每帧 256 次保护上限截断。现在先执行一次真实前缀，再以“完整首轮成本 + 后续净消耗”计算最大批次；直接量子缓冲也会探测并缓存稳定的多作业循环。配方、库存、托盘容量、目标上限和守恒门禁均未放宽。
2. 纯挂机首个 3 × 10 秒校准完成前没有可验证宏观快照，旧界面却用启动存档减自身显示“本次 +0”和“未运行”。现在校准期明确显示“首个验证快照生成中 / 校准后显示”，产线效率显示“校准中”；只有 Worker 返回首个权威摘要后才显示实际增量、速率和效率。
3. Electron `closed` 回调在窗口已销毁后读取 `BrowserWindow.webContents.id`，普通退出可能抛出 `Object has been destroyed`。现在窗口创建时即捕获 renderer owner，关闭回调只使用不可变 owner id，并把窗口清理绑定到对应实例；延迟 `ready-to-show` 和升级前保存也增加已销毁边界。
4. Windows Rust 影子核心同步采用步骤开工前的原子输入预留，并能从真实托盘、WIP 和量子缓冲重建旧持久任务的未提交后缀；完整 35 项 JavaScript/Rust 确定性差分门禁通过，不会让 Beta 包在两套权威投影间产生分叉。
5. 终局存档会同时向多个恒星系发射火箭，旧 `v7` 事件账本硬限制单恒星系，因而即使 30 秒校准真实发射了火箭，后续宏观速率仍显示 0。`v8` 改为逐恒星系整数权重和独立小数余数；全局生产、发射、结构以及各星系结构必须同时闭合，分段与一次结算必须逐星系一致。普通快速离线结算复用同一账本。大存档因复杂度主动进入低内存宏观时，界面也不再误报为“Worker 连续失败”。

更新后的真实档专项结果：施工领域 64 个模拟秒约 0.65 秒并完成 17,482,938 件；15×、10 分钟纯挂机白矩阵增加 150,795,242,815，火箭由仅精确校准期 23,663,839 枚恢复为按 8 星系闭合账本结算 2,935,893,620 枚，建筑制造在纯挂机结算中按真实库存递归完成 17,697,402 件。30 秒校准约 56.9 秒、尾段约 53.2 秒、正式序列化与重载约 3.45 秒，结束时 heap used 约 848 MiB；这些是当前机器受并行负载影响的实测值，不冒充峰值或性能承诺。终端守恒、v47 序列化/重载均通过，源文件大小和 SHA-256 未变化。600 秒普通快速离线专项也以 `fast-30s-v5-multisystem-rocket-ledger` 完成并通过重载。

## 实现结果

### 1. 建筑制造巨构从永久缺料恢复

持久任务生成计划时，中间件可能仍在行星托盘；任务真正执行该步骤前，中间件可能被普通生产或其他施工中心消费。旧实现没有在步骤开工前预留完整输入，也不会重建已经失效的未提交计划，因此任务会永久停在“缺少某物品”。

修复后：

1. 每个步骤开工前将完整输入从行星托盘、任务 WIP 和本中心量子直供缓冲原子预留到任务 WIP。
2. 旧持久任务发现当前步骤缺料时，从当前托盘、WIP 和量子缓冲重新规划未提交后缀。
3. 原目标、已完成前缀、真实库存与配方/科技门禁保持权威；不能制造的原料仍明确阻塞，不会生成材料。
4. 施工宏观入口只推进施工中心，复用正式递归规划和批处理，不推进生产、物流、戴森、科研或游戏时钟。

真实档旧任务无需删除即可在 3 个模拟秒内恢复产出；施工领域推进 64 个模拟秒约 392 ms，完成 1,656,464 件，源档不变。

### 2. 大档校准、内存所有权与常数时间尾段

算法标识升级为 `fast-30s-v5-multisystem-rocket-ledger` 和 `pure-idle-macro-v8-multisystem-rocket-ledger`：

- 三个 10 秒窗口在实体/线路数组身份不变时复用同一个 `SimulationLookupContext`，仍保留精确的 10/20/30 秒边界。
- 大型存档的纯挂机 Worker 直接消费 `postMessage` 已隔离的状态，不再在 Worker 内二次克隆；主线程持久检查点仍是回滚权威。小档继续保留普通克隆路径，避免短任务被 Worker 等待预算反向拖慢。
- 精确前缀在 Worker 消费后立即记入会话，不重复创建校准检查点；待处理施工只在下一权威边界或最终收口应用。
- 紧凑普通合同改为原地事务：用原始数值 undo journal 和余数回滚，不再为尾段重新克隆整个 GameState。任一容量、守恒、数值或序列化门禁失败都会恢复原值。
- 采样期合法的任务/科研奖励和银河出口特殊奖励进入显式 grant ledger，防止把正常奖励误报为凭空生成；物流重分布仍不能冒充产量。
- 火箭事件账本记录所有活跃恒星系的稳定整数增量；每个星系持有独立小数余数，避免结算桶切分改变火箭归属。普通离线结算的宏观段和尾验也复用该账本。

更新真实档在当前机器上的 15×、10 分钟墙钟纯挂机结果：

- 3 × 10 秒精确校准及多星系账本建立：约 56.9 秒
- 宏观尾段、终局事件提交和最终收口：约 53.2 秒
- 正式序列化与重载：约 3.45 秒
- 最终白矩阵增加：150,795,242,815
- 最终小型运载火箭增加：2,935,893,620
- 正式守恒、`serializeEnvelope()`、`inspectSave()` 和 v47 重载均通过，源文件未变化。

这些墙钟耗时只描述当前机器的一次完整真实档门禁；进程结束时内存只作诊断，不将其描述为峰值内存证明。

### 3. 多恒星系闭合终端事件领域：小型运载火箭

旧轻量尾段会冻结全部终端事件。新版本新增 `PureIdleRocketMacroLedger`，只在四个紧凑校准点能证明以下条件时启用：

- 生产、发射和结构增量稳定且非负；
- 全局发射/结构增量与全部活跃恒星系结构增量之和严格一致；
- 火箭制造原料边界能沿活动配方闭合传播；
- 每个恒星系使用独立整数余数，分段结算和一次性结算逐星系一致。

满足条件时，火箭生产、发射和结构点按逐星系整数余数账本推进；普通合同仍排除火箭库存，事件账本只确认并记入被立即发射消耗的制造量，未知位置的采样剩余库存不复制。缓存耗尽只停止该事件链。负缓存、来源不闭合、有限矿脉或校准不稳定时继续冻结终端尾段，不降级为猜测。太阳帆、壳面、银河合同等尚未建立闭合账本的领域保持冻结。

更新真实终局档的校准期共制造 24,032,483 枚、发射 23,663,839 枚火箭，发射分布在 `helios`、`borealis`、`aurora`、`ember`、`sirius`、`white_dwarf`、`neutron` 和 `blue_giant` 八个恒星系。旧单星系门禁因此错误冻结；新账本在 15×、10 分钟墙钟测试中安全结算 2,935,893,620 枚，逐星系结构、全局结构和火箭累计完全闭合。当前上游物料最短边界为 3,692 个模拟秒；到达该边界后仍会停止该事件链，不能凭空复制材料。

### 4. 时间扭曲滚动证书

时间扭曲算法升级为 `time-warp-rolling-v5`：

- 第一次切片执行 0.5 秒精确校准和 0.5 秒独立验证，并把已闭合的普通合同、科研账本、逐物料剩余边界、余数和配置签发为 Worker 内存证书。
- 同一 Worker 权威状态、实体/线路身份、模式、控制器和请求倍率不变时，后续切片直接复用证书。
- 证书最多复用 10 秒墙钟；科研完成、倍率命令、普通/多核精确推进、注册表变化或任何权威命令都会使其失效并重新校准。
- 任何未预期异常都丢弃 Worker 权威运行态并要求主线程重新发送检查点，不在可能部分修改的状态上做精确重放。

真实档生产 Worker E2E：

| 请求 | Worker 内部 | 往返 | 证书 |
| --- | ---: | ---: | --- |
| 8× 首次 | 5.589 s | 7.035 s | 新建 |
| 12× 改倍率 | 5.627 s | 6.158 s | 失效后新建 |
| 16× 改倍率 | 5.764 s | 6.246 s | 失效后新建 |
| 16× 连续第二次 | 1.533 s | 2.047 s | 复用，精确校准 0 s |

同一 fixture 的直接 Node 基准约为首次 16× 7.27 秒、连续复用 1.42 秒。时间扭曲倍率变更仍通过真实命令路径，不能绕过证书失效逻辑。

### 5. 恢复边界与迁移兼容

- 旧存档迁移会恢复 101 个资源矿脉锚点。若这些锚点全部没有矿机，且不存在线路、科研、任务、出口或其他活动，快速恢复会把它们识别为“惰性资源锚点”，不再错误弹出离线决策。
- 该特殊判断只用于离线候选选择，没有放宽普通精确引擎的静止语义。
- 取消、跨标签候选和异常恢复继续保留源检查点；生产 Worker 意外失败会清空运行时 revision、索引和投影缓存，必须由新权威快照恢复。

## 诚实限制与后续边界

- 本次只闭合了火箭这一类终端事件；真实测试档的八恒星系火箭已按独立余数账本推进。太阳帆、戴森壳面、银河出口和合同尾段仍只保留已证明前缀。
- 时间扭曲真实档的非关键瞬时库存诊断仍可能达到 200% 相对误差；关键结果误差上界仍为 1.0。它是有守恒围栏的近似结算，不能宣传为精确结算。
- 第一次时间扭曲切片仍约需 5.6～5.8 秒 Worker 时间；收益主要体现在同配置连续切片约 1.53 秒，而不是把首次校准伪装成常数时间。
- 1× 大档纯挂机仍可能等待完整 30 秒校准；操作现实截止为 90 秒。当前真实档 15× 门禁的校准及多星系账本建立约 56.9 秒。
- 施工宏观使用结算时的功率快照，不在领域外额外燃烧发电燃料；燃料型孤立电网的超长尾段仍需未来的闭合燃料账本。
- 本分支未升级 GameState v47、envelope v2、cloud schema v8 或 SQLite layout v3。
- 当前仅为开发提交。正式发布仍需由独立 release 角色固定 clean SHA、构建不可变制品、签名并执行生产发布门禁。
