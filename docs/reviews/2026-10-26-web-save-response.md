# 网页性能循环：大档保存回包响应

Role: develop。继 [保存投影](./2026-10-26-web-save-projection.md) 后继续减少页面停顿。本轮针对普通 `serializeEnvelopeInWorker` 的回包，不改游戏数值、存档格式或自动备份停用设置，不代表线上发布。

## 改动

超过 1 MiB 的保存回包分段执行完整 FNV 校验，随后使用一次严格 UTF-8 解码。这样不会为了分段保存多个已解码的大字符串。小回包保留同步快路径，原有权威保存客户端的流式解码默认行为保留。

低内存模式用于私有一次性 Worker 的独占回包；验证期间缓冲区不交给其它写方，避免校验后又被修改。它仍有一次同步原生解码，不能作为通用的无长任务字符串解码器。

可见页面在校验段之间让出调度机会，兼顾输入、画面和普通定时器；隐藏页面避免依赖受节流的计时器。回包尚未验证完成时不发布结果。新增中止、重复回包和结束状态保护；Worker 错误、反序列化错误和坏字节回退到原始状态，回退本身失败则拒绝 Promise，不继续悬挂。

曾试验直接分段拼接字符串、文本回传和 Blob 回传。它们分别出现更高内存或更长停顿，未保留生产改动。最终只保留二进制协议及低内存校验方式。

## 实测与限制

在 Chrome `147.0.7727.138` 的真实保存 Worker 中，以同一私有预热大档运行旧/新/新/旧两轮，四次旧、四次新。旧回包实现从 `d84392b5` 读取，仅替换 `storage.ts` 和 `saveTransferDecode.ts`；其余模块相同。八次输出均为 110,789,823 字节，SHA-256 均为 `22cbbcd7aae757d67b376028c15bf21f84596df4c418253cba9706c775589962`。

| 中位指标 | 旧实现 | 本轮候选 |
| --- | ---: | ---: |
| 回包阶段最长画面间隔 | 259.30 ms | 158.10 ms |
| 回包后立即发送的测试点击响应 | 253.25 ms | 3.00 ms |
| 回包处理总时间 | 252.75 ms | 273.15 ms |
| 完整 Worker 往返 | 2,392.65 ms | 2,371.55 ms |
| 初始完整状态复制 | 339.65 ms | 332.20 ms |

最长画面间隔减少 **39.03%**。点击在回包时立即注入，说明校验期间能响应输入，不代表任何时刻点击均只需 3 ms。最终一次原生 UTF-8 解码仍有约 150 ms 停顿；初次完整状态复制仍约 330 ms。完整保存耗时没有可靠的实质下降，不能宣传为整体帧率或整个保存流程提升 39%。

开启精确内存读数的独立内存观察中，主页面和结果均保持存活，主动 GC 后页面堆为旧 261,428,101 / 新 261,438,533 字节，基本相同。八次探针的主要 renderer 生命周期峰值工作集分别中位 1,885,243,392 / 1,887,270,912 字节，也相近。页面瞬时堆采样受 GC 时机影响有波动，不将其当作内存下降证据；renderer 生命周期峰值包含样本读取和测试结果编码，并非完整游戏运行峰值。
