## 2. 本轮新增实现

### 2.1 WIN-410：保存峰值、磁盘水位与空闲合并

- renderer 收到新检查点或 WAL 后会取消并重新安排尚未开始的 15 秒空闲 compaction，减少连续活动期间无意义的保存合并；已经进入 Rust Host 的合并任务仍不可中途取消。
- JavaScript 主进程在发送原生保存批次前，以精确 UTF-8 字节数和 `bavail` 检查目标卷可用空间，并固定保留 64 MiB。仅 API 明确不受支持时返回 `checked=false`；空间不足、路径、I/O、回执或整数异常均失败关闭。
- Rust 在实际写入 chunk、WAL、manifest、superblock、统计 sidecar、实时 lease 和 v47 导出 `.part` 前再次执行写入字节数加 64 MiB 的最终门禁。磁盘不足不会替换旧检查点、WAL、lease、sidecar 或导出源状态。
- v47 导出先流式编码到计数/校验 sink，再以相同摘要进行第二遍流式落盘，取得精确预留量而不额外保留一份完整正文。
- 仍未关闭：base 五域每次保存仍需先序列化和哈希；已启动 compaction 不可取消；真实磁盘满、只读目录、Defender 锁文件、进程终止、覆盖升级和 24 小时矩阵未执行。

### 2.2 WIN-420：稀疏线路预留热循环

- `ActiveSelection` 除 mask 外携带稳定的选中行索引；稀疏模式下线路 reservation 只访问本步已选路由，避免再次遍历全部线路行。
- 活动度达到 75% 时自动使用稳定顺序全扫描，不为真实稠密工厂伪造“跳过 90%”收益。
- 选择阶段仍遍历全部 route group，因此当前只能称为“稀疏热循环”，不能称为完整事件驱动或真正 O(active) 网络。

### 2.3 WIN-430：本机确定性线程门禁

- 增加独立 Host 的 `1/2/4/8` 实际 Rayon worker 矩阵，每个 cell 都在新进程中运行并校验 worker 观测、完整状态哈希、领域哈希、守恒摘要以及输入文件不变。
- 44.17 MB 真实存档的最终矩阵 4/4 通过；四档得到相同 revision、规范状态哈希、领域哈希和守恒摘要。
- 该结果只证明本机当前覆盖范围内的确定性，不代表全部权威领域已经并行，也不替代跨 CPU、Windows 10/11、不同调度和 24 小时矩阵。

### 2.4 WIN-440/WIN-460：统计窄读与持久化分层桶

- 统计工作区不再为了打开面板索取完整顶层 checkpoint，而是请求 revision 绑定并经过 renderer 边界校验的 `statistics-v1` 窄投影。
- 打开面板只发起一次统计请求；只有 `historyRecordedAt` 进入新采样边界时才刷新。E2E 同时证明统计入口为 1 次 `sync-statistics`、0 次 checkpoint；戴森入口仍使用既有 `sync-projection`。
- Rust session 的 1 秒、1 分钟、10 分钟和 1 小时生产历史冷层写入私有 sidecar，并绑定 checkpoint 身份与 SHA-256；恢复要求规范、有序、连续、无重叠、无缺口且不超过 24 小时。与历史无关的 pause-only WAL 保留缓存，未知或影响历史的补丁安全重建。
- 公开 v47 的 `productionHistory` 字节没有改变。采样边界仍需扫描权威记录，且工厂 viewport UI 尚未改为薄投影，因此这不是完整全领域事件统计或完整薄 UI。

### 2.5 原生保守纯挂机会话

- 私有 wire mode 增加 `pure-idle-macro-v10`。Rust 精确执行 `3 × 10` 秒前缀；无法证明守恒的物料尾段只推进时间，不复制生产、火箭、太阳帆、出口、合同或施工结果。
- 私有 `pureIdleMacroSession` 记录持续额度、检查点身份和最终 `SettlementProof`；旧版不认识该私有字段时仍可按旧私有会话降级读取，没有新增公开持久字段。
- 这条 Rust 路径选择“宁可少发收益，也不凭空复制物料”。它没有把 JavaScript e503 的 productive 宏观尾段完整移植到原生，所以 `pureIdleMacro=false`、`offlineAndTimeWarp=false`、`authorityEligible=false` 继续保持。
- 玩家当前使用的 JavaScript 路径仍采用 e503 的 `3 × 10` 秒校准、闭合稳态证书、逐恒星系火箭账本、最终守恒门禁和量子库存直供建筑制造；本轮没有用较弱的 Rust 冻结尾段替换玩家结果。

### 2.6 启动冒烟证据规范化

- 性能开发版冒烟只允许 beta/nightly 包显式使用系统临时目录下的专用 profile，拒绝 stable、目录重定向、reparse/symlink 和越界路径。
- 启停只追踪本次启动得到的精确 PID 树，不按进程名批量终止。
- 修复 PowerShell 空数组序列化，使 `residualProcessIds` 明确输出 `[]`，而不是虽然逻辑计数为 0、JSON 却显示 `null`。
