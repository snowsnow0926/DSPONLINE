# 时间扭曲退出：释放后台与检查点验证

状态：本轮本地验证与冻结完成，未发布；后续取消/重试边界修复见 [恢复记录](./2026-10-27-durable-idle-recovery-findings.md)。持续性能优化保持进行。

## 给玩家看的进展

此前测得约 25% 的退出等待改善，但该实验包含后来发现不满足完整存档一致性的转交路径，
已经撤回，不能作为保留方案的性能结果。保留方案恢复原有保存校验后，三组网页对照的停止保存
等待中位 **17.277 秒 → 13.492 秒，减少 21.9%**；内存峰值仍约 5.5 GB，最长停顿超过 1 秒。

## 本轮处理的问题

原默认网页路径在停止时保留宏观模拟 Worker，等主线程解码完大档后才关闭它。
随后保存流程还会取得一次即将废弃的普通模拟 T0 检查点，并把完整新状态复制给保存 Worker。

本轮将暂停、科研完成和挂机记账移动到终态序列化之前，沿用原有的终态结算函数。
主线程收到并核对终态元数据后先关闭宏观 Worker，再解码；解码得到的完整状态仍保留供失败重试。
已解码终态仍交给原有的完整状态保存通道，保留原来的标准化与独立校验；不再采用直接转交存档的试验路径。
只有与当前终态候选对象、权威租约和模态会话一致、且普通模拟没有待办工作时，才省略旧 T0 检查点。

保留原有内存保护、单次保存所有权、存档目录升级回退、revision/fencing 校验、独立读回、旧主档备份、
自动快照规则和失败重试。写入失败后复用已保留的终态对象，不重新计算挂机收益。
GameState v47 / envelope v2 不变；没有修改生产服务器或自动备份停用设置。

## 固定大档对照

只读输入为 205,464,026 字节、110,042 个实体、233,300 条运输线；SHA-256：
`6a6aa320dd9d5fd5e5b618b745fc864c2ccb2d96143e0b852d1f270358de9ebf`。
对照每次使用独立 Chrome，以旧/新/新/旧/旧/新串行执行，不并行构建或测试。

**已撤回的单独保存交接没有加快**：旧式完整状态复制三组中位 2,672.5 ms，终态存档转交为 3,068.5 ms，
增加约 14.8%。该步骤仍重新核对、解析和压缩存档，因此不能把转交本身称为速度优化。
这项测量不含数据库、停止结算及普通模拟检查点；整页收益需要另测。

六次后台返回的完整存档 SHA-256 均为
`f95edd5cbb4542d9f1eaa943fcc3eb4ea5c1010b97a9ac55ce26f5e7b32f1329`，
调用者完整状态前后摘要一致。但此试验未覆盖界面解码时的全部标准化，不能证明实际终态的完整一致性。
后续大档终态对照发现，直接转交路径对 2,171 个实体的增产进度字段和电网统计标准化与旧版不同，
落盘内容增加 116,108 字节。界面状态与旧版一致，但不能以此推定保存内容等价，故撤回该路径。

撤回后，分别用原科研状态和浏览器副本中人为构造的科研完成边界，比较旧流程与保留流程。
两种情况下，界面完整状态、最终持久状态及实际保存 Worker 返回正文的 SHA-256 均与旧流程一致；
实体、运输线、暂停状态和挂机时间也一致。科研完成场景是明确标注的本地压力副本，
不是对原存档自然状态的描述。另以原库存启用建筑制造、8 倍产率复制，固定推进 30 秒墙钟、
240 个模拟秒；制造巨构完成计数增加 122,880，旧/新完整状态及保存 Worker 正文 SHA-256 一致。
该计数按游戏现有规则包含制造成品及可能的载具，不等同于建筑数量。

## 已撤回方案的实际页面对照

对照基线为干净运行源码 `c01ad5dcc2fb` 的冻结 Web 包，新版是包含已撤回转交路径的实验构建。
下表和 25% 结果只用于保留过程证据，不代表当前保留方案，也不应据此发布。
使用原库存，先推进约 40 个普通模拟秒以取得真实产率统计，然后通过实际界面进入 8 倍复制，
观察 5 个墙钟秒，再停止并保存。每次浏览器会话独立，运行顺序仍为旧/新/新/旧/旧/新。

| 指标，三组中位 | 旧版 | 新版 |
| --- | ---: | ---: |
| 停止并完成保存 | 18.265 秒 | 13.701 秒 |
| 退出阶段最长画面间隔 | 1.259 秒 | 1.152 秒 |
| 保存请求在主线程发送的耗时 | 513.3 ms | 低于计时分辨率 |
| 普通模拟预热等待 | 46.963 秒 | 47.964 秒 |
| 渲染进程旅程峰值工作集，十进制 GB | 5.481 GB | 5.373 GB |

三次旧版退出耗时为 19.616、17.439、18.265 秒；新版为 13.654、13.701、13.793 秒。
旧第一例普通预热也更慢，全部样本均保留；反向顺序的旧/新退出仍为 17.439 / 13.701 秒。
六次种子主档摘要一致，六次均保留 110,042 个实体、233,300 条运输线、暂停状态和副本的禁用自动保存设置。
普通模拟不是本轮加速目标；各次墙钟结算边界不同，不能声称六次实际页面最终状态完全相等。

日志确认旧路径每次额外取得 1 份普通模拟检查点，新路径均为 0；传送完整对象的主线程发送长任务被省去。
最长画面间隔仍超过 1 秒，进程峰值差异很小；不宣称整体 FPS 或内存问题已经解决。
独立交接步骤虽变慢，整页减少约 4.6 秒等待，但大档完整落盘内容不一致，故整个转交改动被拒绝。
