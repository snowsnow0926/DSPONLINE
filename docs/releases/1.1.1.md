## 发布期间异常与恢复

发布过程没有隐去以下事故：

1. 香港前两次新鲜备份在 `create_backup_evidence` 阶段被拒绝；失败临时快照被精确清理，API、代理和 timers 自动恢复。最终使用既有 Backup API，并仅把新快照自身规范为 DELETE journal 后完成 evidence；没有触碰生产库侧车。
2. 第一次两地 dry-run 更新控制入口并重启代理时，远端解包没有恢复 `api-active-entry.sh` 与 `api-writer-lock.sh` 的执行位，active API 以 systemd `203/EXEC` 进入 start-limit，health/ready 短暂为 503。Web/API 代码指针始终保持 1.1.0，数据库未改。发布代理逐字核对冻结脚本 SHA 后只恢复 `0755` 安装权限，使用 1.1.1 控制入口启动既有 1.1.0 API；两地恢复后 active API/代理 `NRestarts=0`，再重新执行 dry-run 与正式切换。上海访问日志最后一条该窗口 5xx 距收口审计 440 秒，之后 20×health 与 20×ready 全为 200，critical journal 为 0。
3. 下载页前三次尝试分别被 HTTP→HTTPS 301 误判、历史状态备份同名保护和本地 shell 局部变量提前展开阻止；每次 `current` 都恢复为 1.1.0。修正发布脚本后使用严格 TLS 本机 vhost 验收，最终一次原子切换成功。

这些异常没有修改或恢复玩家数据库，没有上传玩家存档，没有更改排行榜、账号或生产数据。
