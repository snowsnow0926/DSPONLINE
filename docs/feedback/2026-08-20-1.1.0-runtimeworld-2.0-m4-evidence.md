# RuntimeWorld 2.0 M4 物流、量子与稳定岛证据

日期：2026-08-20（Asia/Shanghai）  
基线 SHA：`58456b391c4311c0a4969cfe7075c0f47bc75b12`  
M4 运行时代码 SHA：`3230e9f002318ad66a924a0f3effe50626d41290`

本报告只使用本地只读玩家夹具和仓库内合成夹具。没有连接生产服务器、修改玩家原档、签名、部署或更新下载页。

## 1. 实现结论

- 为持久模拟增加独立 `compiled` / `legacy` 物流选择器，并贯穿同步、可续跑和多核协调路径；旧路径继续作为领域 oracle 与 fallback。
- 站点槽位在拓扑编译边界规范化并缓存；热路径不再反复克隆槽位。单站点拓扑命令会重建索引并保留所选 oracle。
- 量子库存容量按原始十进制字符串缓存；五秒结算产生的显式零值在下一次实际存入前集中清理一次，避免每个站点重复扫描，同时保持旧状态形状。
- 本地非量子调度使用包含库存、在途、预留、车辆、电力、最低载荷和公平游标的精确阻断快照。快照未变时跳过已证明无结果的扫描；量子边界、跨岛和快照变化均显式 fallback，并记录原因与比例。
- 物流计时改为互斥阶段，`logisticsMs` 的归因覆盖率为 100%；嵌套诊断不重复相加。
- 同时移除单核运行中只供多核合并使用的逐行星 `totalProduced` 拷贝/差分，复用供电 scratch map，并以无展示文案的精确 oracle 聚合堵塞机器数。

## 3. 领域级与 fallback 证据

在同一进程交替运行当前 `legacy` / `compiled` 物流选择器的 60 秒诊断中：

| 档 | 物流+量子下降 | 互斥归因覆盖 | 结果 hash |
| --- | ---: | ---: | --- |
| A | 62.6% | 100% | `de6d26da` |
| B | 74.9% | 100% | `224c9d5d` |

A 的真实档没有传统调度槽位，因此稳定岛计数为 0；B 的 617 个调度槽位全部跨量子边界，60 秒内 37,020 次检查均以 `quantum-boundary` 明确 fallback。仓库内物流压力夹具同时证明本地非量子岛会产生 `stableDispatchSkips > 0`，而 `snapshot-changed`、`cross-island` 和量子边界继续走完整扫描。这里的 fallback 比例是运行形状事实，不把量子扫描伪装成稳定岛收益。
