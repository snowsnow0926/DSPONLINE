### 2.1 保存与恢复

私有检查点格式升级为 v2，但公开存档版本不变。base 分为 core、logistics、Dyson、statistics、unknown-mod 五域，实体页 1,024、线路页 2,048；所有 v2 chunk 必须有合法 SHA-256。v1 继续可读，缺 SHA 的旧实体/线路页在首次 v2 升级时重新编码。

脏状态只在 durable commit ACK 后清除。若 superblock 已替换而 ACK 丢失，同 session 先用 generation/root/revision 对账；对账无法确认时，核心拒绝命令、推进、普通提交、精确提交和新检查点，防止继续生成无法持久化的 revision。状态/投影查询仍可用于诊断。该机制不等于完整 per-domain dirty bitset：五个 base 域目前仍会先序列化并哈希后再比较。

### 2.2 线路、统计与导入

- 线路热循环支持 `All / Dense / Mask`；稀疏路径只处理活动路由和触及槽位，75% 以上退化全扫描。选择阶段仍遍历全部 route group，不能宣称 O(active)。
- 原生 session 私有统计按 1 秒、1 分钟、10 分钟、1 小时分层，目标保留 24 小时；公开 v47 历史保持原字节语义。缓存不持久化，重启后只能从公开约一小时历史重建。
- 原生导入支持 `.json` 和严格单 member `.json.gz`；压缩输入和解码正文均限制 256 MiB，拒绝损坏、截断、尾随、第二 member、reparse/symlink 和身份变化。renderer 不接收路径或正文。
- `advanceMode` 在分段推进、Beta mirror、durable intent 和幂等重试中保留；近似纯挂机明确使用 `pure-idle-conservative-v2`。
- 实体/线路列、拓扑、路线组和本地物流目录建成后收紧容量；没有增加 mmap/LRU。
