## 1. 结论

1.2.3 已完成当前独立工作树中能够安全开发、自动验证并形成闭环的 Windows 原生增量热路径：活动 revision 脏页保存、事件驱动线路候选、有界视口/统计投影、带身份校验的二进制数据面、原生流式 v47 导出、压缩记录流式读取和解析图复用。

这不是“《Windows 高性能架构三层开发计划书》所有终态都已验收”：

- JavaScript 仍是玩家可见权威，`authorityEligible=false`；完整纯挂机/时间扭曲没有切换为 Rust 权威。
- 原生模拟提交仍是确定性单线程；只有解析和编码具有稳定分片并行，未完成 1/2/4/8 线程权威状态矩阵。
- 现有 Canvas/视口虚拟化继续使用，没有在本版新建 WebGL/WebGPU 渲染器。
- 24 小时、三档硬件、Windows 10/11、Defender、磁盘满/只读、覆盖升级、签名、邀请 Beta 和生产灰度需要外部环境或授权，不能由本工作树冒充通过。
- Electron 外壳替换保持 No-Go：尚无“薄 UI 后 Electron 固定开销仍超过总量 15%”的证据。

因此本版的准确名称是“Windows 原生增量热路径开发候选”。

## 2. 本版实现

### 2.1 WIN-410：活动 revision 脏页保存

- base、实体页、线路页、实体拓扑和线路拓扑分别记脏；实体页大小 1,024，线路页大小 2,048。
- manifest 和已验证页 metadata 可跨检查点复用；清洁页不重新编码、哈希或写入。
- 只有 chunk、manifest、WAL、superblock 完成 durable commit ACK 后才清除脏标记。
- 写入失败、响应丢失或重试不会把未提交页误标成清洁；下一次提交会重新发出同一批脏页。
- 10,000 次确定性故障注入覆盖提交、恢复、幂等与代际选择，最后有效 generation 始终可恢复。

### 2.2 WIN-420：事件驱动线路与精确退化

- 原生线路按稳定路由组维护 active queue；源产出、目标消费、当前步生产、库存、进度、流量、拥塞、额度、电力和物流变化均可唤醒依赖组。
- 同一源的并联线路继续使用稳定原顺序、相同预留和公平额度，不能因队列化改变产量或线路缓存。
- 80 条休眠线路合成夹具在 1/5/60 秒下与旧 full-scan oracle 的规范状态完全一致。
- 活动比例过高时自动退回顺序全扫描，避免队列维护比扫描更慢。
- 诊断公开路由/组数、队列、pass、check、skip、wake、sleep、fallback 和变化线路数，不能用少结算伪造收益。

真实极限档中大多数线路确实活跃，本版正确退化为完整扫描；没有通过错误休眠、降频或少产来制造性能数字。

### 2.3 WIN-440：有界视口、统计投影与二进制数据面

- 原生端维护实体位置 SoA，以及按行星划分的实体/线路索引。
- `viewport-v1` 使用稳定游标，只返回视口实体和接触这些实体的线路；单页最多 4,096 个实体、8,192 条线路、1 MiB。
- `statistics-v1` 按时间窗、行星和物品筛选，稳定游标分页，单页最多 512 条、1 MiB；查询不解析实体/线路页。
- 每个 MessagePort 数据块包含 schema、session、revision、sequence、类型、长度和 SHA-256；主进程、preload 与 renderer 均验证身份和 UTF-8。
- Electron `MessagePortMain` 不能把任意 `ArrayBuffer` 放进 transfer list，本版使用受 1 MiB 上限约束的 `Uint8Array` clone，而不是写入一个运行时不支持的伪零拷贝路径。完整原因记录在 ADR-007。

### 2.4 WIN-460/470/480：统计、导出和分配治理

- 同 revision 规范摘要缓存；重复诊断约为亚毫秒级。
- Rust 直接按规范字段顺序流式写出 envelope v2/GameState v47，同时计算旧 UTF-16 兼容 checksum、UTF-8 字节数和 SHA-256，不建立第二份完整 `Value`/字符串。
- Host 使用自有 `.part` 文件、fsync 和原子 rename；Electron 复制到玩家选择位置前后校验来源/临时文件 SHA 和长度，替换失败保留可恢复备份。
- 压缩记录读取由计数 SHA reader 直接进入 zstd decoder，不再同时保留完整压缩正文和解压正文。
- 原始记录使用共享 `Arc<str>`，实体位置使用 SoA；稀疏结算只编码真实变化线路。
- 启动解析结果用于初始化规范证明缓存，推进后的已解析图直接生成证明，避免推进后重新解析完整记录。

原生流式导入、实际云文件句柄上传、mmap/LRU 冷页预算和全部领域事件驱动统计桶仍未闭合，故对应工作包保持“部分完成”。

测试附件为 `76,898,141` 字节、`80,674` 个实体、`155,746` 条线路。原文件测试前后 SHA-256 均为 `ab869c2b52d5f89e1fcbd8bfcb715daa2f5e7b02b4b7d1bd553f12f566531554`；未写回、未迁移、未修复玩家文件。

同一工作阶段的重复样本中，原生相对 JavaScript 的一秒精确推进约为 `1.65～2.20` 倍；单次结果受系统负载和缓存影响，只作为同机观察，不承诺所有玩家获得固定比例。

该档的线路诊断为：

- `activeQueueEnabled=false`
- 路由 `155,746`，路由组 `78,025`
- transfer pass `2`、route checks `311,492`
- reservation pass `1`、reservation checks `155,746`
- full-scan passes `3`
- skips/wakes/sleeps 均为 `0`
- 变化线路 `140,023`

这说明当前真实档是稠密活动网络。事件队列对休眠网络有确定性收益基础，但在这个样本上正确选择全扫描，因此报告不宣称“真实档跳过 90% 线路”。290 MB 也只是原生子进程打开增量，不是完整 Electron 进程树，更不能替代 24 小时内存斜率。

## 7. 发布边界

本任务没有连接香港或上海服务器，没有 SSH，没有改生产数据库/云档/下载页，没有签名、部署或发布，也没有修改任何真实玩家存档。

正式发布前仍必须由独立 Release Agent 在固定 clean SHA 上完成：Windows 10/11 三档硬件 24 小时 A/B/C、Defender/磁盘/只读/覆盖升级、完整进程树内存与 IPC Gate C、签名、邀请 Beta、生产云往返、灰度和观察期。任何一项失败只关闭对应原生能力，不自动回滚或改写玩家 GameState。
