## 2. 根因与修复

### 2.1 历史戴森差额被当成本段新造物

旧门禁要求逐恒星系合计与全局合计在每个候选边界绝对相等。部分合法旧档本来就带有历史差额，即使新结算让差额向零收敛，也会被当作新的守恒失败。

新门禁区分干净基线和历史债务：

- 起点差额为零时，终点仍必须为零；
- 起点已有差额时，只允许保持同一方向并缩小绝对值；
- 新增差额、扩大差额或越过零点均拒绝。

回归测试覆盖精确 580,144 的历史差额：收敛候选通过，额外制造 1 单位的候选拒绝。

### 2.2 建筑制造的供电证书过窄且失效过度

旧施工证书只把可再生余电作为持续额度；燃料电站或储能已经由主供电证书证明的有限运行时长没有正确传递给施工。同时科研完成会无条件让施工证书失效，即使中心需求和电网配置没有变化。

现在三个精确窗口继续保留制造中心的真实负载，并为每个中心记录最低实测供电比例。可再生供电可持续；燃料和储能只能使用主供电证书已计量的有限时长，耗尽后仅停止施工，不向其他产线或施工创造无限电力。证书重新绑定实际实体/线路数组、控制器、倍率、难度、中心需求、数量与优先级；科研完成本身不再构成失效条件。

产率复制挂机新增施工运行时证书：先让施工用真实库存递归制造，再验证施工领域守恒，最后才复制产品定义允许的终局统计。施工不会复制原料或中间件。目标已满足且没有施工任务时会直接返回，不遍历终局大实体图。

### 2.3 Worker 异常被误报并导致会话退出

模拟 Worker 原来把通用运行异常与内容包注册表异常混在一起，主线程只能按“内容包同步失败”停止。现在协议分别返回：

- `registryError`：真实内容包注册表缺失、指纹或目录校验失败，继续失败关闭并显示明确原因；
- `runtimeError`：可恢复的引擎运行异常，要求重新提供权威状态。

运行异常、超时、durable stage/finalize/checkpoint 失败或 Worker 临时不可用时，主线程先退还尚未完成的模拟秒和墙钟预算，终止故障 Worker，再从 durable recovery 或已确认 authority 重建；纯挂机在恢复成功后自动继续。

### 2.4 自动保护安装旧检查点造成视觉或真实回退

内存保护与多条 Worker 失败路径曾直接用最近检查点替换当前画面。该检查点可能早于已经显示的进度或玩家编辑，因此看起来像回档，后续保存还可能把旧状态固化。

所有后台安全路径现在只能暂停“当前可见状态 + 尚未提交的模拟债务”，不能安装历史检查点。历史状态只保留给玩家明确点击的恢复操作。durable recovery 重建期间画面保持不变，但新 Worker 只接收已验证的恢复 authority，以及已有协议明确记录的受支持 UI 编辑；整份画面快照不会被命令重放，避免累计量、时钟或引擎内部字段被重复应用。

### 2.5 蓝图详细卡片固定布局互相覆盖

旧详细视图的紧凑网格与内容高度组合，在卡片包含大量配方参数、外部端口、超大数量或字体放大时会让内容穿出卡片并覆盖下一行。

详细视图现在使用独立 class 和行流式布局，卡片按内容自然增高，列最小宽度为 420 px；长内容在卡片内换行或省略，选择框、施工需求和组合标签不再突破卡片边界。紧凑视图保持既有行为。
