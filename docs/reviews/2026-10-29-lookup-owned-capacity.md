# 2026-10-29 容量缓存随索引代际管理（待性能验证、未发布）

上一候选的八次自然时序未复现持续多占约 551 MB，但守恒退出前 3/10 秒仍有较高工作集。为继续原瞬态内存目标，本实验只改变 engine 的运行时缓存所有者，不改变材料、容量公式、存档或 GameState v47。

原先模块 WeakMap 以 lookup 对象身份存储最多 512 项原始标量。lookup 在部分路径通过 Object.assign 重建索引，而模块表仍跟随相同身份。本候选用模块私有 Symbol 把 Map 放到 lookup 本身，每次构建索引都建立新 Map，原位重建时一起替换。该字段不进入 GameState/存档，也不承诺 WeakMap 就是之前高工作集的成因。

值仍逐次匹配库存和配置上限，启用状态、本地余量与编辑实时读取；最长 256 位、512 项界限不变。旧式或未初始化该内部字段的 lookup 保留直接计算，未引入跨帧库存不变的假设。

已运行容量、槽位、供电三文件 **62 通过 / 0 跳过 / 0 失败**，应用 TypeScript、native coverage 通过。首次命令因已安装 Vitest 不支持 minWorkers 而在执行用例前退出，修正参数后的日志另存；不算功能失败，也不覆盖原记录。
