# 量子入库批处理：大档计算与网页推进

状态：开发验证完成；未发布。用户要求本轮结束后暂停，不自动进入下一轮。

## 给玩家看的结果

本轮把同一轮连续入库的重复整理合并为一次。每笔物资仍按原来的顺序核对容量、保留库存和剩余物资。

| 测量项目 | 优化前 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 同一大档计算 30 个模拟秒，三组中位 | 49.465 秒 | 26.410 秒 | 46.6% |
| 实际网页推进约 41 个模拟秒，单组对照 | 97.265 秒 | 67.776 秒 | 30.3% |

两组指标不相加。第一组不含读取、索引准备、保存和界面调度；第二组是实际生产页面中的进度推进。
网页仍有偶发长帧，进入/退出及制造计算预算仍待后续处理。

## 范围与实现

角色 develop，任务 web-quantum-deposit-batch-20261027，P1；来源为持续优化香港网页版的直接授权。
维持 GameState 47、存档封套 v2、材料守恒、配方优先级、量子容量规则和自动备份停用设置。
没有修改服务器、云存档、签名、下载站或原生引擎。

原 CPU 样本显示，大量时间花在物流塔每次排空槽位时重新规范化整份量子网络。
现由 [quantumLogisticsNetwork.ts](../../src/game/quantumLogisticsNetwork.ts) 提供局部批次：
第一次复制并规范化输入，随后复用该批次自己的返回状态；换入别的网络对象即重新规范化。
批次只覆盖同一个同步上传阶段，不跨出库、设置修改或模拟步骤保留。
原有独立入库 API 继续保持不可变调用语义。

[engine.ts](../../src/game/engine.ts) 在物流缓存转移和量子边界上传的循环内使用该批次。
逐笔的整数、单物品容量、保留库存和余量返回算法保持原样，也没有重新排列物流塔。
[新增测试](../../src/game/quantumInventoryDepositBatch.test.ts) 覆盖容量边界、禁用网络、异常数值、
256 位余额、冻结输入、网络替换、运行统计与反向塔顺序的守恒检查。

## 复现与一致性

输入是只读私有准备态，205,464,026 字节，110,042 个实体、233,300 条运输线；
SHA-256：`6a6aa320dd9d5fd5e5b618b745fc864c2ccb2d96143e0b852d1f270358de9ebf`。
普通模拟保留原库存，关闭副本的时间扭曲与自动保存。旧/新/新/旧/旧/新各独立启动 Chrome，
以 1、10、30 个累计模拟秒推进。测量时不并行构建或测试。

三次旧值为 49.465、49.661、49.073 秒；三次新值为 26.410、26.624、26.407 秒。
六次包含运行字段的完整状态 JSON 均为 205,529,767 个 UTF-16 代码单元，
UTF-8 SHA-256 均为 `932decef7a8a201cfd01ea46cdb96118360f4ce917523283930a892bae3720a5`；
量子网络摘要均为 `f497973e3429e51dbb8a56185fe0233b2b5e3e581157cfdf0e37f12de63212d5`。

另用明确补充行星托盘的材料压力副本对照 8 倍产率复制，两个完整持久化输出摘要均为
`2b56509b5cd28c50e187f1a4c9030bb3fd2b459a9740e57a870c3e51c1613acd`。
该压力场景不代表原存档天然材料充足；这次对照仅证明复制结果没有改变，没有给复制模式计入速度收益。

实际网页使用对应的旧/新生产构建、同一原库存副本、同一视图与设置，分别推进 40.904 和 40.998 个模拟秒。
两边均完成进入 8 倍复制、停止、有效主档读回、实体/运输线数量及暂停状态检查。
单组网页样本的最长普通运行画面间隔为 164.7→323.0 ms，P95 为 7.1→7.2 ms；
因此不宣称 FPS 或所有操作响应改善。正常运行阶段渲染进程旅程峰值约 3.25→3.07 GB，
不足以证明整体峰值内存降低；转换阶段的大内存副本仍需处理。
