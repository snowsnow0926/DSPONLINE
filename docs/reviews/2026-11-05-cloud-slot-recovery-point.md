## 补修

银河手动槽位的冲突“使用云端版本”在已有格式/模式检查后、写新槽位前，读取目标槽位的实际正文，验证它并创建非自动的已校验恢复快照。只在返回已验证快照后继续原有 `saveGameSlotVerified` 和成功同步标记；失败保留候选与原槽位，通过活动冲突框已有 status 显示中英文说明，允许重试。

使用现有存储 API，不改公共兼容存储、格式、fencing、原生所有权或保存算法。私有模块函数只接收槽位/模式，旧档的完整解析状态留在创建快照的函数作用域，不把它保留到后续新槽位写入；不载入旧槽位、不计算离线收益，也不反复串行化再解析旧正文。

本批新增三个公开浏览器场景：正常兼容存储、仅拒快照写入、默认 IndexedDB。实际从存档页读回后端标签，正常路径在导出前便核对恢复点可见，再验证 99 后实际回滚 88；拒写路径验证失败保留 88 / 12，恢复权限后同页重试、再实际回滚并刷新导出。134 类型检查指出误导入了未公开的槽位键函数，已改用现有菜单槽位目录的 key 和现有正文读取 API，没有扩大持久化 API。135 类型及 136 **69 文件 / 466 单元**通过；保留既有 React act 提示，不称零告警。
