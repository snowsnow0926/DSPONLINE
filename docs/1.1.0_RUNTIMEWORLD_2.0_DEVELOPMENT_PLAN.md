## 1. 版本目标

1. 把 Worker 内部的通用 `GameState` 对象运行方式逐步升级为编译式 `RuntimeWorld`，避免每秒重复扫描、查表、创建临时对象和深比较。
2. 保留 `GameState` 作为玩家存档和玩法权威格式；RuntimeWorld 是可丢弃、可重建、不进入云存档的运行时索引。
3. 让生产、传送带、物流和电力共享稳定编号、紧凑数组、拓扑索引、dirty bit 和事件唤醒机制。
4. Worker 只通过变化账本向 UI 发布必要数据；UI 通过 selector store 更新订阅区域，不让一个字段变化触发整棵 `FactoryGame` 重新计算。
5. 用旧引擎作为精确 oracle，按领域逐步替换；任何不一致都能回退，不做一次性大爆炸重写。
6. 两份真实大档的完整运行周期耗时至少下降 40%，正式目标 55%，冲刺目标约 63%。发行说明只能写最终实测值。

## 2. 小白版架构图

```text
玩家旧存档 / 云存档
        │ 仍然是 GameState v47
        ▼
┌──────────────────────────────┐
│ GameState Adapter            │ 读档时编译、保存时导出
└──────────────┬───────────────┘
               ▼
┌─────────────────────────────────────────────────────┐
│ Worker 私有 RuntimeWorld                            │
│ 编号表 + 紧凑数组 + 拓扑索引 + dirty bit + 事件队列 │
└───────┬──────────────┬──────────────┬───────────────┘
        │              │              │
        ▼              ▼              ▼
     传送带        生产/电力       物流/量子
        └──────────────┬──────────────┘
                       ▼
              Change Journal 变化账本
                       ▼
              UI Selector Store
                       ▼
           Canvas 批绘制 + 选中对象 DOM
```

现在像是“每秒询问全工厂谁变化了”；新架构是“规则执行时，变化者自己登记，并告诉下游什么时候需要再次醒来”。

## 3. 为什么不直接换语言或堆 Worker

- 当前 Projection 已把传输量减少约 99.3%～99.6%，继续压缩消息不是主要收益来源。
- 项目已有多 Worker 实验；真实终局档的拆分、复制、校验和合并成本曾使多 Worker 慢于单 Worker。应先改变数据布局，再重新评估并行。
- Rust/WASM 只有在数据已经变成紧凑数组、边界复制受控后才可能有稳定收益；直接把几十 MB JS 对象送进 WASM 仍然要编码和复制。
- 全量替换 React 只能影响显示，不能加速生产、线路、物流和电力规则。
- 本版本禁止为了“看起来底层”而改存档格式、云数据库或玩法数值。

## 4. RuntimeWorld 核心设计

### 4.1 兼容适配层

- `compileRuntimeWorld(state, registry)` 从合法 GameState 构建运行时。
- `exportRuntimeWorld(world, stateShell)` 只在保存、权威检查点或完整重同步边界生成兼容 GameState。
- 实体、线路和站点 ID 映射为稳定整数 slot；删除使用 generation/revision 防止旧引用复活。
- 内容包 fingerprint、活动行星和拓扑 revision 是编译边界；变化时只重建受影响的表。
- RuntimeWorld 构建失败、版本不匹配或完整性检查失败时，保持原始 GameState 并回退旧引擎。

### 4.2 数据布局

- 高频数值字段使用紧凑 `Float64Array`、整数数组或有界 bitset；需要大整数/稀疏扩展的字段保留 sidecar。
- 线路端点、端口、行星范围、源到线路、目标到线路和物品路由使用连续索引，不在热循环创建 Map/数组对。
- 静态字段与每秒变化字段分离；配方、building、planet、端口拓扑不因进度变化而复制。
- 玩家可见库存继续遵守非负安全整数；量子十进制大整数保持既有规范表示，不能因 typed array 截断。
- RuntimeWorld 只存在于模拟 Worker，不改变存档、云同步、排行榜哈希或 React Flow 持久边界。

### 4.3 变化账本

- 每个领域写入明确的 dirty domain、slot、字段掩码和 revision。
- Projection 从 journal 构造，不再在推进前后对活动行星全部记录做 `JSON.stringify`。
- 结构变化、行星切换、内容包切换、命令失败和 revision 缺口触发完整活动行星快照。
- 现有 Projection v2 保留为开发 shadow oracle 和运行时回退；在 1.1.0 稳定观察完成前不得删除。
- 目标：A 档扫描 + 差异平均从约 72 ms 降到 25 ms 以下；B 档从约 37 ms 降到 13 ms 以下。

### 4.4 混合事件调度

- 每秒仍有全局确定性边界，但稳定领域可以跳到下一个生产完成、缺料、输出满、电力变化、物流到达或量子结算事件。
- 先支持能严格证明边界的普通机器、矿脉、稳定线路和静态电网；复杂站点、共享资源、玩家命令和无法证明稳定的链继续走旧扫描路径。
- dirty dependency graph 只唤醒下游受影响岛，不以通用 JSON 深比较判断稳定。
- 同一总时长使用不同切片、事件化路径和旧逐秒路径时，玩法字段必须逐字段一致。

### 4.5 UI 读模型

- Worker 仍是权威状态拥有者；主线程维护只读 view store。
- 壳层、检查器、资源栏、画布、统计和工作区通过 selector 订阅最小切片。
- 活动行星保持精确；非活动行星按现有 Projection 合同在切换时完整同步。
- 画布优先保留现有 React Flow 交互层；线路和非交互卡片逐步进入 Canvas 批绘制，选中、拖动、连线和无障碍节点保留 DOM。
- 大档 raw-cache P0 和 production-preview 帧基线未收口前，不启动全面 WebGL 重写。

### 4.6 保存边界

- 1.1.0 首要目标是运行时，不默认重新启用 durable WAL。
- Change Journal 可用于减少保存投影准备，但正式 envelope、导出和云上传仍生成完整、可验证、向后兼容的 GameState。
- 本地分块/增量快照只能作为独立开发开关实验；必须通过掉电、跨标签页、fencing、CAS、backup、checksum、逐字读回和旧版本导出矩阵后才能进入稳定版。
- 当前真实档自动保存平均约为 A 4.59 秒、B 1.76 秒；1.1.0 最低目标分别不高于 2.75 秒和 1.05 秒，production-preview 最大 Long Task 不高于 100 ms。

## 5. 分阶段实施

### M-1：正式开发前证据门

优先级：P0；只允许只读复现、开发诊断和独立收口已确认的 raw-cache P0，不实现或默认启用 RuntimeWorld，不改变玩法或持久化合同。

- 从最终批准提交冻结干净开发 SHA，记录 Node、Chrome、操作系统、电源模式、CPU、内存和两份只读真实夹具哈希；计划书与基准报告必须进入同一可追踪版本。
- 修复或解释 36.7 MB 档连续两次出现的 raw payload cache 120 秒不释放；dev 与 production-preview 各连续三次归零后，才允许记录正式画布和浏览器内存基线。
- 在 production-preview 补齐 CPU trace、Worker/renderer/GPU 内存、强制 GC 后存活堆、6 秒画布帧和 30 分钟趋势；分别记录载入、运行、玩家命令、检查点、写入峰值和保存后回落。
- 把模拟计时继续拆到可解释覆盖率至少 95%。当前 10 秒短测中，物流分类仍有 A 82.9%、B 79.3% 未归入 dispatch、route advance 或 congestion 子阶段，不能在这个黑盒上直接重写 M4。
- 固定玩家命令突变矩阵：顶层非拓扑设置、单实体字段、单线路字段、配方/电力变化、增删实体/线路，以及 100/1,000 项蓝图批量。每项记录 patch、apply、runtime invalidation/rebuild、Worker 排队、UI 确认和首个 painted frame。
- 固定运行形状矩阵：两份真实档外，再加入中期、生产重、线路重、物流重、完全堵塞、内容包和速通/离线样本；不得只对两份当前大档过拟合。
- 对 1x/4x/11x、1 小时/24 小时/30 天、运行中暂停/保存/编辑记录 pending debt 与最大连续不可让出段，决定是否需要可续跑 session 和安全让出点。
- 输出单独的 M-1 Go/No-Go 记录。第 6.4 节任一证据门未通过时，M0 可以补诊断，但不得开始默认引擎替换或给出新的整局收益承诺。

M-1 已确认、需要写入实现约束的短测事实：

- A 每模拟 1 秒约检查 97,834 条线路，B 约 29,268 条，接近全档线路的两轮检查；两档 `beltStableRoutesSkipped` 都是 0。M2 不能只增加一个名义休眠集合，必须同时降低每次检查成本或建立可证明正确的分阶段活跃前沿。
- 只改一个顶层非拓扑字段或一个实体字段，现有命令路径仍会重建完整 lookup。A 中位约 268～282 ms，B 约 87～100 ms，其中重建占 97%～100%；M1 必须支持按 patch 类型局部失效。
- 生产历史聚合占 10 秒短测总耗时约 A 3.0%、B 1.8%，适合由 Change Journal 增量累计，但不是整局 20% 级主战场。
- 原始只读副本的检查点编解码微基准中，额外完整 `JSON.parse` 占 codec 时间约 39%～40%；它对当前自动保存总时间的直接影响预计仅约 1%～2%，主要价值是压低保存峰值内存。
- 乐观只读行星分区探针中，A 使用 8 Worker 相对协调器串行只快约 24%，B 使用 8 Worker 反而慢约 11%。正式模拟还有确定性 barrier 和固定顺序合并，因此 M4 前继续禁止把“多 Worker”当作默认捷径。

### M0：固化观测与开发护栏

优先级：P0。

- 把 M-1 的一次性探针固化为不进入 GameState、默认关闭的分阶段计时：compile、command patch/apply、domain invalidation、engine domain、journal、projection、postMessage、main merge、React commit、paint、save worker、IDB write。
- 固化冷进程、热进程和连续运行三种可比较模式；同一报告不得混用不同机器、不同浏览器模式或 dev/preview 数字。
- 为两份真实档和合成形状矩阵建立旧引擎 oracle、守恒检查、pending debt、完整周期与局部命令预算；性能回归输出必须标明绝对值和相对值。
- 建立 profiler 自身开销对照。诊断关闭时不得保留 JSON 编码、全量 trace 或每记录计时；开启后必须报告相对未开启基线的扰动。
- M0 未完成前，RuntimeWorld 不得替换默认引擎。

### M1：RuntimeWorld 外壳与 Change Journal

优先级：P1，低玩法风险、架构基础。

- 新增 Worker 私有 RuntimeWorld 类型、稳定 slot、domain revision、dirty bitset 和 GameState adapter。
- 首版仍调用旧领域算法，只替换索引生命周期和 Projection 数据来源。
- 每个请求同时生成 journal Projection 与现有 Projection v2，逐字段比较；不一致自动使用 v2。
- 顶层非拓扑命令不得重建实体、线路、站点或电网 lookup；单记录命令只更新目标 slot 和受影响依赖，增删/换配方/换电网才使明确领域失效。
- 把普通推进改造成可续跑 session，只在已提交的确定性安全边界让出控制；UI 不得观察半步状态，命令 revision 顺序和旧引擎结果不变。
- 生产历史、活动/堵塞计数和其他可加减统计优先从 Change Journal 增量维护；完整扫描保留为低频 oracle。
- 预期整体收益约 6%～13%；本阶段价值主要是为后续领域迁移提供底座，不能以此单独宣布 RuntimeWorld 完成。

### M2：传送带编译运行时

优先级：P1，高确定性风险。

- 迁移端点、端口、路由、预留、拥塞、进度和累计运输热字段。
- 分别记录每模拟秒 route checks、target-capacity checks、活跃 source group、两阶段检查数和单次检查成本；A/B 当前约 97,834/29,268 route checks/s 只作为诊断基线，不允许靠漏算降低。
- 为输入阶段和输出阶段建立独立活跃前沿；源产出、目标腾空、供电、配方、拓扑和量子边界必须精确唤醒。`lastFlow`/拥堵延迟衰减只能存在于 RuntimeWorld sidecar，导出 GameState 时仍需物化为旧引擎等价值。
- 保持线路数组顺序、公平游标、多输入/多输出、尾货和量子/传统物流兼容。
- 用旧 `transferBelts()` 作为 oracle，在 1/4/12/60/600 秒和拓扑命令边界双跑。
- 阶段目标：两档完整周期较基线至少下降 20%；线路领域本身下降至少 35%，无物资差异。

### M3：生产与电力编译运行时

优先级：P1，高确定性风险。

- 迁移进度、输入/输出、增产剂、功率因子、燃料、连续发电和电网分配热字段。
- 建立机器事件时间和依赖唤醒；缺料、堵塞、断电、低电和配方变化立即退出休眠。
- 阶段累计目标：两档完整周期下降至少 35%，目标 45%。

### M4：物流、量子和稳定岛调度

优先级：P1，高风险。

- 迁移站点槽位、调度候选、缓存、路线、拥塞和量子五秒边界。
- M-1 的物流子阶段归因覆盖率必须达到 95% 后再决定迁移顺序；优先处理在两档中都能复现的热点，不按文件长度或函数名称猜测。
- 按行星/生产链建立可证明稳定的事件岛；任何跨岛依赖或玩家命令唤醒相关岛。
- 保留全扫描 fallback，并记录 fallback 原因和比例。
- 阶段累计目标：两档完整周期至少下降 40%；目标 55%；冲刺约 63%。

### M5：UI selector、Canvas 和保存收敛

优先级：P1/P2。

- 从 `FactoryGame` 抽出 simulation lifecycle、persistence lifecycle、runtime view store 和 canvas presentation，保持行为不变。
- 只有实测 React/paint 占比达到 20% 以上时，才扩大 Canvas 批绘制范围。
- 使用 journal 减少重复保存准备；本地分块存储保持实验关闭，除非完整故障恢复门禁通过。
- 检查点实验优先消除可证明冗余的完整对象图和重复解码，不改变 envelope、checksum、逐字读回或 backup/CAS 合同；若规范字节等价无法证明，保留现状。
- production-preview 运行/保存最大 Long Task ≤100 ms，画布 6 秒帧 P95 ≤20 ms。

### M6：默认启用与 1.1.0 候选

优先级：P0 发布门禁。

- 默认切换前完成两份真实档、合成极限档、旧存档、内容包、普通/速通、离线/纯挂机、Web/PWA/Electron/Android 全矩阵。
- 关闭影子双跑的生产开销，但保留可控的旧引擎 fallback 和诊断原因。
- 从干净固定 SHA 生成不可变制品、manifest、SBOM 和 provenance。
- 开发完成只形成 release handoff；没有用户发布授权不得部署。

## 6. 量化验收表

### 6.1 模拟性能

| 指标 | 当前 A | 1.1.0 最低线 | 正式目标 | 冲刺目标 |
| --- | ---: | ---: | ---: | ---: |
| 60 秒精确模拟 | 35.66 s | ≤21.4 s | ≤16.1 s | ≤13.2 s |
| 逐秒 P95 | 816 ms | ≤490 ms | ≤370 ms | ≤305 ms |

| 指标 | 当前 B | 1.1.0 最低线 | 正式目标 | 冲刺目标 |
| --- | ---: | ---: | ---: | ---: |
| 60 秒精确模拟 | 9.52 s | ≤5.7 s | ≤4.3 s | ≤3.6 s |
| 逐秒 P95 | 242 ms | ≤145 ms | ≤110 ms | ≤90 ms |

最低线约等于耗时下降 40%，正式目标约 55%，冲刺目标约 63%。必须在同一机器、独立进程、相同 runtime 和相同只读副本上比较；百分比不能跨设备或跨热/冷启动直接相除。

### 6.2 正确性与兼容

- 相同初始状态、内容注册表和时间，旧引擎与 RuntimeWorld 在 1/4/12/60/600 秒、1 小时、8 小时、24 小时和 30 天逐字段等价。
- `productionHistory` 允许沿用既有切片密度差异规则，但不能反向影响玩法状态。
- 库存、托盘、线路、站点货物、量子库存、矿物、科研、戴森、制造队列和空间站材料无丢失、重复或负数。
- v1～v47 旧档、稀疏档、普通/速通、槽位、备份、快照、导入和云恢复继续可读。
- GameState、envelope、cloud schema、SQLite layout 只有真实持久形状变化时才允许升级；性能实现本身不构成升级理由。

### 6.3 UI、内存和保存

- 活动行星 Projection 响应保持低于 1 MiB，通常不高于完整状态的 2%。
- raw payload cache 在权威读取/提交边界后按合同归零；不得靠刷新、清空 IndexedDB 或删除玩家档解决。
- production-preview 画布帧 P95 ≤20 ms，单个 Long Task ≤100 ms；继续/暂停第二个 painted frame ≤100 ms。
- 30 分钟 Chrome、Android 真机和低配 Windows 测试中，Worker/renderer/GPU 堆无持续无界增长。
- 自动保存保持 Worker active 和玩家暂停意图；A ≤2.75 秒、B ≤1.05 秒，且主线程无 ≥100 ms Long Task。

## 8. 风险、开关与回滚

| 风险 | 防护 |
| --- | --- |
| 少算/多算物资 | 旧引擎 shadow oracle、逐字段比较、整数守恒、领域级 fallback |
| slot 指向已删除实体 | generation/revision 校验；结构命令原子提交 |
| 事件岛漏唤醒 | 依赖 dirty propagation；无法证明时走扫描路径 |
| 内容包定义变化 | registry fingerprint 建立编译边界，迟到响应作废 |
| 内存因双运行时翻倍 | 双跑只限开发/抽样；生产只保留一个权威世界 |
| 保存与运行态不一致 | 保存只接受 Worker 权威检查点；adapter 输出后完整校验和读回 |
| 新引擎故障 | 当前请求回退旧引擎；不迁移或重写玩家存档 |
| 局部命令漏失效 | patch 类型、domain revision 和依赖唤醒同时校验；开发态与完整 rebuild oracle 对照 |
| 安全让出暴露半步状态 | 只在完成确定性提交的 session 边界让出；中间态不递增公开 revision、不发送 Projection |
| profiler 改变被测性能 | 默认关闭；开启/关闭成对测量并报告扰动，禁止在每条记录热循环做字符串编码 |
| 取消重复解码破坏规范字节 | 保留原路径作为 oracle；envelope/checksum/逐字读回任一不一致即回退 |

建议开发开关只存在于开发构建，例如 `VITE_RUNTIMEWORLD_V2=true`；具体命名由实现时确定。默认生产启用必须由 M6 门禁决定，不能因为开关存在就提前切换。

## 9. 明确不在 1.1.0 首轮范围

- 不增加新玩法、配方、科技、平衡或空间站规则。
- 不迁移云数据库，不把 SQLite 换成其他数据库。
- 不直接用 Rust/WASM 重写全引擎。
- 不默认启用 durable WAL，不把 RuntimeWorld 与保存恢复实验绑成一次大切换。
- 不删除旧引擎、Projection v2 或同步兼容路径，直到稳定发布和观察窗口完成。
- 不用通用 JSON 深比较实现生产休眠。
