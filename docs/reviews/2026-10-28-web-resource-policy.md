# 与另一个项目并行时的本机资源约束

2026-10-28 用户要求继续性能循环开发，同时给另一个项目让出本机资源。本要求是持续目标的新约束，不是暂停或完成目标的指令。当前角色 develop，生产香港 Web 1.3.4 与全部存档、自动备份停用设置保持。

在用户忙于另一个项目期间，优先源码分析、审查、小范围编辑和轻量语法检查。本任务启动的小检查使用 Idle 优先级、一个逻辑处理器；小测试最多一个 worker，不与其它检查并发。运行小测试前检查可用物理内存，低于 8 GiB 则延后。该阈值是启动门槛，不是内存硬上限，也不证明无资源争用；只约束本任务进程，不修改另一个项目或 Codex 应用的优先级、配置和进程。

真实终局大档压测、完整 Chromium/单元回归、浏览器/堆剖析和打包等重任务暂不启动，待用户确认电脑空闲或另行指定验证环境再执行。生产不作为性能实验环境。代码可以继续分析和开发，缺少必要回归和正式对照的候选不得列为已验收优化或发布。

切换前的三种供料共十二次精炼原型测试均已结束；`engine.ts` 单次制造缓存原型因跨场景收益不一致，已移出运行并保存完整源码/补丁。当前候选组合是当次规划仓库判空复用和按目标依赖提前筛选量子规划库存；新增边界曾因低于 8 GiB 延后，内存恢复后实际完成 **57 项聚焦检查和应用类型**。尚无正式性能对照或全量资格，不接受为成果。已接受的开发运行仍为 `13e80829361afe0c5a7b30b2aff14819dd19ec3e`。后续继续轻量源码工作，重验证仍按上述约束延后。

开发工作树继续使用 D 盘现有 `web-performance-loop-20261026`。本机限制检查助手在忽略的 `artifacts/web-low-impact-20261028` 保存；不覆盖真实存档或先前冻结证据。
