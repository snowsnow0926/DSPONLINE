## 本轮推进：减少长离线统计历史的重复排序

源码核对发现，普通离线重建每推进一秒都调用已有追加器，追加器每次重新稳定排序全部历史，再执行 1/10/60 秒分桶和保留窗口。记录在上一轮完成后已有顺序，可以在独占的局部重建过程中保留该不变量，省去后续重复排序。

已实现并提交为 `5c619817`：首次未知历史继续走原排序；乱序追加恢复原路径；同时间戳稳定顺序、浮点舍入、加权桶合并、保留窗口、历史终端遥测和所有字段保持一致。取消/拒绝仍不安装局部候选，不放宽长离线或实时资格。

两个独立 release 测试进程共完成 30 对同输入测量，每对完整结果字节相同、源数据不变。600 / 3,600 / 28,800 秒历史重建耗时中位分别缩短 **27.3% / 27.8% / 27.3%**；八小时历史部分为 **665.18 → 483.72 ms**。这是历史重建子步骤的收益，不能当作玩家整个离线等待或 FPS 提升，也不会自动进入已发布网页和安卓。

新增 13,000 次逐步字节对照通过；新测试 Host 的 66 项差分集成通过，公共目录 12/12 完整状态一致。核心串行 1,099 项通过，但全量验证尚未全部通过：一次并发核心进程发生 Windows 堆损坏，原因未明；Host 的两项目录联接测试在创建夹具时被系统拒绝，独立复查仍复现。保留失败证据和原断言，详细复验结果见 [本阶段记录](./reviews/rust-rp1-history-append-2026-09-08.md)。因此本轮已取得局部性能结果，仍不具备发布资格。
