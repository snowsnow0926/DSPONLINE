## 1. 结论

本轮没有把 Windows E18 和 e503 二选一，而是保留各自正确的职责：

- E18 提供紧凑线路/索引、确定性线程池、原生增量存档/WAL、Windows Host、独立性能版身份和启动单写者保护。
- e503 继续作为玩家可见的离线、纯挂机、时间扭曲和建筑制造方案：`3 × 10` 秒精确校准、闭合稳态供需证书、逐恒星系火箭账本、量子库存直供以及“首轮本金/后续净消耗”的递归制造。
- 新增最终联合守恒门，保证普通产量、科研、施工、火箭/结构和逐恒星系统计只能整体提交，不能再次出现“终端增长、原料没有同步扣除”。
- 施工尾段不再借用瞬时供电快照：校准会隔离施工物料变化，但仍把施工负载留在逐电网供电审计中；只有同一电网三个窗口都证明存在可持续可再生余电且中心实际获得供电时，才签发施工工作量。
- 燃料电站只有同时通过本地供料拓扑、完整物料合同、无有限库存寿命和“合同产率不低于全部电站实测燃耗”的闭环，才可为普通产线签发无限供电尾段。整数燃料与余热只允许每台电站小于一件燃料的相位差，不能把预填缓存当成永续来源。
- Rust shadow 核心同步增加守恒证明和施工口径，但原生宏观尾段仍未移植 e503 的生产性证书，因此继续固定 `authorityEligible=false`，不会接管玩家权威。

当前 Windows 计划仍不是“全部完成”。真正 O(active) 的线路反向唤醒、Rust 统一离线/挂机/时间扭曲、renderer 薄化、共享内存、完整事件统计、24 小时多硬件与签名/升级/灰度仍是后续 Gate。

## 2. 本轮实际修复

### 2.1 离线与纯挂机 v10/v6

- `fast-30s-v6-final-conservation-gate`
- `pure-idle-macro-v10-final-conservation-gate`
- `time-warp-rolling-v6-final-conservation-gate`

三个路径共同采用紧凑联合检查点，统计全部持久物料所有权、累计生产、明确奖励/消费、有限资源和戴森终端。纯挂机每段及最终候选都验证；普通离线或首次时间扭曲失败会返回仅安全推进时钟的原检查点，滚动 Worker 候选失败会丢弃整份孤立 authority 并要求重建。

科研尾段不再因为实验室里有一批预填矩阵就无限推进；当前、队列和无限研究所需的每一种矩阵都必须有同一稳态合同能证明的来源。时间扭曲半秒探针改用微秒边界，避免 `0.5 s` 被按 `1 s` 计算后把物料寿命放大两倍。

### 2.2 戴森与施工守恒

- 火箭按恒星系维护生产、发射、结构和小数余数；全局结构必须等于逐恒星系结构之和。
- 太阳帆的发射、在轨、吸附、过期与壳面仍只在能闭合时提交；无账本尾段冻结。
- 建筑制造步骤开始前原子预留输入，旧任务只重建未提交后缀。
- 量子库存直接进入制造中心的材料缓冲，不再强制绕行行星托盘。
- 递归制造采用首轮完整本金和后续净消耗；副产物循环最多探测 8 个稳定相位，失败回到原子单步。
- JavaScript 与 Rust 都只把“聚合所有权 + 已知消费 - 生产 - 奖励”的剩余缺口视为施工转换，并把转换总数限制在 `ΔtotalCrafted`。WIP 退款或舰队库存搬运不会再被误判为制造。
- 施工的量子直供精确回放在每份联合检查点内共享最多 30 个模拟秒；初始校准已经消耗的额度不会再次发放，只有后续真正被采纳的精确检查点才能返还相应额度。普通合同的安全整数和规范十进制增量分别保存余数，长窗口与任意有序分段不会因逐段截断少产。

### 2.3 Windows 原生导入和启动保护

- 主进程选择 v47 JSON；renderer 只传 registry/catalog，不接收本地路径或完整正文。
- 主进程和 Rust Host 统一 256 MiB 输入上限。
- Host 拒绝相对路径、symlink/reparse、非普通文件、空文件、超限文件和打开期间长度变化。
- Rust 流式解析 envelope v2/GameState v47；实体和线路逐条处理，旧 JavaScript UTF-16 FNV checksum 对 pretty JSON、Unicode/代理对、控制转义、`-0`、`1e-7`、`1e20` 和 `1e21` 保持一致。
- 只有 checksum、catalog、完整 CoreState 和 checkpoint 都成功后才发布 generation 并创建 owner-bound `authority:"shadow"` session；发布前故障不留下 session 或可见 slot。
- Host 不可用时只检查固定性能版原生存档根；不能证明租约不存在时阻止普通窗口，避免双写。
- 主进程在把任何原生结果交给 renderer 前，按 24 种明确结果类型执行精确字段白名单、长度/数量/数值范围和关联身份校验；未知字段、嵌套 Host 诊断、路径和异常正文都不能越过受信边界。

## 6. 明确未完成

1. Rust 尚未移植 e503 的生产性稳态证书、科研/火箭长尾和时间扭曲；原生 pure-idle 在一个 session 的 30 秒 exact 后仍冻结物料。
2. WIN-420 只有安全稀疏 mask；没有完整路由状态机、反向依赖和真正 O(active) 队列。
3. 原生投影没有接入玩家 UI，renderer/Worker 仍持有完整 GameState；无共享内存零拷贝。
4. 原生多核只完成本机若干热阶段的确定性分区；没有全领域权威并行、跨 CPU/Windows 版本复核和完整串行比例/全进程树成本，因此 WIN-430 仍是部分完成。
5. 系统领域独立 dirty bit、可取消空闲 compaction、磁盘水位、mmap/LRU 和完整事件统计桶未完成；WIN-410、WIN-460 与 WIN-480 仍是部分完成。
6. 玩家普通导入入口、gzip/旧版迁移适配、真实云上传流水线和大档 renderer 峰值门禁未闭合，WIN-470 仍是部分完成。
7. GPU/Canvas 新权威呈现路径与上下文恢复矩阵未完成；WIN-490 外壳替换按计划保持 No-Go。
8. 没有 Windows 10/11 三档硬件 24 小时、Defender/磁盘满/只读/强杀、覆盖升级/降级、GPU 丢失或 RDP 矩阵。
9. 没有 Authenticode、installer、生产云文件上传、下载页、邀请 Beta 或灰度；本任务不授权部署。

因此本候选可以描述为“E18 性能基础与 e503 聪明结算的安全整合开发版”，不能描述为 Windows 三层计划全部完成、Rust 唯一权威或正式发布版本。
