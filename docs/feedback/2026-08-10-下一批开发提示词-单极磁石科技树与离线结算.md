# DSP极简网络下一批开发交接提示词

> 交接对象：开发 Agent  
> 本文仅包含需求、实现边界、验收标准和测试方案。请先完成分析与测试，再分阶段开发。  
> 明确排除：本批不处理氢气量子仓库问题，也不修改量子物流结算规则。

## 一、总目标与优先级

本批包含三个相互独立的需求：

1. **P0：单极磁石矿脉数量异常与排行榜公平性**
2. **P1：科技树横向布局和滚轮行为重构**
3. **P0：离线结算失败后不能提交零收益结果**

所有改动必须满足：

- 不直接修改正式玩家存档；先使用内存副本、迁移测试档和备份验证。
- 不因修复资源而无条件给所有玩家增加矿脉。
- 不允许离线结算失败后静默推进离线时间并丢失生产收益。
- 不改变普通生产、科技依赖、排行榜统计和量子物流的既有规则。
- 需要保留可回滚路径，并在交接结果中列出修改文件、测试命令和已知风险。

## 二、P0：单极磁石矿脉异常

### 2.1 用户问题

部分终局存档只有一个单极磁石矿脉。单极磁石会影响终局生产能力和排行榜公平性，用户希望确认是否需要补充一个矿脉。

### 2.2 先做根因调查，不要直接全局补矿

请重点检查：

- 星系/行星资源生成表是否允许单极磁石只生成一个矿脉。
- 新档生成、旧版本迁移、蓝图/复制、存档导入是否会漏掉资源实体。
- `resourceMode`、难度和无限资源设置是否影响矿脉数量。
- 资源实体是否存在但被地图视图隐藏、合并或错误归类。
- 云存档导入、版本迁移或校验修复是否可能丢失资源实体。
- 排行榜存档是否能验证矿脉数量、位置、资源剩余量和生成版本。

### 2.3 修复边界

- 未确认异常来源前，不得对全部玩家自动增加矿脉。
- 设计一个只针对已确认受影响存档的人工修复/迁移方案。
- 修复前生成原存档备份和哈希，修复后重新计算校验值。
- 修复日志至少记录：账号/存档标识、原矿脉数量、修复后数量、修复原因、时间和操作人。
- 不得改变玩家已有的矿脉剩余量、生产记录、科技进度或其他建筑。
- 如果涉及速通或排行榜存档，必须单独定义是否保持资格、是否需要重新审核，不能直接覆盖排行榜历史数据。

### 2.4 验收标准

- 能用测试存档复现“单极磁石只有一个”的来源，或明确证明这是合法生成结果。
- 正常新档、旧档迁移、导入导出和云存档恢复的矿脉数量一致。
- 受影响存档修复后只增加缺失的目标矿脉，不产生重复矿脉。
- 存档校验、排行榜读取和生产统计均通过。
- 修复工具具备预览、备份、确认、回滚和审计信息。

## 三、P1：科技树 UI 层级与滚轮行为重构

### 3.1 用户问题

- 科技树第 **6、16、17、21 层**科技节点较多。
- 字号放大到200%后，单层内容高度过大，出现上下滚动。
- 当前鼠标滚轮同时造成上下和左右移动，方向不可预测。
- 用户希望科技树只横向移动，鼠标滚轮直接转换为左右滚动。

### 3.2 实现要求

重点文件可从以下位置开始检查：

- `src/components/TechnologyWorkspace.tsx`
- `src/styles.css`
- `src/hooks/useHorizontalPan.ts`

要求：

1. 科技树主视口固定可用高度，内部层级按列横向排列。
2. 科技树视口默认允许横向滚动，禁止纵向滚动：`overflow-y: hidden`，横向滚动保持可用。
3. 鼠标位于科技树区域时：
   - `wheel.deltaY` 转换为 `scrollLeft` 增量；
   - 已有 `deltaX` 保持横向移动；
   - 阻止该区域的纵向页面滚动，但鼠标移出科技树后不得劫持全局滚轮。
4. 兼容鼠标、触控板、Shift+滚轮、拖动平移和键盘操作。
5. 200%字号下不得通过缩小到不可读字体来规避问题；节点仍需保持阅读性和可点击性。
6. 节点名称、进度、矩阵图标、前置条件、完成状态和点击按钮不得被裁切。
7. 保留“标准/精简”布局切换；如果精简模式需要重新设计，应保持原功能和状态。
8. 移动端列表模式不能被桌面端横向滚轮逻辑破坏，移动端仍可上下滑动列表。
9. 聚焦某个科技时，`scrollIntoView` 应优先横向定位，不能把页面带到不可见的纵向位置。

### 3.3 验收标准

在字号100%、150%、200%分别验证：

- 科技树第6、16、17、21层的全部科技可访问。
- 鼠标滚轮只改变左右位置，不改变科技树纵向位置。
- 浏览器页面本身不会因科技树滚轮而上下跳动。
- 节点没有被底部施工托盘、顶部标题栏或右侧面板遮挡。
- 标准模式和精简模式均可点击研究、暂停、取消和排队。
- Windows鼠标、触控板、手机触摸和横屏平板均能操作。
- 关闭科技树后，主画布和其他页面的滚轮行为不受影响。

## 四、P0：离线结算失败导致零收益

### 4.1 已确认的现象

用户提供的离线结算截图显示：

- 结算方式：保守宏观结算。
- 精确校准：未进入实验。
- 宏观覆盖：3分钟13秒。
- 估计最大误差：100%。
- 算法版本：`fast-30s-v2`。
- 科研投入：0。
- 报告显示没有新增物资、科技或戴森结构。

这说明本次进入了“零校准保守回退”，而不是正常精确结算或合格的近似结算。

### 4.2 当前代码行为与问题

重点文件：

- `src/game/offlineSimulation.worker.ts`
- `src/game/offlineSimulation.ts`
- `src/game/offlineApproximation.ts`
- `src/game/offlineSettlementStrategy.ts`
- `src/components/OfflineReportWorkspace.tsx`

当前 `runConservativeOfflineSettlement` 会复制源状态，只推进：

- `elapsedSeconds`；
- 必要时的速通时钟；
- 可选的科研宏观账本。

它不会执行生产、传送带、物流塔、量子物流、矿机、轨道采集器或戴森工程。因此一旦该结果被直接提交，玩家会消耗离线时间但没有生产收益。

当前 Worker 超时、快速合同失败或低内存策略触发后，可能自动重试零校准保守路径。这个行为需要改为“等待用户选择”，不能静默提交。

### 4.3 目标行为

离线结算必须区分以下状态：

1. **精确结算**：完整执行确定性模拟。
2. **合格近似结算**：经过校准和尾验，误差在规定范围内。
3. **保守预览**：只用于告知用户当前快速路径失败，不得默认提交。
4. **取消/失败**：原存档完全不变，离线时间不被消费。

当快速结算失败、超时、Worker 崩溃或进入零校准保守路径时：

- 保留原始状态、原始 `savedAt` 和原始离线时长。
- 弹出明确提示：本次快速结算失败，尚未提交离线收益。
- 提供按钮：
  - `使用精确结算`（推荐）；
  - `保守跳过本次收益`（二次确认，并明确显示本次不会产生生产收益）；
  - `取消并返回`。
- 用户选择精确结算后，必须从原始状态重新启动 Worker，不能从已推进时间的保守候选继续，避免重复或丢失离线时间。
- 精确结算支持进度、取消和内存风险提示；取消或再次失败时，原存档仍保持不变。
- 只有用户明确确认保守跳过，才允许提交只推进时间的结果。

### 4.4 设置项

建议增加离线结算策略：

- `自动：近似失败后询问`（默认，推荐）；
- `始终精确结算`；
- `近似失败后保守跳过收益`（高级选项，必须明确警告）。

低内存设备仍可推荐保守路径，但不能以推荐策略为理由直接吞掉收益。

### 4.5 离线报告要求

报告需要显示：

- 本次结算是否真正提交收益；
- 结算状态：精确、近似、保守预览、已取消、失败；
- 失败原因：超时、Worker错误、内存风险、校准不稳定、边界验证失败等；
- 原始离线时间和实际提交时间；
- 生产收益、科研收益、戴森收益的明确变化量。

保守结果不能再显示“离线期间网络保持稳定”作为成功提示，应显示类似：

> 快速结算未完成，本次尚未产生离线生产收益。请选择精确结算或取消。

### 4.6 关键验收标准

- 制造一个会触发快速结算失败或超时的测试存档。
- 确认失败后不会改变原存档哈希、`savedAt`、库存、建筑缓存和产量。
- 点击“精确结算”后从原始状态计算，最终离线时间只计入一次。
- 点击“取消”后重新进入游戏，不能出现离线时间被提前消费。
- 明确选择“保守跳过收益”后，报告必须显示收益为0及原因，并要求二次确认。
- 正常近似结算仍保持现有速度和误差校验。
- 速通存档继续强制精确路径，不得进入近似或保守路径。
- Worker错误、浏览器关闭、页面刷新、内存不足和用户取消都不能提交半成品。

## 五、测试计划

### 5.1 单元测试

- 单极磁石资源生成、迁移、导入导出和修复工具测试。
- 矿脉数量修复前后状态哈希和资源剩余量测试。
- 科技树布局状态、滚轮事件转换和焦点定位测试。
- 精确/近似/保守/取消策略选择测试。
- 保守回退不提交源状态、精确重试不重复计算离线时间测试。
- Worker 超时、异常、取消、重试和原档回滚测试。

### 5.2 浏览器测试

- 100%、150%、200%字号。
- 标准/精简科技树布局。
- Windows鼠标、触控板、移动端触摸、横屏平板。
- 大型终局存档和普通小存档。
- 低内存模拟环境和标准设备环境。

至少运行并记录：
