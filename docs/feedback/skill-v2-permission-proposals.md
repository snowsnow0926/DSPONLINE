# Skill v2 权限放宽待批准提案

**状态：未批准，不是生效规则。** 本轮 A 类整理没有把下列项目写入 `AGENTS.md`、主 Skill 或 `references/`。执行器不得自行采用。

用户说“提高自主性”或“整理 Skill”不构成这些权限的明确授权。不建议提出自动发布、自动 push、自动提权、自动读取凭据或自动豁免验收。

## AUTH-01 同一会话从反馈切到本地开发

**待批准变更：** 用户在同一会话明确追加实现请求后，允许从 feedback 角色切换到本地 develop，不要求新开会话。

**现行生效规则：** 直接实现请求可以在对话开始时推断为 develop，且不额外索要反馈交接书。已经开始的只读审阅不得自行升级为改代码。

**必须保留的边界：**

- 不允许 Agent 自行把审阅升级为修改。
- 不允许开发自动进入生产操作、签名、SSH、push 或发布。
- 追加请求必须是用户明确的实现/修复指令，而不是“继续”“看着办”或“提高自主性”。
- 切换后仍受未提交工作保护、数据保护和执行器审批约束。

**未获批准时的行为：** 审阅会话保持只读，产出交接，等待已生效的新角色授权。

## AUTH-02 本地提交 / 分支 / 工作树的默认授权

**待批准变更：** 调整本地 `git commit`、创建任务分支或附加 worktree 的默认授权范围，减少每次询问。

**必须保留的边界：**

- 创建提交不等于允许 push、打标签或打开公开 PR。
- 不能提交其他 Agent 的改动，不能把无关脏工作树一并提交。
- 不增加 reset、clean、filter-repo、rebase --onto 生产历史或强制推送的权限。
- cherry-pick / rebase / merge 进行中时，不得为“干净工作树” abort 他人序列。

**未获批准时的行为：** 无提交权限则不创建提交；提供 HEAD 与本轮 diff。不操作他人进行中的 git 序列。

## AUTH-03 审阅角色的临时复现与诊断产物

**待批准变更：** 若现有规则未明确允许，授权审阅角色在隔离目录运行只读复现、生成诊断截图/日志副本。

**必须保留的边界：**

- 只读源码与会产生文件、网络、启动脚本副作用的命令必须区分。
- 不得写 `src/`、`server/`、`native/`、发布目录或生产状态。
- 不得用生产账号、玩家存档正文或生产 SQLite 做写测试。
- 诊断产物默认不提交；需要入库时单独授权路径。

**未获批准时的行为：** 审阅保持源码/附件只读。需要启动游戏、写文件或联网复现时先停在边界。

## 明确不提案

- 自动发布或自动切换 `current`
- 自动 push / 自动远程 CI
- 自动读取或转录受保护凭据
- 自动豁免验收、删除失败测试或放宽断言
- 把测试环境特例写成生产规则
