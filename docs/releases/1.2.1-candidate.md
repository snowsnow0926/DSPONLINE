# 1.2.1 候选说明

> 状态：开发侧预发布候选，未签名、未部署。

1.2.1 在 1.2.0 的 Windows 私有原生存档和 Rust 影子核心基础上，优化大型存档冷启动、状态摘要、事务候选内存和相同 revision 重复保存，并阻止 Android Gradle 残留进入 Windows 包。

## 候选内容

1. 原生恢复批量读取同一 generation，健康最新代际验证成功后停止。
2. 原生实体/线路记录使用共享不可变表示，事务命令只分配变化记录。
3. 冷启动解析结果复用于索引和线路路由；状态摘要融合扫描并按 revision 缓存。
4. 相同 Worker 权威 revision 的重复检查点复用经过 manifest/物理 chunk 证明的集合页。
5. Windows 打包在 asar 和 unpacked 两侧拒绝 Capacitor Android `build/**` 残留。
6. production-preview 版本测试不再依赖 DEV-only `/src` 路径。

## 兼容与数据保护

- JavaScript 仍是唯一权威；`authorityEligible=false`。
- GameState v47、envelope v2、cloud schema v8、SQLite layout v3 不变。
- 不自动修改、降低、重算或回滚玩家现有戴森球和其他存档数据。
- 原生失败不安装更旧检查点；无法证明连续性时失败关闭。
- Web、Android 与旧 Windows 客户端继续使用兼容 v47 导入、导出和云正文。

## 尚未满足

- 第二层 10,000 次随机故障、真实 Defender/磁盘/升级矩阵。
- 第三层完整 CORE-370、CORE-390、24 小时三硬件 Gate C。
- Windows/Android 正式签名、Android 真机、Windows 覆盖升级与正式灰度。
- 香港/上海生产预检、备份、切换、公网 smoke 和观察期。

详细证据与原始数字见 [1.2.1 Windows 性能开发报告](./1.2.1-windows-performance-development-report-2026-08-27.md)。候选 manifest、SHA256SUMS 和最终 gate JSON 生成后是制品身份的唯一来源。
