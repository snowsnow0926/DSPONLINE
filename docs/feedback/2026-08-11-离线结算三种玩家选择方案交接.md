# 离线结算三种玩家选择方案交接

> Role: feedback
> 日期：2026-08-11
> 状态：产品方案已由用户确认；待 Development Agent 实现和测试
> 边界：本文档不修改玩法代码、玩家存档、云存档、排行榜或生产环境

## 1. 任务信息

- Task ID / title：离线结算由玩家选择快速、精确或放弃收益
- Priority：P1（进入游戏的核心体验，同时涉及离线时间消费和存档保护）
- Source and attachments：2026-08-11 用户与 Feedback Agent 关于 1.0.38 离线结算的功能确认；无新附件
- Reproduction or observed evidence：当前 1.0.38 先自动尝试快速结算，失败后才显示精确重试、二次确认零收益跳过或取消；标准/受限/低内存设备快速预算分别约为 30/60/75 秒，精确重试没有统一总时限
- User-visible acceptance criteria：普通模式玩家可在结算前选择“快速结算”、“精确结算”或“放弃离线收益并进入”；超时、失败、取消或刷新不得自动消费离线时间
- Compatibility and data-preservation constraints：保持 GameState v46、save envelope v2、云 schema v7、SQLite layout v2 和排行榜协议；旧存档无需迁移即可使用
- Target platforms：Web、PWA、Windows、Android；桌面、手机横竖屏和 80%～200% 字号
- Release target and version：下一开发版本，具体 SemVer 待用户指定；不夹入已发布的 1.0.38，不因本文档触发发布
- Known risks / rollback：快速结算仍有近似误差；精确结算在终局大档上可能运行很久；回滚仅恢复旧 UI/策略，不回滚存档、云数据或排行榜数据

## 2. 已确认的产品决定

1. 普通模式检测到待结算离线区间时，由玩家选择结算方式，不再先无提示自动尝试某一路径。
2. 三种选择必须同时可见：快速结算、精确结算、放弃离线收益并进入。
3. 快速结算是推荐选项，目标约 30 秒，从玩家确认到工厂可交互的端到端总时间不得超过 60 秒。
4. 精确结算可运行超过 60 秒，但必须在开始前明示“大型工厂可能需要数分钟或更久”，并在运行中可取消。
5. 放弃离线收益只能由玩家主动发起并二次确认；程序不得因超时、Worker 崩溃、内存不足或校验失败自动选择。
6. 快速或精确结算失败、超时、取消或页面刷新时，必须保留原存档、原 `savedAt` 和完整待结算离线时间。
7. 速通模式为保证公平只允许精确结算，不显示快速估算或放弃后推进计时的入口。

## 3. 选择界面

当存档存在至少 1 秒待结算离线时间时，进入存档前显示结算选择卡。卡片顶部至少显示：

- 存档模式；
- 本次离线时间；
- 存档时间；
- 快速结算的目标和最长等待时间；
- 精确结算可能长时间运行的提示。

推荐文案：

```text
检测到离线 8 小时 32 分钟

[快速结算（推荐）]
使用受校验的估算，目标约 30 秒，最长等待 60 秒

[精确结算]
使用普通模拟规则完整推进，大型工厂可能需要数分钟或更久

[放弃离线收益并进入]
立即进入，本次离线生产、科研和戴森收益均为 0
```

可提供“在此设备上记住我的选择”，但仅允许记住快速或精确结算：

- 偏好只存在当前设备，不进入 GameState、导出文件或云存档；
- 记住后自动开始相应策略，进度界面仍需提供“更改结算方式”；
- “放弃收益”永远不得记住、默认或自动执行。

## 4. 快速结算规则

1. 30 秒是常规目标，60 秒是支持环境中的端到端硬上限，不是仅限 Worker 计算的内部 deadline。
2. 端到端时间从玩家确认“快速结算”开始，到新状态通过序列化、完整性校验、写入、读回且工厂可交互为止。
3. 开发实现必须将解析、Worker 启动与传输、校准、宏观结算、尾验、权威序列化、主存档写入和读回都纳入 60 秒总预算。
4. 当前低内存设备 75 秒预算不符合新规则，必须改为最多 60 秒，不能通过另外一个未计时的保守重试突破上限。
5. 快速结算可放宽数值精度，但仍必须保证：
   - 同一区间只提交一次；
   - 库存、缓存、在途物资和有限矿脉非负；
   - 有限矿脉减少与可追踪矿物产出一致；
   - 输入、输出、副产物、燃料、物流和量子库存不得凭空增减；
   - 结构校验、传输哈希、存档写入和读回成功后才提交。
6. 到达 60 秒时没有得到合法候选，立即终止本次尝试并返回选择卡；不得自动切换精确、自动跳过或写入部分候选。
7. 超时提示必须明确说明“本次未提交，原存档和离线时间保持不变”。

存档本身无效、内存或存储已不足以完成一次可验证写入时，不得伪造“60 秒内成功进入”；应保留原存档和离线区间，显示真实失败原因。

## 5. 精确结算规则

1. 精确结算使用现有普通模拟和 Worker 确定性推进规则，不改配方、产能、运输顺序、资源模式或科研规则。
2. 开始前根据存档分级和已测吞吐显示估计时间；无法可靠估计时显示“预计时间未知”，不显示虚假倒计时。
3. 进度界面显示已推进时间、总离线时间、现实耗时和可用时的动态预计剩余时间。
4. 玩家可取消并返回三种选择卡；取消只丢弃 Worker 内临时副本，不推进 `savedAt`、不消费离线区间。
5. Worker 崩溃、传输校验失败、序列化失败或写入失败均返回选择卡，不自动切换到零收益。

## 6. 放弃离线收益规则

1. 首次点击不立即提交，而是打开二次确认。
2. 二次确认必须显示本次完整离线时长，并明确列出生产、库存、建筑缓存、科研、戴森工程和活动收益均不增加。
3. 确认文案不得使用模糊的“保守结算”，应直接写“收益为 0”和“本次离线时间将被视为已处理”。
4. 确认后只允许走现有时钟推进路径：不修改原有库存、缓存、科研、戴森、产量和建筑数据，不凭空发放补偿物资。
5. 提交必须记录原始离线秒数、实际提交秒数、零收益状态和玩家主动确认，以便离线报告和诊断。
6. 同一区间不得因重复点击、刷新、重进或云恢复再次放弃或再次结算。
7. 速通存档不得调用该路径。

推荐二次确认文案：

```text
确认放弃本次 8 小时 32 分钟的全部离线收益？

确认后，本次生产、科研、戴森和活动收益均为 0，
该离线时间将被视为已处理，之后不能重新领取。

[返回] [确认放弃并进入]
```

## 7. 失败、取消与刷新

| 场景 | 是否写入候选 | 是否消费离线时间 | 后续界面 |
| --- | --- | --- | --- |
| 快速结算成功且验证通过 | 是 | 是 | 离线报告后进入工厂 |
| 快速结算超时或失败 | 否 | 否 | 返回三种选择卡 |
| 精确结算成功且验证通过 | 是 | 是 | 离线报告后进入工厂 |
| 精确结算取消或失败 | 否 | 否 | 返回三种选择卡 |
| 选择界面或计算过程刷新 | 否 | 否 | 下次进入仍显示同一离线区间 |
| 玩家完成二次确认放弃 | 仅写入时钟推进结果 | 是 | 显示零收益报告后进入工厂 |
| 保存、校验或读回失败 | 否 | 否 | 保留原档并显示失败原因 |

## 8. 离线报告

成功后报告首屏显示：

- 原始离线时间；
- 实际提交时间；
- 结算方式：快速估算、精确结算或主动放弃；
- 主要生产、科研、戴森和返回奖励；
- 实际现实耗时；
- 快速结算的“估算结果”标记。

算法版本、校准秒数、边界修正、最大估计误差和失败分类收进“计算详情”，不在首屏压过玩家实际收益。

## 9. 入口与模式一致性

三种选择必须覆盖所有普通模式待结算入口，不得只修主存档“继续游戏”：

1. 普通模式主存档；
2. 普通模式手动槽位；
3. 自动快照和备份恢复；
4. 导入后恢复；
5. 云存档下载、历史恢复和上传前发现待结算离线时间；
6. 纯挂机转入的普通离线尾段。

云上传不得绕过玩家选择、偷偷放弃离线收益，也不得上传未验证的半成品候选。

## 10. 实现所有权建议

最小主要范围：

- `src/components/StartMenu.tsx`：进入前选择卡、进度、失败返回和二次确认；
- `src/game/offlineSettlementStrategy.ts`：策略命名、设备级记忆和旧偏好兼容；
- `src/game/offlineSimulation.ts` 与 `src/game/offlineSimulation.worker.ts`：60 秒端到端预算、取消和候选丢弃；
- `src/game/storage.ts`：成功、取消与主动放弃的离线时间消费边界；
- `src/components/OfflineReportWorkspace.tsx`：报告中的选择方式、耗时和收益状态；
- `src/App.tsx`：仅当纯挂机普通离线尾段需要接入相同决策流程时窄范围修改，避免广泛重构高冲突文件。

策略偏好建议保留旧 localStorage 键的读取迁移，而不是清理玩家设置。旧“自动：失败后询问”可迁移为“每次询问/快速结算”，旧“始终精确”继续为精确；旧“失败后优先跳过”不得迁移为自动放弃，应回到每次询问。

## 11. 必须新增的测试

### 策略与数据保护

1. 普通存档有离线时间时显示三种选择，速通只显示精确结算。
2. 快速结算成功只消费区间一次，报告标记为快速估算。
3. 快速结算在端到端 60 秒到期后取消 Worker，不写候选，不改 `savedAt` 或离线时间。
4. 低内存和粗指针设备不再使用 75 秒预算。
5. 快速结算超时不自动切换精确，不自动跳过。
6. 精确结算取消、Worker 崩溃、过期回应、传输哈希错误、序列化失败和写入失败均保留原档和待结算区间。
7. 选择卡或两种计算中刷新，重新进入仍处理同一区间，不重复收益。
8. 主存档、手动槽、快照、备份、导入、云下载和历史恢复使用相同选择规则。
9. 普通和速通同槽位不串策略、不串存档。
10. 旧存档和缺失新偏好的设备正常打开，不得默认放弃收益。

### 主动放弃

11. 首次点击只打开确认，不修改存档。
12. 二次确认后只推进时钟，生产、库存、缓存、科研、戴森和累计产量不增加。
13. 快速双击、连续确认、刷新、重进和重复云恢复不会重复推进时钟。
14. 放弃偏好不可记住，旧 `skip` 偏好安全迁移为询问。
15. 放弃报告明确显示零收益、原始离线秒数和实际提交秒数。
16. 速通存档无论通过 UI、导入、修改偏好或直接命令调用都无法放弃收益并推进计时。

### 守恒、性能与 UI

17. 快速和精确结算继续覆盖无电、低电、缺料、输出满、传送带堵塞、量子仓库满、有限矿脉和无限资源。
18. 快速结算结果没有负库存、负矿脉、非安全整数或矿脉减少但产物无去向。
19. 使用小、中、终局大档在标准桌面、受限设备和低内存设备分别记录点击到可交互的端到端时间。
20. 快速结算常规目标约 30 秒；支持环境上的任何超过 60 秒都是门禁失败，不得仅报告 Worker 内部耗时。
21. 320×568、390×844、844×390、桌面宽屏及 80%、100%、125%、150%、200% 字号下，三种选择、风险说明、进度、取消和二次确认均可见、可聚焦、可点击且无溢出。
22. 键盘、鼠标和触摸端使用同一语义；高风险放弃按钮不得因 Enter 或背景点击意外提交。
23. 记录内存峰值、Worker 往返、序列化、写入和读回分段耗时；不得通过删缓存、跳生产、清物资或放宽存档完整性来达到 60 秒。

## 12. 开发与发布门禁

本需求修改离线时间消费、Worker 截止和高风险二次确认，Development Agent 必须至少运行：

```powershell
npm run typecheck
npm test
npm run build
npm run test:e2e
git diff --check
```

候选版本必须报告精确通过、失败、跳过和超时数，并用旧存档迁移夹具和至少一份终局大档只读副本完成下列对照：

- 快速成功后的主要收益、有限矿脉、库存、缓存、在途物资、科研和戴森摘要；
- 精确结算取消和重试的存档哈希；
- 放弃前后除时钟与报告外的状态差异；
- 快速超时、Worker 崩溃、传输损坏和写入失败的原档保护。

任何自动消费失败离线区间、默认零收益、快速路径突破 60 秒、速通绕过精确结算、或失败覆盖原档，均为发布阻断项。

## 13. 回滚方案

- UI 和策略选择可独立回滚到 1.0.38 行为，不修改已保存的 GameState。
- 新的设备级偏好必须有安全默认；旧客户端不识别时仍使用现有询问/精确逻辑，不得落到自动放弃。
- 回滚代码不回滚任何玩家存档、云修订或排行榜记录。
- 若候选版本曾由玩家二次确认放弃某个区间，回滚后不得重新发放该区间收益，以避免重复结算。
