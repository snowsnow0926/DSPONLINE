## 实现边界

- [普通尾段](../../native/dsp-native-core/src/pure_idle.rs)：先用现有矿量证明和量子剩余容量判断是否触界。对于已有普通生产证书且不含复合终端/施工尾段的离线请求，触界后从真实 30 秒精确前缀继续 Exact；此前没有执行宏物料写入，因此不会在已外推状态上重复结算。回退最多 8 小时，`ceil(请求秒数) × max(1, 实体数 + 传送带数) ≤ 4,000,000`；超预算返回 unsupported，源状态、revision 不变。
- 若在初始满仓或校准期间就失去普通生产证明，且没有可独立处理的手工/施工尾段，新版明确拒绝。没有把“冻结后 supported”当成已完成结果。未触界的有证产线仍可使用宏尾段；原 `PureIdleMacroV10` 信用、模式及算法标识不变。
- [无出口窗口](../../native/dsp-native-core/src/simulation.rs)：只接受普通生产证书范围内明确无出口写入者的状态。先真实推进至首个窗口以结算已有 amount，之后只对已证明零新增出口的窗口跳算；保留 51 → 621 / 28,821 的相位，校验源时钟及四个计数没有被其他尾段改写。实际出口、未知 legacy 派发等情况不借用此证明。
- 普通宏只接受已证明的整数尾段起点和整数请求，窗口路径不超过 8 小时；分数或未知步长明确拒绝。Exact 回退保留 Exact 自身四位小数的 elapsed，避免再次用浮点加法覆盖为 `600.0043000000001`。小数源回退有完整规范状态回归；一般小数源宏仍待证明。
- 所有修改在私有 candidate 上完成，最终总账证明通过后才安装源状态。独立手工、施工、外贸、科研及戴森等复合尾段不属于本次六例逐秒等价验收范围，不能由本阶段推断其完整资格。

## 日志升级与恢复

[Host 日志路径](../../native/dsp-native-host/src/core_runtime.rs) 为超过 30 秒的原生离线记录使用 `stable-offline-operation-v2` 和 `offlineAlgorithmVersion`；对应有摘要的 durable 读入也支持 `durable-offline-operation-v2`，算法字段参与原始 intent 摘要。新版在重放前同时验证 kind 与当前算法，旧 Host 会拒绝未知 kind，避免升级或降级时悄悄换算法重算。

已完成检查点按既有格式恢复；**旧版尚未进入检查点的长离线实验 WAL，需匹配的旧 Host 读取/导出后再迁移**。新版拒绝该日志时不改写主检查点、WAL 或已有会话。缺少新字段的旧 ≤30 秒日志保持原精确语义兼容；Exact 和 MacroV10 不进入新增门禁。

外部 JS durable 作者只产生原 JS 操作及 approximate 标志，没有遗漏的 `OfflineMacroV1 >30s` 作者；原生离线作者统一经过新增字段的 Host 写入点。测试用的旧无电矿脉不能证明长时生产，Host 的长时提交/冷重开用例已改用有电的量子矿源夹具。

尚保留的宏差异为 `belts` 的累计传输、`productionHistory`、`historyRecordedAt`、`quantumLogisticsNetwork` 的运行边界。没有盲目乘末帧流量或直接挪动历史时间来隐藏这些差异。自动采用仍为 NOT_QUALIFIED，下一阶段应为这些字段建立与逐秒原引擎一致的更新证明，再做复合产线及真实入口验收。

RPC、导出与 JS 推进的计时只作诊断；本轮测试/构建有并行任务，不做性能 A/B 或加速倍率结论。8 小时边界回退需要逐秒工作，正确性提升可能增加计算时间。
