# 全星系空间站扩展设计与开发计划

> Role: feedback
>
> 记录日期：2026-08-14
>
> 设计状态：产品方向与核心规则已由用户逐项确认
>
> 当前代码基线：`GameState v46 / save envelope v2 / cloud schema v7 / SQLite layout v2`
>
> 目标产品版本：待开发排期后确定

本文档是“全星系唯一空间站”扩展的实现级需求与开发交接。它只授权后续开发、测试和必要的规范文档更新，不授权部署、修改生产数据库、上传玩家存档、切换 Web/API、更新下载页或发布原生安装包。

星环建筑不在本轮范围。只有空间站完成、稳定并经过实际玩家验证后，才重新设计星环。

## 0. 一句话定义

空间站是一座属于当前普通工厂存档、跨全部恒星系通用的终局轨道设施：玩家在首次生产宇宙矩阵后建设空间站，通过各行星的轨道货运终端或量子共享库存完成出口合同，获得轨道徽记和空间站声望，购买并布置纯装饰内容；登录玩家还可以把经过脱敏的只读空间站主页公开给其他玩家参观。

它是现有工厂产物的出口、收藏与展示层，不是新的普通工厂，不替代量子物流，不改变已有银河出口项目，也不进入现有排行榜计算。

## 1. 已确认的产品决策

以下规则已经由用户确认，开发阶段不得自行改回旧的“恒星系空间站/太空电梯”方向。

| 编号 | 已确认规则 |
| --- | --- |
| D1 | 每个普通模式存档只有一座全星系空间站；切换恒星系或行星不会切换空间站。 |
| D2 | 桌面入口常驻在行星横向导航条左侧的独立位置；入口从开局可见。 |
| D3 | 首次实际生产至少 1 个宇宙矩阵后，获得建设资格；不是只看科技是否完成。 |
| D4 | 已生产白糖的旧存档获得建设资格，但不免费获得空间站、材料、点数或装饰。 |
| D5 | 建设分为轨道核心、物资出口港、展示舱段三阶段，并按阶段逐步开放功能。 |
| D6 | 首版只消耗现有后期物资，不增加新的普通生产链。 |
| D7 | 每颗已殖民行星最多放置一座“轨道货运终端”，通过真实输入口提交建设或合同物资。 |
| D8 | 量子共享库存支持在空间站界面手动确认交付；首版不得自动抽取库存。 |
| D9 | 每日生成 3 份普通合同和 1 份特殊合同，最多同时接受 3 份，采用低时间压力规则。 |
| D10 | 已交付物资不会因刷新或到期消失；未完成合同结算部分基础奖励，但失去完成奖励。 |
| D11 | 奖励分为可消费的“轨道徽记”和只增不减的“空间站声望”。 |
| D12 | 轨道徽记只购买装饰；声望决定等级、称号、区域和装饰容量。购买装饰不降低等级。 |
| D13 | 空间站不放置采矿、制造、电力、普通仓储或普通传送带设施。 |

| D15 | 装饰购买为永久收藏许可；普通装饰可重复放置，唯一奖杯或纪念物只能放置一个。 |

| D17 | 公开主页默认公开，但与排行榜可见性完全分离；玩家可随时隐藏。 |
| D18 | 访客看到只读空间站画布、站主选择公开的生产数据、成就和展柜，不能进行任何玩法操作。 |
| D19 | 首版社交包括访问、分享、收藏和预设通讯信号；不做自由留言、实时在线状态或社交奖励。 |
| D20 | 空间站建设、出口、点数和装饰支持离线；云账号只用于公开主页、同步和社交。 |
| D21 | 普通存档的本地槽彼此独立；只有普通模式主云存档可以发布账号公开空间站。 |
| D22 | 速通模式不开放空间站。 |
| D23 | 内容包存档可在本地使用空间站并展示布局，但生产数据标记为非官方，不进入官方推荐或验证成就。 |

## 2. 当前实现事实与新方案边界

### 2.1 已确认的当前事实

- `src/game/types.ts` 仍保留 `systemSpaceStations`、`galacticHubNetwork`、Mk.II 和 elevator 等历史字段。
- `src/game/systemSpaceStation.ts` 与 `SystemSpaceStationWorkspace.tsx` 仍保留旧“每个恒星系一座空间站”的实验实现。
- 旧设计文档和旧 Agent 提示词已经明确标记废弃；星图不再公开旧空间站与太空电梯入口。
- v43 若包含有效旧空间站、旧 hub 舰队或 elevator 资产，`migrateGame()` 会拒绝加载，避免把旧资产并入量子共享库存。
- 当前正式终局物流为 `quantumLogisticsNetwork`；量子库存、上传和下载额度属于现有正式玩法。
- 当前“超大型物资出口”和生产统计中的银河出口活动仍是独立现有玩法。
- 当前排行榜公开开关为 `leaderboardVisible`，默认参与，服务端从普通主云存档提取指标；公开接口不需要读取玩家完整存档。

### 2.2 新方案必须遵守的隔离规则

1. 新空间站使用全新命名空间，建议命名为 `orbitalStation`；不得复用 `systemSpaceStations` 或 `galacticHubNetwork`。
2. 不把旧 v43/v44 空间站库存、材料、模块、舰队、翘曲器或装饰迁入新空间站。
3. 不改变 v43 有效实验资产的拒绝规则；历史资产是否救援属于单独任务。
4. 不复用旧 `space_station_construction_launcher` 作为新货运入口；新增稳定 ID `orbital_cargo_terminal`。
5. 不复用 `endgame.constructionActivity`、`galactic_material_exporter` 或四项长期银河出口的交付记录。
6. 不改变量子塔上传/下载带宽、容量、公平游标、运输船、翘曲器或五秒结算公式。
7. 不把轨道徽记、声望、访问量、收藏数或通讯信号加入现有普通/速通排行榜公式。
8. 未解锁或从未进入空间站的旧存档，其模拟热路径不得承担持续空间站扫描成本。

## 3. 产品目标与非目标

### 3.1 目标

- 为白糖之后提供稳定、可持续且不依赖继续堆生产倍率的长期目标。
- 给现有生产网络增加可选择的物资消耗出口。
- 让不同行星的生产分工通过“来源行星合同”获得展示价值。
- 给轨道徽记提供纯装饰消费出口，不形成生产强制或付费数值优势。
- 让空间站成为玩家公开的银河名片，使排行榜从纯数字列表扩展为可访问入口。
- 保持离线可玩、确定性结算、旧存档兼容和跨端一致。

### 3.2 非目标

- 不增加星环、黑雾、战斗、角色移动、多人实时同屏或协作建造。
- 不在空间站内复制采矿、生产、科研、电力、物流塔或普通传送带系统。
- 不让空间站替代量子物流、行星物流或现有银河出口。
- 不用访问量、收藏或通讯信号发放游戏资源。
- 不做自由文本留言、聊天室、访客赠礼、交易或玩家间物资转移。
- 不公开完整云存档、库存、线路、物流槽、精确工厂布局或账号隐私信息。
- 不承诺精确发布时间、正式版本号或上线节点。

## 4. 玩家流程与阶段开放

### 4.1 入口状态

空间站入口从新档开局就显示，状态分为：

1. `locked`：尚未生产宇宙矩阵。按钮可点击，打开只读预告页并显示真实解锁条件。
2. `eligible`：已经生产宇宙矩阵，但尚未开工。打开建设总览和第一阶段需求。
3. `core-building`：轨道核心施工中。
4. `dock-building`：核心完成，独立空间站画布开放，出口港施工中。
5. `showcase-building`：出口合同开放，展示舱施工中。
6. `operational`：建设完成，装饰、公开主页和全部基础功能开放。

解锁判定使用权威累计量 `totalProduced.universe_matrix >= 1`。一旦进入 `eligible` 或更高阶段，即使后续数据整理使当前库存为零，也不能重新锁定。

### 4.2 三阶段功能

| 阶段 | 完成后开放 | 仍未开放 |
| --- | --- | --- |
| 轨道核心 | 独立空间站画布、核心档案、后续施工管理、独立视口 | 合同、商店、公开主页 |
| 物资出口港 | 每日合同、轨道徽记、声望、货运终端合同绑定、量子手动履约 | 自由装饰、公开主页 |
| 展示舱段 | 装饰商店、装饰编辑、展柜、公开主页和访客模式 | 后续高阶区域按声望开放 |

空间站画布开放后，施工中的出口港与展示舱以固定灰模模块显示。功能必须在对应阶段真正完成后才启用，不能只靠 UI 隐藏。

### 4.3 首轮建设成本候选

用户已经确认材料种类方向，以下具体数量是首轮平衡候选，不是不可修改的产品承诺。所有数值必须集中在一个领域目录中，并在白糖初期、中期和超后期三类存档上试玩后再定稿。

| 阶段 | 候选材料 |
| --- | --- |
| 轨道核心 | 钛合金 200,000；框架材料 100,000；处理器 200,000；宇宙矩阵 20,000 |
| 物资出口港 | 量子芯片 100,000；粒子容器 200,000；空间翘曲器 20,000；物流运输船 200 |
| 展示舱段 | 钛化玻璃 300,000；粒子宽带 200,000；塑料 500,000；宇宙矩阵 50,000 |

运输船来自 `portableFleet.logistics_vessel`，由玩家在空间站施工页显式确认交付；其他物资必须来自轨道货运终端或量子共享库存。任何渠道都只能扣除当前阶段尚缺数量。

## 5. 轨道货运终端

### 5.1 内容定义

- 稳定建筑 ID：`orbital_cargo_terminal`。
- 玩家名称：轨道货运终端。
- 解锁：空间站进入 `eligible` 后显示于物流施工分类；白糖前保持隐藏，符合“锁定施工隐藏”规则。
- 每颗已殖民行星最多一座，禁止堆叠；批量放置、蓝图和混合增加均调用同一领域守卫。
- 候选建造成本：钛合金 500、框架材料 200、量子芯片 200、处理器 500。
- 候选功耗：50 MW；断电时不上传，低供电按同一确定性比例降低上传量。
- 四个稳定输入口，支持多物品建设阶段和组合合同。
- 首轮候选总上传能力为 20,000 件/分钟，四口共享；具体值属于平衡数据。

### 5.2 绑定目标

终端一次绑定一个目标：

- 当前空间站建设阶段；
- 一份已接受合同；
- 未绑定。

绑定建设阶段时只接受该阶段尚缺物品；绑定合同时只接受合同尚缺物品。一般合同保留来源行星记录，指定来源合同只接受满足来源条件的终端。

### 5.3 物资守恒

1. 输入口缓存属于普通实体状态，玩家可查看和取回。
2. 固定模拟边界只转移 `min(缓存、目标剩余、终端额度)` 的非负整数。
3. 目标完成后立即停止继续消费；线路尾货和终端多余缓存原地保留。
4. 解除绑定、合同到期、合同放弃或切换目标不能删除缓存。
5. 回收终端时，输入缓存和相关线路货物按既有保护性返还规则进入所在行星托盘；已正式提交的建设/出口物资不退款。
6. 低电、断电、暂停、输出目标失效和离线分段必须保持相同结果。
7. 同一行星第二座终端、非法堆叠、未殖民行星或速通模式必须在领域命令层拒绝，不能只禁用按钮。

## 6. 量子共享库存手动交付

空间站建设页和合同页提供“从量子库存交付”：

1. 玩家选择目标、物品和严格正整数数量。
2. 界面同时显示量子现有量、目标尚缺量和本次实际扣除预览。
3. 玩家确认后，由纯领域命令原子执行；实际扣除为三者最小值。
4. 命令直接修改规范十进制字符串库存，不经过浮点数，不增加或占用量子上传/下载带宽。
5. 首版没有自动履约、后台预留或“自动抽到完成”。
6. 暂停状态允许玩家执行这项显式库存管理操作；操作不推进模拟时间。
7. 量子模式未开启、库存不足、目标已完成或输入非法时返回结构化原因，原状态不变。

这是一条主动的终局便利路径，不改变现有量子塔的生产物流职责。

## 7. 每日出口合同

### 7.1 每日面板

- 每个任务日生成 3 份普通合同和 1 份特殊合同。
- 最多同时接受 3 份。
- 接受、放弃、领取完成奖励和选择展示合同只能在空间站内操作。
- 行星终端检查器可以跳转到对应合同，但不能代替空间站接受新合同。
- 未接受合同随下一个任务日刷新；已接受合同不被当天刷新覆盖。

### 7.2 合同类型

首版模板至少覆盖：

1. 单一物品出口；
2. 多物品组合出口；
3. 戴森工程物资出口；
4. 指定行星来源出口；
5. 多行星协同出口；
6. 量子库存应急出口；
7. 高级矩阵或终局部件特殊合同。

生成器必须根据当前能力过滤模板：未殖民目标行星、未启用量子网络、未解锁物品或无法合法获得的材料不得成为硬要求。普通合同允许终端和量子两种来源；只有明确标注来源的合同才限制渠道。

### 7.3 P1/P2/P3 难度

- P1：单物品或简单组合，基础徽记和声望。
- P2：多物品、指定行星或较高数量，奖励提高。
- P3：多行星、高级物资或特殊渠道，奖励最高。
- 每日特殊合同从当前可完成能力中选择，并提供额外完成奖励，不得要求登录。

物资数量由稳定的“物品权重 + 合同难度 + 模板倍率”数据表计算，不直接按玩家当前产能缩放，避免玩家在刷新前停机来降低需求。所有需求在生成时固化，后续平衡更新不改写已接受合同。

### 7.4 生命周期与部分结算

- 已接受合同保留到生成日后的第 3 个任务日，即提供两个额外日周期的宽限。
- 完成交付后，奖励进入待领取状态；重复点击只能领取一次。
- 到期或主动放弃时，已经交付的物资按完成比例结算基础轨道徽记和基础声望，向下取整。
- 完成奖励、特殊奖励和展示徽章只在 100% 完成时发放。
- 多物品合同按各需求的加权完成比例结算，不能只交付最便宜的一项获得全部基础奖励。
- 到期、放弃和领取均保存稳定结算 ID，刷新、重载、云恢复和离线结束不能重复发奖。

### 7.5 任务日与离线时间

任务刷新使用独立的单调任务时钟，不读取模拟倍率：

- 联网时采用服务器校准的 `Asia/Shanghai` 任务日索引，只允许向前推进。
- 离线时从持久化任务日、已确认墙钟进度和存档种子继续；系统时间倒退不回退任务日。
- 时间扭曲、1x/2x/4x、暂停和画面刷新频率不能提前刷新任务。
- 任务随机性从持久化银河种子、任务日、槽位和规则版本派生，禁止 `Math.random()`。
- 离线无法提供强反作弊保证；因此公开页区分“本地记录”和“主云已同步记录”，但本地玩家仍可完整获得装饰奖励。
- 首版目标是阻止倒退和重复刷新，不承诺在完全离线环境中抵御主动篡改存档或系统时钟。

## 8. 轨道徽记、声望与装饰

### 8.1 双轨经济

- `orbitalMarks`：可消费的规范十进制整数字符串，只用于购买装饰收藏许可。
- `stationReputation`：只增不减的规范十进制整数字符串，用于派生空间站等级、称号、区域和容量。
- 公开主页显示等级和声望，不显示玩家当前可消费徽记余额。
- 购买、摆放、移除、切换主题均不得改变生产、物流、科研、离线收益或排行榜数值。

### 8.2 声望开放内容

等级阈值集中在装饰目录中，初版建议开放：

- 核心甲板；
- 舷窗与观景区；
- 外部货运平台；
- 纪念展柜；
- 更高装饰数量上限；
- 站名牌、背景和灯光主题。

等级只由声望派生，不重复保存可漂移的等级字段。解锁新区域后仍需用现有工业物资完成扩建；轨道徽记不能替代扩建材料。

### 8.3 装饰目录

每个装饰定义至少包含：

- 稳定目录 ID、中文/英文名称、分类和说明；
- 徽记成本；
- 最低声望等级；
- 是否可重复放置；
- 占用边界、合法层级、可用旋转档位；
- 是否允许微动画及减少动态效果时的静态状态；
- 公开展示安全标记。

首版分类建议包括舱壁/地板主题、灯光、货柜、植物、机器人、旗帜、全息投影、窗景、奖杯和纪念碑。

### 8.4 放置规则

- 购买一次后永久加入收藏。
- 普通装饰可重复放置；唯一展品只允许一个活动实例。
- 装饰保存目录 ID、位置、旋转、层级和有限变体，不保存 React Flow Node 对象。
- 移除只删除摆放实例，不删除收藏，不返还或再次扣除徽记。
- 位置限制在已开放区域；越界、重叠固定功能模块、未知目录 ID、非法层级或数量超限必须拒绝。
- 初版硬上限建议为 256 个摆放实例，低等级使用更低软上限；精确上限应经过手机性能验证。
- 不允许任意 HTML、SVG、图片 URL、脚本、CSS、超长文字或自由上传素材。

## 9. 独立空间站画布与导航

### 9.1 状态边界

- 空间站不是 `PlanetId`，不得把 `activePlanetId` 改成虚构行星。
- 新增独立 workspace 和独立 `orbitalStation.viewport`。
- 离开行星进入空间站前保存当前行星视口；返回时恢复原行星和原视口。
- 切换恒星系不改变空间站状态或空间站视口。
- 打开空间站时工厂模拟继续，底层行星画布快照按现有全屏工作区规则冻结。

### 9.2 画布结构

固定功能锚点由状态派生：

- 轨道核心；
- 物资出口港；
- 合同终端；
- 装饰商店；
- 展示舱/展柜；
- 公共通讯信标。

功能锚点不能自由移动、删除或复制。装饰层使用同一平移/缩放坐标系，但不生成普通生产端口和线路。

### 9.3 桌面入口

- 在 `.planet-navigator` 左侧建立独立、稳定宽度的空间站入口容器，位置与用户截图红圈一致。
- 行星导航折叠时空间站入口仍可到达。
- 按钮显示锁定、施工、可领取、正常和私密状态；避免持续闪烁。
- 再次点击当前空间站入口时返回工厂画布，遵循现有工作区交互习惯。

### 9.4 手机入口

- 新版手机壳在行星抽屉或“更多工作区”中提供明确的空间站入口，不能依赖桌面横条缩放。
- 经典手机界面也必须可达。
- 返回键按“装饰详情 → 空间站画布 → 原行星画布”顺序工作。
- 触摸目标不小于 44px；装饰移动、旋转、层级和删除必须有显式编辑模式，避免浏览时误拖。

### 9.5 视觉与可访问性

- 深色、亮色、减少动态效果及 80/100/125/150/200% 字体均需支持。
- 画布底板、功能模块和装饰使用语义主题变量，不新增只适配深色的硬编码区域。
- 装饰选中不能只依赖颜色；提供边框、句柄或文字状态。
- 公共访客模式中的控件仍可键盘导航，所有只读状态有可读标签。

## 10. 公开空间站主页

### 10.1 访问方式

- 公共页面路由：`/station/:publicId`。
- 匿名只读 API：`GET /api/stations/:publicId`。
- 排行榜真实玩家行增加“访问空间站”操作；只在该玩家存在公开快照时显示。
- 自己的空间站提供“预览公开主页”和“复制链接”。
- 直接链接可以不进入本地工厂、不读取本地存档，按需加载公共页面和只读渲染器。

公开 URL 使用服务端生成的稳定不透明 ID，不使用邮箱、用户名或可枚举的内部账号 ID。

### 10.2 页面布局

- 中央：站主真实发布布局的只读空间站画布。
- 侧栏：头像、显示名称、空间站名称、简介、等级、声望、精选展柜、出口成就和最后同步时间。
- 数据页签：默认展开安全聚合数据；站主主动选择的物品级数据单独展示。
- 访客点击功能模块只查看说明，不打开站主合同、库存、商店或编辑操作。

### 10.3 独立隐私开关

新增 `stationVisibility`，首版取值 `public | private`：

- 首次具备发布条件时默认 `public`，但界面必须明确列出将公开的字段并提供预览。
- 它与 `leaderboardVisible` 完全独立。
- 切换为 `private` 后，公开 API立即按不存在处理，排行榜同时移除访问入口；云存档和空间站本体不删除。
- 恢复公开时，从当前普通主云存档重新生成脱敏快照。
- 未登录玩家只有本地空间站，不会被静默上传或获得公共 URL。

### 10.4 默认公开数据

- 账号显示名称和头像；
- 空间站名称、受限长度简介；
- 空间站布局、主题和官方装饰；
- 空间站等级、声望、已完成合同数和出口成就；
- 当前排行榜已经公开的安全聚合指标：累计发电、实际结算吞吐峰值、戴森功率、探索星系数和殖民行星数；
- 快照发布时间和来源主云修订的公开状态，不公开修订号或校验值。

### 10.5 站主可选数据

站主最多选择有限数量的白名单指标或物品作为精选数据，例如：

- 某物品累计生产；
- 某物品经主云相邻修订形成的实际产率；
- 白糖、火箭、太阳帆等终局里程碑；
- 精选成就或最近完成的出口合同。

服务端只接受稳定白名单键，不接受客户端提交任意字段路径。

### 10.6 永不公开的数据

- 完整云存档正文和保存 envelope；
- 精确库存、设备输入输出缓存、物流槽、线路、蓝图和生产区域；
- 行星画布坐标和普通工厂布局；
- 邮箱、登录用户名、会话、IP、设备信息、云修订号、校验和及内部账号 ID；
- 未被站主选择的物品级数据；
- 轨道徽记余额、未完成合同和建设储备。

## 11. 发布快照与服务端验证

### 11.1 快照来源

公开页面不得直接返回云存档。服务端在普通模式主云存档成功上传或恢复后：

1. 使用现有完整性检查读取该主云修订；
2. 从 `orbitalStation` 提取允许公开的布局和档案；
3. 独立验证装饰 ID、数量、坐标、旋转、层级、文本长度和阶段；
4. 使用现有服务端指标函数计算公开生产聚合；
5. 写入版本化 `station-showcase-v1` 快照；
6. 公开接口只读取该快照。

“立即发布”接口只要求服务端从当前主云存档重建快照，不接受客户端直接上传任意公开 JSON。

### 11.2 建议快照形状

```ts
interface PublicStationSnapshotV1 {
  schema: "station-showcase-v1";
  publicId: string;
  owner: { displayName: string; avatar: string };
  profile: { title: string; motto: string };
  station: {
    stage: "operational";
    reputation: string;
    level: number;
    themeId: string;
    placements: PublicStationDecorationPlacement[];
    featuredAchievementIds: string[];
  };
  metrics: Record<PublicStationMetricKey, number | string>;
  metricStatus: "official" | "content-pack-unverified";
  publishedAt: number;
}
```

快照不包含可用于恢复游戏的完整状态，也不能反向写回 `GameState`。

### 11.3 内容包规则

- 含内容包的普通主云存档可以发布官方空间站装饰布局。
- 服务端只保留官方装饰目录中可验证的实例，未知扩展装饰首版不公开但不得从玩家存档删除。
- 生产指标标记 `content-pack-unverified`，不进入官方精选或验证成就。
- 排行榜继续沿用当前内容包排除规则；空间站发布不得绕过它。

## 12. 轻社交边界

首版社交不参与经济：

- 收藏：登录账号可收藏公开空间站；同一账号/空间站幂等，站主不能收藏自己。
- 通讯信号：从固定枚举中选择，例如“壮观”“精密”“工业美学”“喜欢这个布局”；不允许自由文本。
- 分享：复制稳定公开链接。
- 访问：匿名可读，但首版不以精确访客计数奖励或排名。

服务端必须提供频率限制、账号删除清理、私密状态过滤和管理撤下能力。自由留言、聊天、礼物、关注动态和实时在线状态延期，直到举报、屏蔽、审核和未成年人治理形成闭环。

## 13. 建议 GameState 领域模型

下面是实现方向，不要求逐字采用类型名，但语义和隔离边界必须保留。

```ts
interface OrbitalStationState {
  stateVersion: 1;
  status:
    | "locked"
    | "eligible"
    | "core-building"
    | "dock-building"
    | "showcase-building"
    | "operational";
  construction: {
    costRevision: number;
    stageRequirements: StationStageRequirementSnapshot[];
    delivered: Partial<Record<ItemId, DecimalIntegerString>>;
    deliveredFleet: Partial<Record<"logistics_vessel", number>>;
  };
  viewport: CanvasViewport;
  contractBoard: StationContractBoardState;
  economy: {
    orbitalMarks: DecimalIntegerString;
    stationReputation: DecimalIntegerString;
    unlockedDecorationIds: string[];
  };
  layout: {
    themeId: string;
    placements: StationDecorationPlacement[];
    featuredAchievementIds: string[];
  };
  profile: {
    title: string;
    motto: string;
    featuredMetricKeys: PublicStationMetricKey[];
  };
  totals: {
    completedContracts: number;
    exportedByItem: Partial<Record<ItemId, DecimalIntegerString>>;
  };
}
```

轨道货运终端的绑定和四口缓存属于对应 `FactoryEntity`；空间站全局合同、建设、点数和布局属于 `orbitalStation`。不要在两个位置重复保存同一权威数量。

## 14. 版本、迁移与跨端兼容

### 14.1 建议版本变化

- `GameState`：从 v46 升至下一版本；若开发开始前仍为 v46，则使用 v47。
- save envelope：保持 v2。
- 公共快照：独立 `station-showcase-v1`。
- 云 API schema：增加账号隐私字段和空间站接口，建议从 v7 升至 v8。
- SQLite layout：空间站快照和社交数据不应重新塞入大型 `app_state`；建议新增独立表并从 layout v2 升至 v3。
- 内容包格式与蓝图交换格式不因本功能自动升级。

如果开发开始时版本基线已经变化，开发者必须使用“当前版本 + 1”并更新本文引用，禁止创建并行版本号。

### 14.2 v46 → 新版本迁移

- `totalProduced.universe_matrix >= 1` 的普通存档初始化为 `eligible`，其他普通存档为 `locked`。
- 速通存档保持锁定且不显示空间站玩法入口。
- 所有旧存档的空间站材料、徽记、声望、装饰和合同从零开始。
- `systemSpaceStations`、`galacticHubNetwork` 和旧实体字段原样保留，不读取、不删除、不转账。
- v43 有效实验资产继续拒绝，不因新扩展放宽。
- 迁移不改变普通实体、线路、托盘、量子库存、科研、蓝图、在途货物、银河出口或戴森工程。
- 重复迁移必须幂等。

### 14.3 稀疏保存与大数

- 默认空 `orbitalStation` 字段可按现有稀疏投影规则省略，但迁移必须精确补回。
- 所有非零建设投入、合同进度、点数、声望、收藏和摆放必须持久化。
- 物资累计和货币使用规范十进制字符串；JSON 中不得出现 BigInt。
- 任务日、结算 ID、合同种子和阶段成本快照必须进入保存，防止刷新重抽、重复发奖或平衡更新改写进行中项目。

### 14.4 原生与云兼容发布

新状态一旦写出，旧 v46 客户端不能安全读取。必须采用兼容桥接发布：

1. 先发布一个能读取、保存并原样保留新状态版本但功能仍关闭的桥接版本；桥接版读取普通 v46 时不得主动把它改写为新版本，只为后续新状态提供前向读取与原样保留能力；
2. Web、Windows 和 Android 稳定客户端都具备新版本读取能力后，才开放空间站写入；
3. 空间站正式版的直接代码回滚目标必须是该桥接版本，而不是不认识新状态的旧版本；
4. 服务端同时接受旧版和新版普通云档，不能强制所有旧玩家立即迁移；
5. 代码回滚不恢复数据库，空间站新表和快照必须由兼容服务保留。

没有完成跨端桥接前，不得让正式 Web 把主云档升级为旧 Android/Windows 无法读取的版本。

## 15. 模拟、离线与确定性

- 空间站每日刷新使用墙钟域；货运终端上传使用模拟域，两者不能混用。
- 终端在未放置或未绑定时不得进入全实体高成本扫描；运行时索引按建筑 ID 收集活动终端。
- 同一初始状态和相同模拟秒数，实时 Worker、主线程 fallback、离线 Worker和不同分段必须产生相同终端缓存、建设进度和合同进度。
- 时间扭曲只加速工厂向终端送货和终端模拟上传，不加速任务日刷新。
- 暂停停止终端自动上传，但允许量子库存手动交付和装饰编辑。
- 玩家可见库存、建设投入和奖励使用非负整数；低供电不足一个物品的余数保留在缓存或隐藏整数累计器，不能凭空消失。
- 合同生成、到期和结算不依赖 UI 是否打开。
- 公开快照、访问、收藏和通讯信号不进入模拟状态哈希。

## 16. 服务端与持久化建议

### 16.1 独立表

建议 SQLite layout v3 至少增加：

- `station_profiles`：`user_id` 主键、`public_id` 唯一、可见性、来源主云修订、快照 JSON、更新时间；
- `station_favorites`：收藏账号、目标账号、创建时间，复合主键；
- `station_signals`：发送账号、目标账号、固定信号 ID、更新时间，复合唯一约束；
- 如需管理撤下，增加最小化的 `station_moderation` 状态，不复制存档正文。

空间站布局可能包含数百个装饰实例，不应重新放进每次普通写入都会序列化的 `app_state`。新表迁移必须在临时 SQLite、备份副本和重启场景验证。

### 16.2 API 草案

- `GET /api/stations/:publicId`：匿名只读，私密/不存在统一 404；
- `POST /api/station/publish`：从当前普通主云修订重建快照；
- `POST /api/station/visibility`：独立公开开关；
- `GET /api/station/me`：读取自己的发布状态和预览；
- `POST|DELETE /api/stations/:publicId/favorite`：幂等收藏；
- `POST /api/stations/:publicId/signal`：固定枚举信号；
- `GET /api/leaderboard`：可选附带 `stationPublicId`，仅当主页公开且快照存在。

### 16.3 安全要求

- 发布、隐私、收藏和信号要求有效登录；公共读取不携带 token。
- 所有正文有严格字节上限、字段白名单、文本长度、数量、坐标和枚举校验。
- HTML 转义；不允许富文本、外链图片、脚本或用户 SVG。
- 公开读取、收藏、信号和发布分别限流。
- 主云修订冲突、缺少主云档、速通档、存档损坏和私密状态使用稳定错误码。
- 账号注销清理公开快照、收藏、信号和公开 ID；不能删除其他玩家存档。
- 服务端重启后数据保持；生产测试必须使用临时 SQLite，禁止写生产库。

## 18. 分阶段开发计划

### M0：兼容桥接与新状态骨架（P0，高风险）

- 定义新状态版本、迁移、稀疏保存和服务端接受规则。
- 保留旧空间站实验字段和拒绝规则。
- 新功能保持内部关闭；v46 存档继续写 v46，桥接版只对未来新状态提供读取、原样保留和安全停用能力。
- 验证跨端前向读取、云往返和回滚桥接；M1 才在首次启用空间站时提交正式版本迁移。
- 完成 Web/Windows/Android 读取兼容后才能进入正式写入阶段。

完成门槛：旧存档逐字段不变；新状态往返不丢；直接回滚目标能读新状态。

### M1：本地空间站建设与独立画布（P0/P1）

- 桌面/手机入口、白糖解锁、三阶段施工和独立视口。
- 新轨道货运终端、唯一性、输入口、功率和物资守恒。
- 量子库存手动交付。
- 暂不开放合同、装饰和公网主页。

完成门槛：三阶段材料可通过终端/量子/运输船闭环交付；旧玩法结果不变。

### M2：合同与双轨经济（P1）

- 确定性任务日、4 份每日合同、3 个接受槽、宽限和部分结算。
- 轨道徽记、声望、等级派生和结算幂等。
- 能力过滤、来源行星、组合合同和量子合同。

完成门槛：在线、离线、分段、暂停、到期、放弃、重载均不重复扣料或发奖。

### M3：装饰与展示舱（P1）

- 装饰目录、永久收藏、商店、区域解锁、布局编辑和数量上限。
- 同一只读渲染器支持站主预览和未来公共快照。
- 完成桌面、手机、主题、字体和减少动态效果 QA。

完成门槛：删除/移动/重载不丢收藏；装饰不影响模拟哈希或生产数值。

### M4：公开主页与隐私（P1，高风险）

- 云 schema/SQLite layout 迁移、公开快照、独立隐私开关和公共路由。
- 排行榜访问入口、安全聚合指标、内容包标记和账号删除清理。
- 先在本地临时 SQLite 与未激活环境验证；没有发布授权不得部署。

完成门槛：公共 API 无法取得完整存档或隐私字段；私密切换立即生效。

### M5：收藏与预设通讯信号（P2）

- 幂等收藏、固定信号、频率限制和管理撤下。
- 不接入奖励、排名或推荐算法。

完成门槛：刷请求不产生资源；私密/删除/注销后所有关联状态正确清理。

### 发布切片原则

M0 是正式扩展前置兼容版；M1-M3 可以组成第一份离线可玩的空间站扩展；M4 是独立的在线公开主页发布；M5 可继续延期。不得为了赶公开页面而让未通过迁移与守恒测试的本地玩法上线。

## 19. 用户可见验收标准

1. 空间站按钮始终位于指定区域，切换任意恒星系后仍是同一座空间站。
2. 白糖前按钮显示真实条件；首次生产宇宙矩阵后立即获得建设资格。
3. 旧白糖存档进入时只有建设资格，没有免费资产。
4. 三阶段按顺序完成，功能不会提前开放。
5. 每颗殖民行星最多一座轨道货运终端；它可以通过四个真实输入口交付。
6. 目标只扣尚缺数量，多余物资保留且可取回。
7. 量子库存每次交付都有预览和确认，从不自动抽空。
8. 每日面板稳定显示 3 普通 + 1 特殊合同，接受槽最多 3 个。
9. 刷新、到期、放弃和重载不清除已交付记录；部分奖励与完成奖励正确区分。
10. 购买装饰只减少徽记，不减少声望；移除装饰不丢收藏。
11. 从空间站返回时恢复原行星、原平移和缩放。
12. 访客只能查看，不能触发站主库存、合同、商店或布局命令。
13. 玩家可以独立隐藏空间站而继续参加排行榜，或退出排行榜而保留公开空间站。
14. 私密主页和不存在主页在公共 API 上统一不可访问。
15. 速通工厂不出现空间站建设、合同或奖励路径。

## 21. 主要风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 误复用旧 v43 空间站资产 | 新 `orbitalStation` 命名空间；迁移测试证明零复制；保留旧拒绝规则。 |
| 新状态让旧原生客户端无法读取云档 | 先发布跨端兼容桥接版本，正式写入后只回滚到桥接版。 |
| 终端重复扣除或吞掉尾货 | 单一权威缓存、剩余量限幅、保护性退款和分段哈希测试。 |
| 日常任务被改时间重复刷新 | 单调任务日、持久种子、结算 ID、服务器校准；明确离线反作弊边界。 |
| 自动量子交付抽空关键库存 | 首版只允许手动预览和确认，不实现自动履约。 |
| 装饰拖动影响普通画布交互 | 独立 workspace、显式编辑模式、独立视口和触摸捕获测试。 |
| 公共 API 泄露完整存档 | 服务端生成白名单快照，公共接口只读独立表，安全字段测试。 |
| 快照重新放大 app_state 写入 | 使用独立 SQLite 表和 layout 迁移。 |
| 社交刷量影响经济 | 收藏/信号不发奖励、不排名，接口限流和幂等。 |
| 内容包伪造官方成绩 | 只展示官方布局，生产指标标记非官方，不进精选/验证。 |
| 手机装饰过多造成性能下降 | 目录边界、摆放硬上限、LOD、减少动态效果和真机门禁。 |

## 22. 回滚原则

- 功能开关只能停止新交互，不能删除或重建已保存的空间站状态。
- 客户端代码回滚到能够读取并保留新 GameState 的桥接版。
- API 代码回滚到理解新 schema/layout 但可以关闭公共入口的兼容版。
- 数据库回滚不恢复旧备份；新表保留。只有明确的数据灾难恢复授权才考虑数据库恢复，并且先备份当前库。
- 关闭公开主页时返回 404，但不删除站主本地空间站和私有快照。
- 任一阶段失败时保留玩家建设投入、合同进度、点数和装饰；不得以补发、清档或重置量子库存作为修复手段。
