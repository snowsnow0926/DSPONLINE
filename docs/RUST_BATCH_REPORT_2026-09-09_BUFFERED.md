# Rust 阶段报告：后台测试和大存档读取收益

> 后续已测到实际游戏入口完整等待收益：公开大工厂三对中位 21.00→5.85 秒，取消、保存和重开通过。最新结果见[完整等待阶段报告](./RUST_BATCH_REPORT_2026-09-09_UI_WAIT.md)；下文保留此前 Host 测量批次的状态。

本批已经测到明确的 Rust 读取收益，并把测试改为后台执行。公开大工厂中，文件导入这一步从约 **5.18 秒降到 0.40 秒**；离线候选请求从约 **16.97 秒降到 1.76 秒**。每项都有三组新旧对照，结果完整一致。

这些数字衡量的是指定计算步骤。玩家点击“继续游戏”到能操作的总等待，还包括加载、检查、保存和界面恢复，本批尚未完成这个总等待的新旧对照。新 Rust 版本仍在开发，没有发布。

## 测试会不会继续打扰你

后续桌面测试只用已验证的不可见、不可聚焦、静音入口。已有 12 次实际游戏启动和正常关闭记录，覆盖完成结算、取消、保存和重开，没有显示窗口或抢焦点。

本批新核心编译及所有新旧对照均在无窗口进程中执行，使用低优先级、限制并发和独立内存监控。编译约 5 分 48 秒，最低可用内存约 6 GiB；终局档诊断启动前要求至少 6 GiB 空闲，本次观测最低约 5.2 GiB，未触发停止。资源不足时停止本任务的重负载测试，保留失败记录。

## 这次 Rust 实际改进了什么

旧代码解析存档时，可能每取一个字节都请求一次底层文件。新代码先取回一小批数据，再在内存里解析，减少大量重复文件读取。存档内容、完整性检查和损坏数据的拒绝规则保持原有语义。

公开测试工厂包含 **9,107 个实体、20,000 条传送带**。每次都启动独立进程，新旧顺序交替，以下取三次测量的中位数：

| 测量步骤 | 旧核心 | 新核心 | 耗时缩短 |
| --- | --- | --- | --- |
| Rust 文件导入请求 | 5.177 秒 | 0.401 秒 | 92.3% |
| 运行中的存档传给 Rust 后，准备并返回 1 秒离线候选 | 16.967 秒 | 1.758 秒 | 89.6% |
| 同一诊断中，从检查来源到完成候选和 JS 对照 | 18.850 秒 | 3.566 秒 | 81.1% |

最后一项包含诊断程序额外进行的 JS 对照，仍不是实际游戏界面的总等待。原始公开文件约 4.14 MB，加载后实际传输约 10.23 MB；这些结果不能直接按存档大小推算给所有玩家。

两种对照共 12 次运行，均完整状态相同、来源文件不变、正常退出；文件导入的检查点身份及离线来源的临时文件清理也通过。新核心另外运行了 49 项本地接口和后台策略测试，全部通过。

## 终局玩家存档的结果

你提供的终局档原文件约 107.6 MB，包含约 11 万个实体和 23.3 万条传送带。副本经过实际加载后，传给 Rust 的来源约 200.8 MB。

旧次诊断到 300 秒超时；新核心本次约 32 秒结束，并明确返回：**存档开启了时间加速，当前 Rust 宏结算路径不接管这种状态**。进程正常退出，临时数据已清理，原文件完整校验不变。

这次查清了超时后面还有一项准入限制。**该终局样本仍未成功生成结算结果，不能算已修好，也不能把 300 秒和 32 秒算成完成结算的性能对照。** 没有修改玩家存档来绕过限制。
