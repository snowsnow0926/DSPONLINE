# 1.2.7 完整检查点内存补修（未发布）

## 发布前发现

冻结 Web `ae5b555fe3a34c9a3de2ebfa195d6d404341511d` 在生产构建的隔离测试中，Chrome 147 完成 30 分钟、三次自然自动保存、最终主档保存和重载比对。Edge `138.0.3351.109` 同样完成 30 分钟和三次自然自动保存，但最后手动保存后的页面响应超时，未提交新的主档。因此该制品不能按长测通过放行，香港、上海和安卓均未执行本次发布。

只读检查了崩溃文件的结构化元数据：异常码 `0xe0000008`，异常发生在一个已运行约 1,832 秒、消耗约 1,325 秒 CPU 的 Dedicated Worker 线程。该异常码由 Chromium 用于内存耗尽；没有读取或导出崩溃内存、栈正文或玩家数据。[Chromium 异常码定义](https://codereview.chromium.org/2130293003/patch/160001/170001)。这个线程的运行时间和 CPU 用量指向持续模拟 Worker，尚不凭此断言所有客户端保存失败都有相同原因。

原始测试驱动 SHA-256 为 `8b47c3ad4d05fad9da912c9d44d658c95e5f949dbbfed538e4e25d2b2cadcd02`，原始失败报告和私有副本均保留。Playwright 的 crash 事件计数为 0，但独立崩溃元数据已经确认 OOM，不能用缺失的事件推翻实际失败。最后保存阶段超时后，诊断读取也未正常退出；等待超过保存期限后，仅关闭了该测试专用浏览器，使驱动完成失败记录。

对关闭后的 IndexedDB 创建独立副本，在不加载游戏代码、不连接 API 的空白页面只读核对：旧主档仍为测试本地 revision 1，主档、catalog、revision 校验均有效，源数据库文件未变化。新手动主档没有提交。自动保存采用独立分块日志，本次只读检查没有验证该日志的完整恢复，不能将旧主档仍在误述为三次自动保存均失败，也不能宣称已恢复玩家当前浏览器的挂机现场。第一次只读诊断漏算了 checksum 的 `formatVersion` 包装，纠正为既有校验合同后通过；第一次记录保留，不当作存档损坏证据。

## 修改范围

模拟 Worker 的完整 transfer 原先先对整个运行态执行 `JSON.stringify`，再编码 UTF-8，可能在大工厂已占用大量堆时进一步分配完整 JSON 字符串。`serializeSimulationStateForTransfer()` 改为按顶层数组记录逐项调用原生 JSON 编码，并写入 64 KiB 二进制块，最后组成既有 ArrayBuffer。

- 保留运行态全部字段、属性顺序、数组顺序、浮点值及原生 JSON 的省略规则；不采用持久化投影，不删字段、不清缓存、不清日志。
- 使用原生 JSON 编码成员值，保留 `toJSON(key)`、空洞、Unicode 和非法输入行为；带根或数组 `toJSON` 的兼容输入走原生路径。
- Simulation transfer 协议 v1、GameState v47、envelope v2、云接口和数据库版本均不变。
- 需要完整主线程镜像的既有 checkpoint 分支仍保留原流程；本次优化针对只需传递完整字节的路径。

这项修改是对确认的内存峰值风险的补修方案，最终是否解决 Edge 长测后的保存失败，必须由新制品的实际浏览器测试确认。

## 当前验证

- 协议测试 **13/13**：包括 2,000 条记录的完整字节一致、UTF-8 边界、可选扩展字段、原生 `toJSON` 调用次数，以及循环引用/BigInt 拒绝；类型检查通过。
- 公开合成夹具包含 50,000 条记录、100,000 条线路；输出 **126,544,568 B**。新旧编码 SHA-256 同为 `0953c36697463cdfa34d088c20010309f68cc3dbc4e0e932f5c2efdcd3c9fe9f`。
- 同机 Node 24、相同 288 MiB old-space 限制的单轮观察：旧路径 max RSS **792,868 KiB**，新路径 **547,496 KiB**；编码耗时分别 644/701 ms。这是合成输入的内存与时间取舍，不是网页、安卓或真实玩家等待时间的收益百分比。192 MiB 的首次新路径试探仍 OOM，保留失败，不宣称任意堆限制都可保存。
- 完整单元测试 **3,137 通过 / 35 条件跳过 / 0 失败**（394 文件通过、13 条件跳过，346.19 秒），类型检查通过。新 clean runtime、Web/签名 APK、完整浏览器矩阵与 Chrome/Edge 长测均待完成；旧 ae5b 的通过项不能冒充新制品验收。
