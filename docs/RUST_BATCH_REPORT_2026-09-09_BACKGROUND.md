# Rust 阶段报告：后台测试与大存档读取

> 后续已完成公开大工厂三对新旧测量，并取得终局时间加速准入拒绝的明确证据。最新结果见[读取收益阶段报告](./RUST_BATCH_REPORT_2026-09-09_BUFFERED.md)；下文保留本报告最初批次的状态。

本批先解决测试打扰桌面的问题，再继续检查大存档读取的性能改动。后台测试已经实际通过；Rust 读取改动通过了正常优化构建的完整 Rust 测试，但尚未证明终局玩家的完整等待时间缩短。本批没有发布新版本。

## 你现在能直接感受到什么

测试游戏改为在不可见窗口中运行，保持静音，不进入任务栏，不抢鼠标和键盘焦点。已经完成 12 次实际启动和关闭，覆盖结算完成、取消、保存和重开；没有一次显示窗口或抢焦点，存档检查也通过。

后续重型 Rust 编译使用 GitHub 云端。本机只在资源允许时运行后台测试，限制并发、降低优先级；大终局档测试要求至少 6 GiB 可用内存，资源不足时先做其他开发。测试使用独立资料目录。

## Rust 开发这次推进了什么

发现旧读取方式存在一个浪费：解析一份存档时，可能每读取一个字节就向底层文件请求一次。现在增加了 64 KiB 缓冲，相当于一次取回一小批数据，再在内存里逐字解析。

公开回归样本中，约 512 KiB 的文件原来触发 524,708 次底层读取，改后最多 9 次。读取结果和完整性校验相同，损坏数据仍按原规则拒绝。

这说明读取方式改善了，**不等于整个游戏快了五万倍，也不能直接换算成玩家等待缩短多少**。加载后的状态整理、完整校验、模拟计算、保存和界面恢复仍然要花时间。下一步要拿同一个大工厂、同一套流程比较新旧版本。
