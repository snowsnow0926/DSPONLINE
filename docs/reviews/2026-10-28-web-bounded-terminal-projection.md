当前角色 develop；连续性能目标仍 active，香港 Web 优先。本轮不发布、不访问生产，也不修改现有存档或自动备份停用设置。上一轮已接受运行是 `3b7f35061a69`；新候选运行 `27eda406a4d3` 已通过构建和完整单元，Chromium/PWA 与冻结网页交替对照待验，不能沿用上一轮资格。

## 问题和已获得的证据

只读终局夹具包含 110,042 个实体、233,300 条线路。205,464,026 B 的 prepared 文件是展开的运行态测试副本，不是原始约 105 MB 存档增大；输入 SHA-256 为 `6a6aa320dd9d5fd5e5b618b745fc864c2ccb2d96143e0b852d1f270358de9ebf`。

旧冻结网页的两次交接诊断开始约 10.1 秒、停止约 11.6 秒。详细一次停止时，宏观终态生成约 3,660 ms，规范化并分批交付后重新序列化约 1,811 ms（含 gzip 466 ms），独立持久化验证约 1,555 ms，后续写入/读回/旧主档恢复副本等约 2,158 ms，其中旧主档完整检查约 988 ms。后两项有包含关系，不能重复相加；后台结束还有 2 秒空闲退役延迟，不是 CPU 耗时。页面 IDB 的同步调用很短，不能据此推断完整数据库开销。

新 `--handoff-progress=1` 只记录已知 Worker 的标签、数量、计时与成功状态，不保存正文、对象引用、键或身份。详细运行 691 条、未截断；开始/停止均有序列化和成功持久化证明。工具会拒绝缺失、截断或失败的必需阶段。默认关闭，启用时明确 `profiled: true`，只作诊断。

固定 30 秒、8 倍复制的完整终态比较发现，源 envelope 与规范化后重新保存的正文不同：2,171 个实体的 `proliferatorBonusProgress` 以及 `powerGridMetrics` 有变化。规范化后的 UI 保存与真实保存 Worker 完整 SHA-256 相同。因此拒绝直接复用源 envelope 的方案；保留规范化、内容包检查和重新保存。

## 候选实现

宏观 Worker 改为复用已有只读投影范围接口，每次投影最多 512 条实体或线路，立即生成 JSON 片段，不再同时构建第二份完整稀疏实体/线路图。原候选不被修改，投影失败后仍可独立重试。

按投影后的真实字段顺序拼接 JSON 片段，保留原实体/线路顺序和完整 v2 UTF-16 状态校验、UTF-8 编码、载荷 FNV 校验。片段边界的代理对也有处理。普通全量序列化保留原单字符串测量；规范化、权威 proof、独立持久化校验、CAS/lease、主档读回、失败恢复和旧主档恢复副本均不省略。GameState v47、envelope v2、cloud schema v8 和生产设置不改。

这一步处理的是 JS 投影/JSON 的重复对象图。现有 Rust 制造内核不执行这一边界的原序 JSON 投影；本轮没有把它接入此路径，也不宣称 WASM 收益。
