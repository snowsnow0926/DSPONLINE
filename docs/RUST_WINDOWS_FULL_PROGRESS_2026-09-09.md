# 完整 Windows Rust 开发进度｜2026-09-09

**完整 Windows Rust 目标持续进行，尚未完成或发布。** 目标是沿用现有界面，让 Windows 游戏在 Rust 核心上可靠运行，覆盖实时游戏、离线结算、完整玩法和存档恢复。网页、安卓的 Rust 接入另行开发。

## 这一批完成了什么

**补好了 Windows 主进程自己的验签助手。** 可以理解为：游戏准备让 Rust 接管之前，主进程另开一个只读检查程序，重新核对授权文件和发布者；检查失败、超时或文件被改动，就拒绝这份结果。它不运行游戏、不修改存档。

| 本批验证 | 结果 |
| --- | --- |
| Rust 助手输入和错误边界 | 3/3 通过 |
| 主进程边界与真实助手调用 | 10/10 通过，含实际进程 2 项 |
| 严格 Rust 检查、格式、助手构建 | 通过，助手约 650 KiB |
| 云端测试脚本误调用拒绝 | 3/3 通过 |
| 原构建入口与桌面包工具兼容 | 构建通过；32 项通过、1 项因符号链接权限跳过 |

**真实 Windows 签名验证取得通过结果。** 首次云端的测试信任库超时已修复；Rust 模块现已实际通过正确签名接受、错误发布者/篡改拒绝，以及移除信任后拒绝。测试证书和私钥清理正常。新增主进程助手也已接入后续同类云端测试，其签名正例仍待验证。

本批还没有把助手装进完整冻结游戏包，也没有开放 Rust 实时接管。正文范围、资格到期和撤销、独立生产者认证以及实际单写者交接仍需完成。没有新增整段游戏提速结论。见[本批实现与证据](./reviews/rust-windows-main-catalog-helper-2026-09-09.md)；[此前完整 Rust/Native 回归](./reviews/rust-windows-catalog-verifier-2026-09-09.md)单独保留，不算本批重跑。

## 已经证实的性能收益

- 较早的公开大工厂案例：约 9,100 个设备、20,000 条传送带，固定 5 秒离线的完整等待中位从 20.79 秒降至 5.96 秒；那一包的保存、取消和重开已验证。
- 11 万设备、23 万传送带的终局档：固定 9 秒精确 Rust 请求中位从 51.77 秒降至 49.19 秒，少约 2.58 秒；完整导出一致，原档未改。
- 同一终局来源的独立校验：中位从 5.49 秒降至 4.97 秒，少约 0.51 秒；完整摘要一致。
- 菜单进入和恢复保存已接到后台 Worker，旧档备份、保存冲突保护、精确读回和失败重试保留。新增的整段等待收益尚未测定。

这些结果属于不同输入、版本和处理环节，百分比不能相加，也不能外推为整款游戏帧率或内存提升。
