## 2. 发现与修复

### A. 更新清单函数名称与导入不一致 — 成立，已修

- 严重度：高（`desktop:release` 在生成 feed 时会直接崩溃）
- 文件：`desktop/pack.cjs` 原第 77 行
- 复现：`require("./pack.cjs")` 后真正调用 `createDesktopUpdateFeedArguments()`。修复前失败：`ReferenceError: resolvePerformanceEditionOutputDirectory is not defined`
- 证据：`artifacts/1.2.7-closeout-20260907/pack-feed-arguments-red.log`（5 fail / 1 pass）
- 修复：feed 参数改为 `resolveAllowedDesktopEditionOutputDirectory(root, identity, sourceDirectory)`，默认身份是 packer 选中的 edition（`DSP_DESKTOP_EDITION` 缺省为 stable），不再调用未导入符号
- 回归：`desktop/pack.test.cjs` 直接调用生产函数；已接入 `npm run test:native`

仅补旧函数 import 不够：那会把普通版 feed 限制在性能版目录。必须联同 B。

### B. 打包身份、输出目录与工作流收集不一致 — 成立，已修

- 严重度：高（正式 `desktop:release` 写入 `release/`，workflow 只找 `release-performance-edition*`，会 0 候选失败；若误改成性能版默认，会把性能制品送进普通更新源）
- 文件：`desktop/pack.cjs`、`desktop/performance-edition-identity.cjs`、`.github/workflows/desktop-release.yml`、`package.json` 桌面命令
- 规则：edition（stable / performance）与 `releaseChannel`（stable / beta / nightly）分开。普通版身份可以使用 beta 通道。正式工作流默认收集普通版 `release` / `release-fallback`
- 修复：身份模块新增 `listDesktopEditionOutputDirectories`、`resolveAllowedDesktopEditionOutputDirectory`、`selectCompleteDesktopReleaseOutput`；CLI `desktop/select-desktop-release-output.cjs` 供 workflow 调用。路径只接受所选 edition 的标准目录及对应 fallback；0 或 2 份完整结果明确失败；跨 edition、越界、伪造身份拒绝；输出目录 junction 拒绝
- 回归：表驱动 pack 测试 + identity 选择测试 + workflow 源码不再硬编码性能版目录

### C. 文档与命令漂移 — 成立，已修

`docs/NATIVE_APPLICATIONS.md` 与 `desktop/README.md` 曾把 `desktop:pack` / `desktop:release` 写成性能版输出。现已按实际命令更正：

| 命令 | 身份 | 输出 | API/更新地址 | 签名 | feed |
| --- | --- | --- | --- | --- | --- |
| `desktop:pack` | 普通版 | `release/` 或 `release-fallback/` | 不需要 | 允许无签名 | 否 |
| `desktop:performance:pack` | 性能开发版 | `release-performance-edition/` 或 `-fallback` | 默认空 | 允许无签名 | 否 |
| `desktop:dist` | 普通版 | 同上 | 需要 HTTPS | 未签名验收 | 否 |

| `desktop:release` | 普通版 | `release/` 或 `release-fallback/` | 需要 HTTPS | 需要 CSC | 是 |

`desktop:dev` 仍使用性能版身份，避免读稳定版玩家目录。

## 4. 实际引擎状态

| 启动方式 | 实际引擎 | 权威所有者 | 门禁 | 证据 |
| --- | --- | --- | --- | --- |
| 普通/性能 Windows 包 | Electron 加载本地 `dist/`；主进程拉起 Rust Host | **JavaScript 玩家权威** | `authorityEligible=false` | `native/dsp-native-core/src/state.rs` `DomainCoverage::implemented_beta_scope()` 硬编码 `authority_eligible: false`；`native/native-coverage-manifest.json` 同值 |
| Host 会话创建 | `desktop/native-host.cjs` `open()` / `importV47()` | **Rust shadow** | 回执必须 `authority === "shadow"`，否则协议失败 | `desktop/native-host.cjs` |
| 玩家权威接管 | renderer `App.tsx` + main handoff | 未发生 | 交接要求 `coverage.authorityEligible === true`；生产 Host 的 test override 在非 test 构建恒为 false | `src/App.tsx` 约 9488/9539 行；`native/dsp-native-host/src/core_runtime.rs` `player_authority_coverage_eligible()` |
| 保存 | 公开 GameState v47 / envelope v2；原生 WAL 只服务 shadow | JS 公开主档 | 未改格式 | 本轮未改存储路径 |
| UI | 薄 UI 工作区可消费 Rust 投影；工厂主循环仍持有 GameState | JS | thin-UI 边界通过，不等于 Rust 玩家权威 | `verify:native-thin-ui-boundary` |

结论：Rust Host 存在、Rust 测试通过、覆盖清单大量 `true`，**都不能**证明玩家正在由 Rust 权威运行。普通候选的 Rust 玩家模式验收：**BLOCKED**。未把开关改成 true。
