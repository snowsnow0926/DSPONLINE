## 行为和边界

原先 Host 和启动入口一律拒绝超过 30 秒的自动候选，完整状态已匹配的公共产线也不能采用。本批让 Host、main 边界和 renderer 接受两种长离线结果：

- `offline-state-proven`：30 秒真实精确校准，加上已证明完整物理状态、累计传输、量子运行字段、历史和时间窗口的尾段；尾段继续标为宏观时间，不冒充逐秒精确计算。
- `offline-boundary-exact`：从真实校准前缀开始逐秒推进容量或矿量边界，全段时间账本为 Exact；此路径证明正确性，不计宏观性能提升。

新能力标识为 `native-core-offline-complete-candidate-v1`。超过 30 秒仍要求完整 v3 算法标识、精确/宏观时间相加与结算时长相符、完整来源和候选摘要、真实 main 观测时刻、信封校验、revision 及注册表绑定。旧 Host 和未证明的通用 `offline-macro-v1` 不能进入新采用路径。

成本上限沿用已有证明算法：总长不超过 8 小时，30 步探针不超过 60,000 记录步（设备与传送带合计最多 2,000），原始记录不超过 8 MiB、估计运行态不超过 32 MiB。具体证明另有历史样本、时钟和普通产线支持约束；容量/矿量 Exact 尾段还须符合 400 万记录步限制。这不是所有小工厂都支持的承诺，更没有放开终局大工厂长离线。

已确认一个具体的未覆盖瞬态：公共量子容量夹具在 31/32/35 秒请求中，30 步证明探针第 21 步发生物理相位变化，因此不能取得稳态证明，继续拒绝并保留原档；59/60/600 秒则触发已有容量边界 Exact 路径。这是已记录的能力缺口，未减少探针、放宽证明或冒充 Native 成功，后续应补短瞬态结算资格。

Rust 只在私有物理状态和历史证明均成功应用、最终结算证明通过后返回新标签。成本准入本身不授予完整状态资格。未证明或超预算的结果不生成可采用导出，继续由现有 JS 流程处理。

候选准备使用临时状态，不能消费打开的源会话、原生检查点或 WAL；取消和拒绝保留原档。没有改变 GameState v47、存档信封 v2、游戏规则、数值算法版本或实时权威开关。
