## 复现和处理

在一次性本地浏览器中先通过真实界面创建槽位 1 和手动快照，再拒绝 IndexedDB 和 localStorage。两种操作分别显示“本地槽位 1 已保存”和“手动快照已创建”，各新增一条仅存在于内存的记录；恢复权限后这些临时记录消失，原槽位和手动快照保持。主存档前批已修复，这两个独立入口没有经过主存档保护，需单独处理。

`auxiliary-storage-red-44` 首次记录两处误报，但恢复断言错误地将正常新增的自动快照算入手动快照数量；不能作为完整恢复检查。限定手动快照后，冻结 `09a875df1412` 上的 `auxiliary-storage-red-45` 两例都执行到结尾，分别在“不得新建临时记录”和“应明确无法保存”断言失败。反例和诊断均保留。

槽位和手动快照现在先执行原生权威保护，再检查网页存储。仅内存后端直接返回失败，不申请整份模拟检查点、不运行序列化或辅助写入。两者复用主存档已有的中英文失败文案与显式操作进度提示；独立文件导出继续可用，健康存储沿用原路径。公共存储 API 的兼容缓存、写入 fencing、检查点所有权和自动快照策略不改动。
