## 内存保护与后台测试

v6 候选第二次配对在正常重开阶段触发既有 2 GiB 系统空闲内存停止线，最低空闲 1,392,608 KiB，守护退出 -1，运行 198.617 秒。该样本只有部分 live/progress 记录，没有最终完整报告和最终内存文件；系列 JSON 遗留的 `RUNNING` 是旧状态，进程已结束，不能据此继续等待或自动重跑。

随后只改测试工具：在计时完成后的诊断阶段释放已读大对象并显式回收测试脚本内存；采样器每点即时追加 JSONL，异常终止也能保留证据。单一已知 Node PID 自检通过，逐点日志与最终采样数组一致。6 GiB 启动 / 2 GiB 停止线、游戏断言和时限不变。测试工具内存改善不计为产品收益，也没有证明产品内存泄漏的根因。

v7 候选内存自检完整成功，最低空闲 4,220,660 KiB；正式第一对仅入场阶段的游戏进程私有内存采样峰值为基线 3,532,087,296 bytes、候选 3,482,607,616 bytes。单对不足以证明内存稳定降低。v7 失败基线最低空闲 3,560,328 KiB，未触发内存停止线，错误是前述 90 秒 UI 超时。

所有完整成功案例均四次隐藏、不可聚焦、离屏、静音启动与正常关闭，零显示、焦点和系统弹窗。v7 超时案例两次正常关闭；v6 内存停止为守护中止，不写作正常关闭。本轮测试已终止，收口前未发现本轮冻结包游戏进程或采样器残留，不再启动下一轮。
