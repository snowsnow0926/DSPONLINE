# 网页大档：页面保留内存与旧显示回调定位

状态：诊断进展，持续 goal 运行中；尚无本轮新增游戏性能收益，未发布。角色 develop。接续 [供电索引验收](./2026-10-28-web-power-runtime-index.md)，游戏运行代码仍为已验收 `9534dbe9f49d`，本轮只扩展诊断工具。

## 证据改变了优先方向

原计划先测普通模拟 Worker 能否回收。真实大档六阶段采样显示，进入挂机前普通 Worker 的使用堆约 189 MB；显式诊断 GC 后约 183 MB，外部 backing 约 2.5 MB。页面侧同期 GC 后仍约 1,103 MB，普通模拟预热后约 1,066 MB。页面存活数据比普通 Worker 更值得优先处理。暂不新增普通 Worker 退役协议，先处理页面引用；这项决定不改变整体性能目标与后续运输线等优先事项。

这些是 Chrome 的分域 JS 堆诊断，不能和上轮约 4.53 GB 的单渲染进程 OS 峰值相减、叠加或换算收益。GC、分配采样和堆快照会改变时序、垃圾回收与内存；正式性能对照仍要求全部关闭。

## 完整快照与分配栈

同一份 110,042 实体、233,300 线路大档，独立运行了普通堆采样、GC 后堆采样、存活分配栈，以及普通模拟约 40 秒后暂停时的完整主页面快照。独立循环最终都核对主档有效、v47、对象数量、暂停和自动保存/备份偏好。前三类诊断成功；完整快照第一次达到 1 GiB 上限，明确不完整、退出 1，保留并排除。第二次把仅诊断的上限设为 4 GiB，得到完整快照并退出 0。调试文件与玩家存档体积是不同概念。

完整快照含 22,462,743 个 V8 节点和 148,821,210 条边。用流式数字解析、磁盘映射数组分析，未把整份 JSON 展开进内存；节点/边数量、数组长度与边计数总和严格核对。原始堆快照只保存在忽略的私有测试资料目录，不发布、不放进代码库；结构摘要对字符串值脱敏。

结构分析找到 130 个大型 GameState 形状的显示视图，其中有 86 个不同实体列表、128 个不同线路列表。分组为 44 个画布快照、40 个投影结果、42 个流量观察视图、3 个运行发布视图及 1 个加载视图。列表共享许多记录；这是运行时视图数量，不是完整存档副本数量。

排除 weak 边后的引用路径显示，旧投影视图被渲染作用域中的 `A`、`M` 槽位保留。作用域关联 `onDismiss`、`getTarget`、`onLongPress` 等回调，以及其他渲染期间创建/复用的函数；回调和相邻作用域之间又有引用。约 200 MB 的存活分配对应投影行更新，约 100 MB 对应流量显示的线路对象副本；这些采样估计用于定位，不是可直接释放或已节省的内存数。

引用摘要的 BFS 最多六层、每对象前 80 个父引用，不是完整支配树；下一步还需定位回调的源码与最终持有者，区分必要的交互快照和多余的渲染作用域。不能仅凭函数名就删除任何回调或恢复数据。

## 下一轮开发与验收

优先把菜单、长按及节点回调的构建逻辑拆到独立作用域，显式传入所需 ref、ID 和交互 epoch，减少闭包连带保留整份旧画面。保留原有快照、过期操作拒绝、写入权与异步继续检查。通用“所有旧回调自动改读最新状态”会改变部分边界语义，不能作为未经逐项审计的批量替换。

先用同档 GC/引用统计确认旧视图数量及存活堆下降，再以干净提交冻结网页进行独立无采样旧/新/新/旧对照；验证数值全文、交互、启动/停止/失败恢复、完整回归与 PWA。若只是诊断数字下降而正式等待/峰值退步，需修正或撤回。现有存档、配方与材料规则、普通 T0、独立校验读回和自动备份停用设置保持。
