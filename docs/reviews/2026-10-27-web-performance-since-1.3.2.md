# 从 1.3.2 到现在：给玩家看的性能优化报告

本轮开发和本地验收已完成，后续性能循环按你的要求暂停。这份报告讲的是 1.3.2 发布之后的开发成果；这些后续优化尚未由本任务部署香港网页，也未发布 Android/Windows 安装包。

最明显的改善是：进出时间扭曲、停止结算并保存时更少卡顿，保存完成后更快释放内存。100 MB 终局档仍未达到全程丝滑，尤其是进入时的一秒级停顿和约 5 GB 以上的内存峰值。

## 正式 1.3.2 和当前成品直接对照

为这份报告补做了四次同档实测：正式 1.3.2 原包、当前最终包、当前最终包、正式原包。每次新开隔离 Chrome，保留测试副本库存并启用建造，预热普通模拟，8 倍产率复制运行 5 秒，再停止保存并观察 3 秒。测试与开发/其它检查串行，原始存档不写回。旧版两次波动较大，因此给出范围和每组改善幅度。

| 玩家能感觉到的项目 | 正式 1.3.2 两次实测 | 当前成品两次实测 | 对应两组改善 |
| --- | ---: | ---: | ---: |
| 点击进入时间扭曲，到准备完成 | 12.80～19.69 秒 | 11.35～11.60 秒 | 等待少 9.4%～42.4% |
| 点击停止，到结算保存完成 | 18.36～30.33 秒 | 13.44～13.82 秒 | 等待少 24.7%～55.7% |
| 停止过程中最明显的一次画面停顿 | 1.25～2.18 秒 | 0.28～0.30 秒 | 停顿少 76.1%～87.2% |
| 停止后观察 3 秒末尾的内存占用采样 | 3.65～3.83 GB | 2.16～2.56 GB | 这次采样少 29.9%～43.7% |
| 整段操作中的内存峰值 | 5.18～5.52 GB | 5.14～5.42 GB | 范围重叠，尚未证明明显改善 |

“画面停顿”指浏览器两次画面刷新之间的间隔，不是鼠标点击延迟或全游戏帧率。内存末尾采样不是长期常驻占用。这里只有两组、本机和这份大档，不能把范围变成每台设备都固定提速的承诺；[四次逐项记录](./2026-10-27-web-performance-since-1.3.2-evidence.json) 保留了每次值和完整证据哈希。

## 1.3.2 之后完成的九个开发阶段

下面每行数字来自该阶段自己的旧版/新版对照，用来解释做了什么，不能把百分比相加。上面的表才是本次正式 1.3.2 到当前成品的直接比较。

| 阶段 | 用小白能懂的话说 | 当时实测的提升 |
| --- | --- | --- |
| 1. 时间扭曲供电准备 | 检查供电时，不再顺便建立一整套用不到的运输线查询表 | 供电准备 1.173→0.421 秒，少 **64.1%**；仅这个准备步骤 |
| 2. 停止结算流程 | 提前关闭不再需要的后台，省掉一次旧检查点，继续完整校验存档 | 停止保存 17.277→13.492 秒，少 **21.9%** |
| 3. 取消、重试和恢复 | 修复取消后迟到的结果仍可能保存、日志失败后重复写主档，以及放弃后不能重新开始的问题 | **3 项既有问题修复**；不是用少结算材料换速度 |
| 4. 大档分段解析 | 大档解析过程中分段让出界面，减少一直卡住的时间 | 整页退出最长间隔 1.126→0.477 秒，少 **57.6%** |
| 5. 终态数据分批交接 | 不再一次性把整份大对象塞给保存后台，分小批发送并逐批确认 | 整页退出最长间隔 491.55→304.10 毫秒，少 **38.1%** |
| 6. 解析和保存共用后台 | 同一份数据少来回搬、少重复解析 | 退出时超过 100 毫秒的间隔 **4 次→2 次**；长任务耗时少 **35.3%** |
| 7. 恢复画布缓存 | 复用没变的连线几何和制造显示查询，减少回到工厂后的重复计算 | 最长退出间隔 339.45→290.15 毫秒，少 **14.5%** |
| 8. 保存后台空闲回收 | 大档写完、读回核对完成且空闲 2 秒后回收后台；下次保存再建立 | 该阶段退出后的内存采样 3.425→2.683 GB，少 **21.7%** |
| 9. 启动检查点分批交接 | 进入纯挂机也分批交接；防止重复启动、参数被改和旧回包在页面恢复后复活 | 本轮相邻版本进入长任务少 **20.2%**；进入等待 11.120→10.736 秒，少 **3.5%** |

阶段原始报告：[1 供电](./2026-10-27-web-power-snapshot.md)、[2 退出](./2026-10-27-web-stop-transfer.md)、[3 恢复](./2026-10-27-durable-idle-recovery-findings.md)、[4 解析](./2026-10-27-web-cooperative-decode.md)、[5 分批](./2026-10-27-web-state-chunks.md)、[6 共用后台](./2026-10-27-web-canonical-owner.md)、[7 画布](./2026-10-27-web-resume-caches.md)、[8 回收](./2026-10-27-web-persistence-retirement.md)、[9 启动](./2026-10-27-web-start-checkpoint.md)。

1.3.2 本身已经包含七项网页优化：建造库存依赖与目录复用、保存投影复用、保存回包分段、手动存档/快照检查点复用、校验传输合并、显式主档交给后台验证，以及量子入库批处理。它们在 [1.3.2 发布记录](../releases/1.3.2.md) 中已有，属于这次对照的起点，不重复算作之后的新增成果。

## 你关心的三个功能，现在到什么程度

**离线结算／停止挂机结算：** 结算结果处理、保存和恢复通道少了很多卡顿，取消/重试更可靠。传统离线推进、超长时间结算和低内存设备的所有情况还没有完整验收，不能说全部已经丝滑。

**建筑制造巨构：** 1.3.2 已有的递归取料、高级原料和量子配送规则保持。这次后续开发主要减少进出时间扭曲、保存和界面计算对制造的拖累，没有更改配方、材料消耗或已有建造加速规则，也没有新增“长时间制造吞吐普遍翻倍”的证据。

**两种时间扭曲：** 共用的供电、启动、停止、保存与恢复路径得到优化。产率复制是本轮真实终局大档的主要实测场景；守恒模式的大档长期运行仍未达到可以全面保证顺滑的程度。可选恢复模式仍默认关闭，其故障回归通过不等于真实大档资格通过。

## 没有纳入成品的尝试，以及剩余问题

试过后撤回的有：完整保存内容对不上的直接转交方案、局部供电更快但整页收益不足的共享方案，以及跳过普通同步后出现无响应的方案。它们没有进入本轮成品，也没有算入最终提升。Rust/WASM 的已有网页适配曾完成 285 场景差分，但 JSON 转换和传输抵消收益；本轮没有把网页切换为 Rust 核心。

当前还存在：进入阶段约 1.2～1.3 秒的最长间隔、停止保存约 13～14 秒等待，以及约 5 GB 以上的旅程内存峰值。当前两组峰值范围与旧版重叠；保存后的占用减少，不能解释为峰值内存问题或所有内存溢出都已解决。长期制造/量子配送吞吐、守恒大档、长时间离线和低内存手机仍需后续验证；本轮结束后已暂停，不继续启动这些工作。

## 存档、验证与交付

实际保存体约 **105.55 MiB**。此前的 **205 MB** 是展开并补齐运行字段、预热后的 JSON 测试副本，原始玩家存档没有翻倍。原始只读样本为 107,637,967 字节，完整哈希未变；测试原件、玩家数据、存档格式、材料规则及自动备份停用设置保持。

当前完整逻辑测试 **3,684 通过 / 38 条件跳过**；完整网页测试 **508 / 34**；可选恢复组合 **21 / 19**；启动 10 场景连续两遍 **20 / 0**；最终离线更新和重开 **1 / 0**，均 0 失败。相比正式 1.3.2 发布记录的 3,562 项逻辑通过和 484 项网页通过，当前通过用例净增加 122 项和 24 项。服务端、完整原生包及实体低内存设备不是本轮验收范围。
