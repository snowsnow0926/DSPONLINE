# Rust 阶段报告：大工厂真正进入游戏的等待缩短

这批已经测到玩家实际操作流程的收益：在一个包含 **9,107 个实体、20,000 条传送带**的公开测试工厂里，结算 5 秒离线进度，从点击“继续游戏”到能打开设置，等待中位从 **21.00 秒降到 5.85 秒，缩短约 72.1%**。

这次走完了实际游戏界面的结算和保存流程。三组新旧对照中，工厂状态和结算秒数完全相同，完整结算结果也相同。

| 同一工厂的三组对照 | 旧包 | 新包 |
| --- | --- | --- |
| 第一组 | 21.33 秒 | 5.99 秒 |
| 第二组 | 21.00 秒 | 5.85 秒 |
| 第三组 | 20.76 秒 | 5.71 秒 |

每次只是刷新存档外层的保存时间来触发真实 5 秒离线，游戏状态相同，游戏时钟没有替换。计时包含自动点击结算确认和打开设置，不包含人看报告时的停顿。

## 存档和取消是否可靠

三组对照的六次运行都核对了完整游戏状态、实际写入的存档、暂停保存、关闭后重开，以及第二次重开。

另外完成了两种检查：

- Rust 已经算好时点击取消：原存档字节和保存时间不变，两次重开正常。
- 先在游戏里实际运行并保存，再退出重进：这份自然生成的存档也能由 Rust 完成结算，保存和重开一致。

这八次流程验证共启动并正常关闭游戏 **32 次**，全部隐藏、静音，没有抢焦点或显示弹窗。新开发包已冻结并校验，仍未发布。

## 这不代表哪些内容已经完成

72.1% 是这个公开大工厂、短离线场景、同一后台显示方式的实测值。它不代表所有终局存档、几小时离线、整个游戏帧率或手机性能都提高了相同比例。

你提供的原始终局档开启了时间加速，当前 Rust 宏结算入口仍拒绝接管；此前已确认原档未改变，该样本尚未结算成功。网页、安卓的 Rust 接入，超过 30 秒的自动 Rust 离线结算，以及实时模拟接管也还没有开放。

云端新一轮 Rust 和 Native 检查已通过，完整游戏单元还在运行。之前两项 JS 计时失败、历史堆异常的根因和时间加速来源兼容仍需继续处理。本批可以确认“普通大工厂的短离线入口已经有实际收益”，还不能宣布整个 Rust 迁移或发布验收完成。
