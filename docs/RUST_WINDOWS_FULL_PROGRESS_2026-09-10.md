## 本批已经确认的进展

最新 `1dfbb57f` Windows 开发包已重新构建并冻结，76 项制品、79 个文件校验一致，包含此前的保存和输入修复。Rust 界面编辑库存上限时，正常模拟刷新会保留正在输入的数字，Escape 取消不会误提交；对应修复已有专项和真实浏览器证据。

约 108 MB、11 万设备和 23 万条带的终局存档，**取消结算流程在新包中完整通过**：Rust 精确计算 10 秒后的完整状态与原 JavaScript 规则一致；取消后主存档没变，退出后两次重开仍保持原档。四次游戏启动均隐藏静音，全部正常关闭。

**成功结算后的完整进入、保存与重进还未过关。** 一轮 9 秒结算进入设置约需 90.5 秒，随后诊断工具的整档传输失败；另一轮 14 秒结算没有在原 90 秒门槛内进入可操作工厂。不同轮的离线秒数和负载不同，不能拿它们直接比较提速。

大存档取证工具已改为分片传输，完整读取、总大小和 SHA-256 校验通过。这个改动解决了当前诊断路径的传输问题，不是新的玩家存档格式，也不能替代游戏保存验收。

## 正在开发的性能改动

Rust 检查完整状态时会产生大量细碎的哈希输入。这一批增加固定 1 KiB 缓冲来合并这些输入，保留原来的全部字段、顺序和校验算法。特殊字符、大记录和完整摘要专项已通过；公开合成场景的校验耗时减少约 **14.9%**。完整 Rust 核心和实际 Host 检查正在继续，随后测终局档，**这个局部数字还不是游戏提速结论**。

已有的历史收益仍成立于各自冻结候选：公开大工厂的短离线完整等待曾从约 20.8 秒降到约 6.0 秒。这个结果不能推广成所有终局存档、实时游戏或最新候选都提速同样比例。
