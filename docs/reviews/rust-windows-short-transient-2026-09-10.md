# Windows Rust 短瞬态精确候选｜2026-09-10

Role: develop。完整 Windows Rust Goal 保持 active。本记录属于开发候选，尚未发布。

## 问题与改动

上一批公共量子容量产线在 31、32、35 秒请求上失败：实际请求只比 30 秒校准多一点，但完整稳态证明会再检查 30 秒；检查窗口内触及容量边界，无法证明整个窗口稳态。旧实现正确地拒绝采用，玩家仍需要原结算路径。

新增只供启动临时候选调用的核心入口。先执行未改动的宏观算法；若它拒绝，且请求严格为 31–60 整秒、墙钟与模拟时间相等、普通未暂停模式、加速关闭且无未结算预算，并通过原 2,000 记录/内存预算，再从未改变的源状态进行真实 Rust Exact 推进。完整物资结算证明通过后才提交这个候选；失败不改变源会话、检查点、WAL 或玩家原档。

算法使用独立 `native-offline-transient-exact-v1` 和 `offline-transient-exact`，精确秒数等于全部请求秒数、近似秒数为零。Host 声明独立能力，main 和 renderer 同时检查算法、范围、完整时间账以及原有源/候选摘要、版本、时钟和传输校验。60 秒是此批独立成本上限，不能用这个能力放行更长的未证明瞬态。

旧 `CoreState::advance`、OfflineMacroV1 v3 算法身份、持久操作和 WAL 回放分发保持原语义。宏观失败原因的文字不用于授权；真正的 Exact 执行和结算证明才提供候选依据。该功能增加 Rust 能处理的场景，不是宏观算法的性能加速证据。
