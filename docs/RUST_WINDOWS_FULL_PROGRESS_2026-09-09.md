# 完整 Windows Rust 开发进度｜2026-09-09

**完整 Windows Rust 目标持续进行，尚未完成或发布。** 目标是沿用现有界面，让 Windows 游戏在 Rust 核心上可靠运行，覆盖实时游戏、离线结算、完整玩法和存档恢复。网页、安卓的 Rust 接入另行开发。

## 这一批完成了什么

**正在补真实签名验证。** 已编写云端专用流程，用临时测试证书验证正确签名、错误发布者、正文和签名包被改动的情况，再检查移除信任后的拒绝。它在独立云端 Windows 测试机执行，本机只做编译和误调用拒绝检查；实际云端结果仍待取得，不计为开放实时游戏。见[执行进度](./reviews/rust-windows-signed-catalog-ci-2026-09-09.md)。

**完成了 Rust 接管前的签名验证初版。** 它核对资格正文是否属于签名包及获准发布者，并锁住文件防止验证期间被替换。已用真实 Windows 接口验证伪造文件、目录跳转、硬链接和文件超限等拒绝路径。

这一模块尚未开放实时接管。真实签名正例、主进程独立验证、资格到期和撤销机制仍需完成。本批没有新增整段游戏提速结论。

**补齐了后台测试设置。** 目录联接辅助命令显式隐藏、低优先级运行；Electron 通信测试使用自己的临时目录，静音、不可聚焦、60 帧离屏运行。实际完成 30 MiB 双向传输时，显示事件和焦点事件都是 0；没有打开游戏或读取玩家资料。

## 已经证实的性能收益

- 较早的公开大工厂案例：约 9,100 个设备、20,000 条传送带，固定 5 秒离线的完整等待中位从 20.79 秒降至 5.96 秒；那一包的保存、取消和重开已验证。
- 11 万设备、23 万传送带的终局档：固定 9 秒精确 Rust 请求中位从 51.77 秒降至 49.19 秒，少约 2.58 秒；完整导出一致，原档未改。
- 同一终局来源的独立校验：中位从 5.49 秒降至 4.97 秒，少约 0.51 秒；完整摘要一致。
- 菜单进入和恢复保存已接到后台 Worker，旧档备份、保存冲突保护、精确读回和失败重试保留。新增的整段等待收益尚未测定。

这些结果属于不同输入、版本和处理环节，百分比不能相加，也不能外推为整款游戏帧率或内存提升。
