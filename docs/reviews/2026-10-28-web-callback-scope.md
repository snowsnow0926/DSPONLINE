# 稳定事件和长按取消回调：阻断初始渲染作用域保留

状态：开发候选，等待冻结大档验证，未发布。接续 [页面保留堆诊断](./2026-10-28-web-main-heap-retention.md)，持续 goal 运行中。

两个独立浏览器用例先在旧实现复现：经过四次新渲染、清理前一 React fiber 并做诊断 GC，初始渲染数据仍被稳定事件/长按 hook 保留。单元函数行为正常不代表旧闭包已经释放。

原因是稳定函数在 hook 内创建，能与同次渲染的 effect/手势回调共用词法环境。即使稳定事件只使用 `callbackRef.current`，该环境仍能保留初始 callback；长按 hook 的稳定取消闭包同样会连带保留 `getTarget`/`onLongPress`。

候选把稳定调度和取消函数定义在模块作用域，以原生 `bind` 只绑定必要的 ref。稳定事件仍在 layout effect 后使用最新已提交回调；长按计时器仍保留按下时的回调快照，普通渲染不饿死手势，路由变化/禁用仍取消。没有将所有旧事件改成读取最新状态，也没有改变 App、模拟、T0、保存或恢复代码。

修正后两个浏览器 GC 用例通过；稳定事件身份/行为、长按普通渲染快照和路由取消单元通过，应用类型通过。第一次泛型绑定表达式缺括号导致转换失败，原始日志保留，修正后重跑通过。下一步检查生产压缩后的同档保留堆/存活视图，再做无采样四次网页对照、全量回归和 PWA。当前不从小用例宣称整页内存下降。

资料目录：`artifacts/web-callback-scope-20261028/`。诊断工具增加 `--runtime-retention=1`，须堆采样和 GC；只输出弱引用的存活计数，避免反复写巨大的私有堆文件。该标记默认关闭，不能用于正式无采样收益验收。
