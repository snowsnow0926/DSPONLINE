# 1.2.7 挂机停止与恢复专项

Role: develop

状态：2026-09-08，未发布。开发基线为 `a0736c85`，工作在隔离发布目录；最终提交、制品身份和完整 QA 由后续发布交接补录。本记录不包含玩家身份、私有存档或其摘要。

## 问题与改动

玩家反馈停止挂机后反复出现结算失败、无法回到游戏。检查发现两处可复现的控制流程缺口：主存档大小变化会重建保存回调，导致启动恢复 effect 再次认领正在停止的会话；候选已经完成但保存失败时，重试又尝试 finalization。

- `App.tsx` 将启动恢复绑定到权威启动状态，保留租约失效时的取消保护。保存状态重渲染不再作为新的启动恢复。
- 在当前页面内保留一份已经验证的 state/envelope 终态候选，绑定会话、权威租约及冻结墙钟边界。保存失败后复用候选；后台普通离线尾段同样不因等待保存而增长。主档提交成功但日志确认失败时继续收口，禁止借放弃入口回退到旧检查点。新会话、权威切换或明确放弃未提交结果会使候选失效；页面重开仍使用持久日志恢复。
- `TimeWarpIdleOverlay` 增加独立“导出恢复数据”。停止挂起或保存失败不禁用它。只读收集原主档、pure-idle 检查点/心跳、当前模式有限的 runtime 恢复引用及必要的内存恢复检查点；不重新结算、不清理日志、不写主档、不自动上传。只存于 App 内的未保存终态候选不在此诊断包内。

诊断包有独立格式，明确 `settlementCompleted=false`，不能直接当作正常存档导入。私人数据仅供玩家本地保存或主动分享；缺失读取会注明，异常消息不输出私有 payload。优先 gzip，复用安卓安全文件导出插件和浏览器下载；原始诊断上限 512 MiB，安卓最终文件仍遵守 32 MiB 上限，失败不改动原数据。
