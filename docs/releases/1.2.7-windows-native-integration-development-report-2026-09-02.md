## 这次实际修复的内容

### 1. 1.2.6 与原生历史兼容

Rust `production_history` 现在生成与 1.2.6 JavaScript 相同形状的 `pureIdleReplication` 只读遥测（宇宙矩阵科研累计、逐恒星系结构点和壳面帆计数），并在历史分段压缩时保留最新遥测。它只进入经过验证的生产历史哈希，不参与物料生产、戴森结构写入或排行榜数值修正。

### 2. StarMap 原生面板路由

修复合并后桌面 StarMap 最终 JSX 仍硬编码旧版行业/量子控制台的问题，改为使用已计算的原生面板；1.2.6 的原生面板不会在渲染最后一步被旧 UI 覆盖。

### 3. Windows 原生线程稳定性

Rayon、回收线程和并发回归线程统一使用有界 4 MiB 栈。此前 Windows 默认小栈在合法的大 v47 批次中可能触发 `STATUS_ACCESS_VIOLATION` 或栈压力；本修复只提高原生工作线程的安全余量，不改变游戏数据和模拟规则。另加入桌面入口 `node --check` 门禁，并删除合并产生的重复 `isDevelopment` 声明。

### 4. 大存档导入峰值

Windows 本地文件检查/导入先以有界 `ArrayBuffer` 传输和字节校验完成（256 MiB 上限、gzip 魔数、严格 UTF-8、长度与 FNV 校验），只在救援或兼容回退时重新读取文本。有效导入不再让 renderer 长期保留整份 raw 字符串，从而减少大档检查时的重复内存副本；原始文件内容和哈希不被改写。
