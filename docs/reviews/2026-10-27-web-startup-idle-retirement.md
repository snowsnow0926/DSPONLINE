# 启动保存完成后的后台回收

状态：本地开发候选，未发布。普通 T0 前置实验已因内存峰值无改善而撤回；本候选恢复原 T0 时序，保留已验收的后台共用和旧 transfer 死引用修正。

大档持久化 Worker 原本在队列排空后等待 2 秒再回收。现在增加一个受保护的立即回收入口：只有至少处理过 16 MiB 证明数据、没有进行中或排队的请求、客户端未关闭时才释放该代 Worker；保持客户端可用，下次保存惰性新建后台。原 2 秒策略与小档复用策略继续存在，旧代的错误、回包和计时器不能影响新代。

默认大档启动在主档完整提交、独立读回和成功返回之后调用这一入口，再初始化挂机后台。忙碌时只返回 false，不能打断保存。失败保存、页面退出、可选 durable 与原生所有权路径继续按原有规则处理。GameState v47、envelope v2、云端 v8、恢复日志格式、材料和自动备份设置均不改变。

验证进行中：先用独立 Worker 堆诊断查明此阶段的后台重叠，再以无堆采样、无强制 GC 的交替真实大档对照决定是否保留。15 项持久化客户端单测已通过，新增忙队列保护、跨代迟到事件、缓冲归还、小档与 pagehide 保持关闭检查；完整回归、生产构建、真实大档完整一致性和性能结论待完成。

前一轮已验收 `1d168a74` 的独立诊断，在挂机初始化请求发出前捕获旧持久化 Worker：`usedSize=665,439,752 B`、`backingStorageSize=221,461,597 B`，新的挂机 Worker 此时仅约 0.60 MB JS 堆。没有强制 GC；这是仍存在的堆和缓冲占用，不等于存活对象或实际进程工作集。证据为私有 `artifacts/web-startup-idle-retirement-20261027/overlap-old-heaps.json`；诊断时序不用于性能百分比。
